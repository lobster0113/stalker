# web/ — 학습 서비스 웹앱

## demo/ (학습 서비스 화면, #337: 학습된 TP-GTO 연결)
- `demo/index.html` 한 파일(경로는 기록 호환 때문에 유지). 빌드 없음(글꼴만 Google Fonts). TP-GTO 엔진(`app/tpgto.js`)과 정책(`app/policy/`)을 `import()`·`fetch`로 불러오므로 **웹 서버로 연다**(`cd web && python -m http.server` → `http://localhost:8000/demo/`). 파일로 열면 정책을 못 불러온다는 안내와 함께 모의 정답으로 동작한다. 자산 경로는 `window.STALKER_APP_BASE`(기본 `../app/`)로 바꿀 수 있다(Artifact 사본은 `app/`).
- **캐시게임 · TP-GTO**(기본): 6인 100BB 노리밋, 매 핸드 모든 좌석을 100BB로 맞춘다(탑업·초과분은 세션 손익으로 적립해 정보 막대에 보인다). 고른 등급에 학습 정책이 있으면 상대 5명이 그 정책(`app/policy/<등급>-6.json`)을 표본으로 두고, 좌석 아래에 `TP-GTO <등급>`이 붙는다. 핸드는 `app/tpgto.js` 엔진에 거울처럼 함께 진행된다(같은 딜·보드·액션). 테이블과 엔진의 차례가 어긋나면 그 핸드만 거울을 끄고 모의 정답으로 돌아간다(콘솔 `[tpgto] mirror off`). 세 등급(초보·중수·고수) 모두 학습 정책이 있다(#360). 규칙 봇 상대와 모의 정답은 정책을 불러오지 못했을 때 '모의로 계속'을 고른 경우에만 쓰며, 시작 화면·헤더에 그렇게 표시한다. 토너먼트는 아직 학습 정책이 없어 모의다.
- **임시 정책·미학습 표시**(#397, ADR 0019 §7): `app/policy/index.json`의 등급 항목에 `placeholder: true`·`trained_on`(게임·인원·스택·사이즈 메뉴)이 있으면(없으면 false) 6인 100BB 캐시 테이블의 정보 막대에 "임시 AI: … 실전 규칙 정책 학습 중" 배지, 좌석 태그에 `· 임시`, 모델 라벨·세션 분석 비교에 "임시 정책 기준"이 붙는다. 정책이 덮지 않는 테이블(인원 4 등)은 정보 막대에 "미학습(규칙 봇)", 좌석에 `· 규칙 봇`. `python -m stalker.tools.export_web_policy --placeholder`가 정책 파일에 같은 필드를 쓴다. 실전 규칙 정책으로 교체하면 `placeholder`를 빼면 된다.
- **한 핸드 = 한 등급**(#364): 게임 중 시작 화면에서 등급을 바꾸면 지금 핸드는 질문·채점·상대 모두 이전 등급으로 끝나고, 정보 막대와 토스트에 "다음 핸드부터 <등급> 정책으로 바뀝니다"가 보인다. 다음 핸드가 시작될 때 새 등급 정책을 `tpgLoad`로(로딩 표시 포함) 불러온 뒤 `G.tier`·`G.eng`(tier·pol·meta)·좌석 태그·헤더·TP 패널 등급을 함께 바꾼다(`setTableTier`). 훈련 게임의 질문·채점 코드는 `S.tier` 대신 `tierNow()`(= 진행 중인 테이블의 `G.tier`)를 읽는다. 새 등급에 학습 정책이 없으면 규칙 봇 상대로, 불러오기에 실패하면 게임 시작 때와 같은 오류 화면(다시 시도·모의 정답으로 계속)으로 간다.
- **사람 입력은 완전한 노리밋**(#341): 벳·레이즈는 최소 레이즈부터 올인까지 아무 금액(슬라이더 + BB 숫자 칸, 0.1BB 단위). 단축 칩은 TP §6 실전 사이즈(#386, `stalker/e3/game.py` 메뉴 `real`)이며 빠른 선택일 뿐이고 모든 등급이 같다: 오픈 2·2.2·2.5·3·3.5·4·5·6·8·10BB(림퍼 1명당 +1BB, BB 금액으로 표시), 3벳 2.5·3·3.5·4·5x, 4벳 2·2.2·2.5·3x, 5벳부터 올인만, 포스트플랍 벳 팟 20·33·50·75·100·150·200·300%, 레이즈 2.5·3·4·5·7·10x(캡 없음, 올인의 80% 이상은 올인으로 합침), 그리고 올인. 폰 폭을 위해 자주 쓰는 크기(`COMMON_SIZES`)와 올인만 먼저 보이고 `더보기 +N`이 나머지를 편다. 단축 금액은 엔진 `sizeMenu(s, "real", null)`과 같다(Gate U). 상대 정책 메뉴에 없는 금액은 TP §6 의사 조화 분할로 읽는다: AI의 해석은 분할에서 시드 난수로 한 번 뽑고(시드 = 딜과 결정 위치, 같은 핸드는 같은 해석), 채점(내 선택 빈도)은 분할 가중 f·p(A) + (1 − f)·p(B)다. 비교 화면에 `AI 해석: 37.8BB = 오픈 2.5BB 6% · 올인 100BB 94% (확률로 읽어요, 이번 핸드는 올인 100BB)`처럼 보인다. 사전 등록 번역 오차 규칙(`translationError` = `stalker/e3/translate.high_translation_error`, #417: 한 이웃만 올인이고 스택 80% 미만, 또는 두 이웃에서 먼 금액이면서 두 이웃의 팟 비율이 2배 넘게 벌어짐)에 걸리면 `근사(번역)` 표시와 `≈` 빈도, 두 이웃의 비중과 각 이웃의 TP-GTO 빈도가 보이고 만점으로 채점하지 않는다(Gate U). 지도: `python -m stalker.tools.translation_map --policy web/app/policy/mid-6.json`. TP 패널 머리에는 내 스택·유효 스택·팟·SPR(모든 스트리트)과 남은 상대마다 스택·나와의 유효 스택·SPR이 보인다(스택은 공개 정보).
- **정답 출처**: 모델이 낸 값에는 `TP-GTO · 학습 중간본` 라벨(마우스오버·줄에 `반복 N회 · LBR x±se bb/hand · run <id>`, 승인 상태 미검증)을, 나머지에는 `모의`를 붙인다. 모델이 내는 것: 액션 비교(내 실제 핸드의 정책 혼합 전략, 메뉴 액션별 %), `hand.equity`(상대 전원의 공개 레인지 — 각자 같은 정책으로 액션마다 베이즈 갱신 — 를 모두 이길 확률, 정책 키가 쓰는 값). #445부터 같은 공개 레인지로 계산할 수 있는 항목도 엔진 값이다(`app/tpgto.js` 교사 함수): `opp.range`(`rangeWidth` — 대상 상대 레인지의 가장 무거운 콤보 대비 상대 가중치 합 %, 채점 격자는 `rangeClasses`), `board.adv`(`boardAdvantage` — 100 × (1 − 내 공개 레인지의 상대 레인지 대비 평균 에퀴티), 헤즈업만), `board.nut`(`boardNut`), `hand.outs`·`hand.vuln`(`nextCardShift` — 보이지 않는 카드를 한 장씩 깔아 남은 상대 전원 공개 레인지 대비 내 에퀴티가 10%p 이상 오르거나 내리는 비율, 플랍·턴). 복기의 레인지·보드 줄도 재생한 정책의 공개 레인지로 계산한다. 성향(`opp.loose/aggr/foldy`)·`opp.value`·`plan.foldeq`·`plan.icm`과 멀티웨이 보드 읽기, 정책이 없는 설정의 값은 모의이며, 결과 줄에 `모의 정답 N`과 이유 한 줄(`MOCK_WHY`)이 붙는다("TP-GTO(모의)"라는 표기는 쓰지 않는다). 판단 Top 3는 아직 모의다. Quick에서 `진행`만 눌러도 대기 패널에 액션 비교를 보여 준다.
- **화면 감사 반영**(#445): 상대 카드는 이름판 테두리에만 닿고(이름·스택을 가리지 않음), 폴드한 상대 카드는 숨기며, 딜러 버튼은 벳 선에서 비켜 놓고, 팟 칩은 금액 옆에 둔다(Gate U가 화면마다 겹침을 사각형 교차로 검사). 프리플랍에 아직 아무도 팟에 들어오지 않았으면 레인지 질문을 하지 않고 '뒤의 N명'으로 표시한다(성향 질문은 다음 차례 상대 기준). 정보 막대의 세션 손익을 누르면 핸드별 결과(최근 30핸드)와 분산 안내가 열린다. 헤더 배지는 화면을 따른다(학습 섹션 `학습 문제 · 모의 정답`, 복기 `복기 · TP-GTO <등급> 비교` 또는 `복기 · 모의 정답`). 점수는 허용 오차를 넘는 1점마다 4점씩 깎는다(`SCORE_SLOPE`; 2.4일 때는 에퀴티 0 답이 참값 18에 69점이었다). 학습 섹션 에퀴티 문제는 정답과 승·무·패 설명을 한 표본에서 낸다.
- 정책 파일: `python -m stalker.tools.export_web_policy --ckpt … --summary … --run <id> --sha <sha> --out web/app/policy/<등급>-6.json`(#336). 파드 결과는 `--pod-result <result.json>`(메타 포함, `--summary`와 같이 쓰면 오류), 평균 전략은 `--strategy average`(#355) 후 `app/policy/index.json`(등급별 파일·메타)을 갱신한다. 현재: 초보 = run 40783153094(`e3-tp-beginner`, 2×10⁵회, LBR 1.13±0.22), 중수 = 파드 run 40919207457(`e3-tp-mid-pod` 체인 3회차, 1.9×10⁶회, 평균 전략, LBR 0.14±0.21, #378), 고수 = 파드 run 40901122090(`e3-tp-pro-pod` 체인 2회차, 3.17×10⁶회, 평균 전략, LBR 0.38±0.19, 21.0만 키 9.3MB·gzip 1.6MB라 3MB 상한 대신 `--max-bytes 10000000`, #378).
- 화면: 시작(설정 1/1-1/1-2/2, TP 등급, 플레이 모드) · 훈련 게임 · 학습 섹션 · 복기.
  - **플레이 모드**(TP §4.2, 등급과 별개 축, 기본 Quick): **Quick** = 내 차례에 액션(+사이즈)부터 고르고 `진행`하면 그 결정이 끝난다(입력 3개 이하). 원하면 `진행` 대신 `분석 보기`를 눌러, 고른 액션은 그대로 둔 채 이 스팟의 핵심 판단 1~3개만 답하고 `비교 보기`로 채점·TP-GTO(모의) 비교를 본 뒤 그 액션으로 진행한다. 묻는 판단은 데모의 `MODES` 상수(= 명세 `modes.quick`의 `max_judgments`·`rule`, `tests/test_tp_spec.py`가 같은지 검사)로 정한다: 스팟 유형(이번 스트리트에 상대 벳·레이즈를 마주함 = `facing_bet`, 아니면 `preflop`/`postflop`)의 목록 ∩ 등급 항목 ∩ 적용·N/A 필터, 최대 `max_judgments`개. **Guided** = 아래 카드 뉴스로 등급의 판단 전부와 액션을 묻는다.
  - 훈련 게임: 테이블 중앙, TP 패널 오른쪽(폰은 바텀 시트), 정책 상대는 1.5초 진행, 규칙 봇 상대는 좌석마다 다른 생각 시간(아래 '상대 페르소나'). Guided의 TP 입력은 **카드 뉴스**: TP 단계(B 보드 읽기 → C 상대 읽기 → D 내 핸드 → E 계획 → F 액션)마다 카드 한 장, 이전/다음 버튼과 진행 점, 카드 사이 슬라이드 전환(`prefers-reduced-motion`이면 생략). 그 카드의 채점 항목을 다 답해야 다음으로 넘어가고, 마지막 카드에서 제출한다. 입력은 슬라이더 대신 탭: 등급 눈금 칩(초보 25 단위, 중수 10 단위, 고수는 10 단위 칩 + ±1/±5), 레인지는 프리셋·상위 % 칩(+ 중수 이상 ±1/±5, 고수는 칸 탭 편집). **내 차례(TP 패널이 열린 동안)에는 토너먼트 레벨 시계가 멈춘다**(`⏸ 정지` 표시). 채점 화면의 항목마다 "왜 이 답인가"를 펼쳐 볼 수 있다.
  - **폰 바텀 시트**(#440, 760px 이하): 내 차례에 열린 시트는 테이블의 내 좌석을 가린다. 그래서 시트 머리에 카드 줄(`#tp-strip`: 내 카드 · 보드 · 팟 · 콜 금액 · 직전 상대 액션)을 두고 액션 버튼과 함께 보이게 한다. 기본 높이는 64vh(상대별 스택 줄은 숨김)이고, 그래버를 위로 끌면 다 펼치고(92vh, 스택 줄 포함) 아래로 끌면 한 단계씩 접힌다. 탭하면 접기/열기. 접히면 테이블 전체와 카드 줄이 보인다. 태블릿·노트북에는 카드 줄이 없다.
  - 학습 섹션: 처음엔 **배우는 순서**(족보 맞히기 → 에퀴티 → 레인지 추정 → 보드 → 유리해지는 카드 → 불리해지는 카드 → 준비 중 항목)로 놓인 갤러리. 순서는 `MODS` 배열(데이터)이 정한다. 근거는 학습자 커리큘럼 검토(#172, `docs/plans/2026-10-27-learner-curriculum-review.md` 단계 0–3)다: 규칙(족보)을 알아야 계산(에퀴티)을 하고, 계산이 되어야 추정(레인지)·보드 해석으로 넘어가며, 카드 변화(아웃츠·취약성)는 그 위에 쌓인다. 하나를 누르면 카드들이 왼쪽 목록(폰·태블릿은 위쪽 가로 목록)으로 옮겨 가는 애니메이션(FLIP)과 함께 문제가 열리고, "← 전체"로 갤러리에 돌아간다. 문제는 훈련 게임과 같은 모양의 6인 테이블에 누가 어디서 어떻게 벳했는지(포지션·칩·액션 태그) 보여준다. 쉬움 = 상대 핸드 공개, 보통 = 상대 레인지 13×13(크게), 어려움 = 테이블 액션만. `족보 맞히기`는 보드·내 핸드·상대 핸드를 보고 둘의 족보를 탭으로 고르면 채점한다(TP 항목이 아니라 약점 점수에는 넣지 않고 `stalker.rankq`에 따로 기록).
  - **정답 설명(공용 컴포넌트 `whyHTML`)**: 학습 섹션 정답, 훈련 게임 채점, 복기 비교가 같은 설명을 쓴다. 보드 읽기·넛 우위 = 내 레인지 대 상대 레인지의 강도 구간(넛급/강한 메이드/중간/드로/에어) 비교 막대 + 차이가 큰 구간 강조 + 대표 콤보, 에퀴티 = 승/무/패 막대와 이기는·지는 상대 핸드 예(상대 핸드가 하나면 순위를 뒤집는 다음 카드), 유리·불리해지는 카드 = 해당 카드 목록, 레인지 추정 = 액션별로 좁혀지는 단계와 경계 핸드·그리드, 상대 성향·계획 = 관측 횟수와 수축 추정 근거, 족보 = 가장 센 다섯 장. 모두 `모의` 라벨을 단다.
  - 복기: 왼쪽에 훈련 게임과 같은 테이블, 오른쪽에 단계(포지션 → 핸드 → 프리플랍 → 플랍 → 턴 → 리버 → 쇼다운(있으면) → 비교). 포지션은 테이블 자리를 눌러 고를 수 있고, 각 스트리트는 포지션 순서대로 차례인 자리의 액션(폴드·체크/콜·벳/레이즈 사이즈·올인)을 테이블 아래 버튼으로 입력한다. 순서가 아닌 자리와 규칙에 맞지 않는 액션은 고를 수 없고, 칩·팟·폴드가 테이블에 바로 반영된다(되돌리기 가능). 끝나면 마지막 내 결정을 TP-GTO(모의)와 비교하고 비슷한 상황으로 훈련을 시작할 수 있다.

- **초보 에퀴티 질문 = 순위형**(TP v0.2, ADR 0011 #263, #315): 질문 형태 실험이 꺼져 있으면 초보의 `hand.equity`는 "내 핸드는 이 상대 상황에서 내 레인지의 상위 몇 %인가?"(`RANK_Q`, 명세 `question_forms.beginner`와 같은 문구)를 형태 B 칩 5개(상위 20% … 하위 20%)로 묻고, 명세 `share_better`(TP §4.1)의 정답 칩과 비교해 채점한다(막대 위치 = (4 − 칩) × 25로 약 → 강, 결과 줄에 `참값 모의` 칩과 기준 노트). 정답 칩은 실험 형태 B와 달리 **내 레인지** 안에서 센다. 모의 근사: 내 레인지 = 데모의 내 레인지 모의값(`heroRangePct`, 프리플랍은 전체) 상위 클래스의 콤보를 균등 가중한 것이고, 그중 60콤보 표본(형태 B와 같은 시드 처리)으로 비율을 낸다. 이 채점은 `eqab` 기록에 넣지 않는다. 중수·고수는 이길 확률 칩 그대로다. 실험을 켜면 등급과 무관하게 A/B 배정이 우선한다.
- **질문 형태 실험**(#262, Gate E 예비, 기본 끔): 시작 화면 토글을 켜면 훈련 게임의 `hand.equity` 질문이 결정마다 (A) "상대가 이렇게 플레이할 때 내가 이길 확률" 또는 (B) "내 핸드는 이 상황에서 상위 몇 %" 5단계 칩으로 무작위 배정된다. 배정 난수는 훈련 세션(테이블에 앉기)마다 시드를 하나 고정한다(`?abseed=N`으로 지정 가능). TP 패널 제목에 형태(`형태 A · 이길 확률`/`형태 B · 상위 %`)가 보인다. 이 답은 채점·약점에 넣지 않고, 결정마다 `{f, ms, a, t, seed}`(형태, 질문이 화면에 뜬 뒤 마지막 칩 탭까지 ms, 답 칩, 정답 칩 0–4)를 localStorage `stalker.eqab`(최근 300건)에 익명으로 남긴다. 정답 칩(모의): A = 모의 에퀴티의 20%p 구간, B = 같은 상대 레인지에 대해 내 핸드보다 에퀴티가 높은 핸드 비율(무작위 60핸드 표본, 게임 난수와 분리)의 20% 구간. 학습 섹션 아래 표에 형태별 기록 수·P50·P95 입력 시간·정답률이 보인다. 끄면 화면과 채점이 이전과 같다.

Artifact 사본에는 `app/personas.js`도 함께 올린다.

## app/ (E3 TP-GTO 브라우저 이식, #335)
- `app/tpgto.js`: 의존성 없는 ES 모듈. E3 게임 규칙, TP 키(초보·중수·고수), 공개 레인지 갱신, 에퀴티를 Python(`stalker/e3/`, `stalker/e2/eq_view.py`)과 정확히 같게 계산한다. 그래서 학습된 정책 표(키 → 액션 확률)를 정적 페이지가 그대로 쓴다. API는 파일 첫머리 주석에 있다(`newHand`·`legal`·`apply`·`decisionKey`·`actionProbs`·`updateRanges`·`betRange`·`sizeMenu`·`splitBet`·`sampleBet`·`translateBet`·`applyBet`·`menuOf`).
- 메뉴(#386): 엔진은 Python의 세 메뉴(`v1`·`tp6`·`real`)와 레이즈 캡 규칙(`streetCap`: real은 프리플랍 캡 3, 포스트플랍은 정책의 `raise_cap`, 없으면 ALLIN_MERGE)을 그대로 안다. 핸드의 메뉴는 정책 파일 메타의 `menu`·`raise_cap`(`menuOf`, 없으면 v1·캡 3)으로 정한다. 지금 내보낸 세 정책은 v1이라 사람의 실전 사이즈는 v1 라벨(`r`·`b33`·`b75`·`a`)로 번역된다. `export_web_policy`는 체크포인트의 메뉴를 메타에 적는다.
- 프리플랍 에퀴티 표 `app/assets/hu_equity.json`을 먼저 넣는다: `await loadEquityTable(url)` 또는 인라인 객체로 `setEquityTable(obj)`.

- 만들기(사전 등록 설정, 두 단계): ① 스크린 `python -m referee.e3.preflop_probe web/app/policy/<등급>-6.json --deals 300 --seed 0 --workers 3 --json <등급>.probe.json`. 칸: 퍼스트 인·오픈 대면 × 그 스팟이 가능한 모든 좌석 × 11개 그룹(AA KK QQ JJ TT AKs AKo AQs AQo AJs KQs), 칸마다 300딜, 시드 0. 고수는 정책이 커서 그룹을 AA KK QQ AKs AKo AQs로 줄였다. ② 확인 `python -m stalker.tools.policy_leaks --tier <등급> --screen <등급>.probe.json --save-confirm <등급>.confirm.json --workers 3 --out web/app/policy/<등급>-6.leaks.json --evidence "…" --command "…"`: 스크린에서 누수가 아니지만 가장 나은 이탈의 이득 > 0.5bb이고 보정 없는 95% 하한 > 0인 칸만 1000딜·독립 시드(7)로 다시 재고, 그 칸들만을 한 family로 본페로니 보정한다. 스크린은 수백 칸을 한 family로 보정하므로 300딜에서는 실제 누수를 놓친다(중수 스크린 2칸, 고수 0칸). 어느 단계든 판정(이득 > 0.5bb, 본페로니 하한 > 0)에 걸리면 누수다(family 오류율 ≤ 2α). 이미 저장한 확인은 `--confirm <파일>`로 다시 쓴다. 실행 시간(로컬, 3 workers): 스크린 초보 5분·중수 13분·고수 8분, 확인 초보 12분(32칸)·중수 12분(28칸)·고수 6분(10칸). 결과: 초보 110칸 중 누수 54(스크린 32 + 확인 22), 중수 110칸 중 14(2 + 12, 퍼스트 인 UTG·CO AA 포함), 고수 60칸 중 4(0 + 4: 퍼스트 인 UTG KK, 오픈 대면 CO·BTN AA, BTN AKs).

- 페이지: 정책과 같은 방식으로 `APP_BASE + "policy/<등급>-6.leaks.json"`을 `fetch`한다(없거나 실패하면 경고 대신 약한 안내만). 프리플랍에서 내 첫 결정이 퍼스트 인(앞 좌석 모두 폴드)이거나 오픈 대면(앞에서 올인이 아닌 레이즈 하나, 나머지 폴드)이고 (스팟, 좌석, 핸드 그룹)이 누수 칸이면, 비교 화면(`[data-model-action]`, 훈련 게임·복기)에 `이 스팟의 정책 답은 검증에서 손해로 확인됨 (#391): 오픈/레이즈가 +x bb` 경고(`[data-leak-warn]`)를 띄우고 내 선택 빈도 대신 `채점 안 함`을 보인다. 그 스팟에서 상위 3% 클래스(`classesInTop(3)`: AA KK QQ AKs JJ AQs KQs AJs)이고 누수로 판정되지 않은 칸이면, 프로브가 쟀든(예: 중수 HJ AA 퍼스트 인, 스크린 CI가 0을 걸침) 안 쟀든 `프리플랍 강한 핸드 구간은 정책 결함 조사 중` 안내(`[data-leak-soft]`)를 붙인다. 판정되지 않은 것은 증명되지 않은 것이지 검증된 것이 아니기 때문이다. 강한 경고는 판정된 칸에만 뜬다. 시작 화면 모델 카드(`[data-known-leak]`)는 학습 중간본이고 프리플랍 결함이 있다고 말하고 #391로 링크한다. 판정 함수 `leakVerdict`는 순수 함수다.

## 정책 파일 (`stalker/tools/export_web_policy.py`, #336)
`{schema: "stalker.web.policy", schema_version: 1, tier, players, k, depth, iterations, run_id, sha, lbr_bb, lbr_stderr_bb, field_worst, job, strategy, nut_k?, q: 255, min_visits, keys, keys_dropped, policy}`. `strategy`는 `current`(regret matching, CI field가 평가하는 것) 또는 `average`(#355), 없으면 `current`. `average`면 field 평가가 없으므로 `field_worst`는 `null`. `nut_k`는 pro 표에만 있다(board.nut 단계 수, `checkNutK`가 확인, #332). `policy[key]`는 0..q 정수 배열이다(합 q, 상태의 합법 액션 순서). 확률은 값/q로 구한다. 확률 > 0인 액션은 최소 1을 보장한다. 파일에 없는 키(드물게 갱신돼 잘라낸 키)는 균등 분포로 둔다.
