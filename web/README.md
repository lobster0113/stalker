## demo/ (D1, AI 없음)
- `demo/index.html` 한 파일. 빌드·외부 의존 없음(글꼴만 Google Fonts, 없으면 시스템 글꼴). 브라우저로 열면 동작한다.
- 화면: 시작(설정 1/1-1/1-2/2, TP 등급, 플레이 모드) · 훈련 게임 · 학습 섹션 · 복기.
  - **플레이 모드**(TP §4.2, 등급과 별개 축, 기본 Quick): **Quick** = 내 차례에 액션(+사이즈)부터 고르고 `진행`하면 그 결정이 끝난다(입력 3개 이하). 원하면 `진행` 대신 `분석 보기`를 눌러, 고른 액션은 그대로 둔 채 이 스팟의 핵심 판단 1~3개만 답하고 `비교 보기`로 채점·TP-GTO(모의) 비교를 본 뒤 그 액션으로 진행한다. 묻는 판단은 데모의 `MODES` 상수(= 명세 `modes.quick`의 `max_judgments`·`rule`, `tests/test_tp_spec.py`가 같은지 검사)로 정한다: 스팟 유형(이번 스트리트에 상대 벳·레이즈를 마주함 = `facing_bet`, 아니면 `preflop`/`postflop`)의 목록 ∩ 등급 항목 ∩ 적용·N/A 필터, 최대 `max_judgments`개. **Guided** = 아래 카드 뉴스로 등급의 판단 전부와 액션을 묻는다.
  - 훈련 게임: 테이블 중앙, TP 패널 오른쪽(폰은 바텀 시트), 다른 플레이어 1.5초 진행. Guided의 TP 입력은 **카드 뉴스**: TP 단계(B 보드 읽기 → C 상대 읽기 → D 내 핸드 → E 계획 → F 액션)마다 카드 한 장, 이전/다음 버튼과 진행 점, 카드 사이 슬라이드 전환(`prefers-reduced-motion`이면 생략). 그 카드의 채점 항목을 다 답해야 다음으로 넘어가고, 마지막 카드에서 제출한다. 입력은 슬라이더 대신 탭: 등급 눈금 칩(초보 25 단위, 중수 10 단위, 고수는 10 단위 칩 + ±1/±5), 레인지는 프리셋·상위 % 칩(+ 중수 이상 ±1/±5, 고수는 칸 탭 편집). **내 차례(TP 패널이 열린 동안)에는 토너먼트 레벨 시계가 멈춘다**(`⏸ 정지` 표시). 채점 화면의 항목마다 "왜 이 답인가"를 펼쳐 볼 수 있다.
  - 학습 섹션: 처음엔 **배우는 순서**(족보 맞히기 → 에퀴티 → 레인지 추정 → 보드 → 유리해지는 카드 → 불리해지는 카드 → 준비 중 항목)로 놓인 갤러리. 순서는 `MODS` 배열(데이터)이 정한다. 근거는 학습자 커리큘럼 검토(#172, `docs/plans/2026-10-27-learner-curriculum-review.md` 단계 0–3)다: 규칙(족보)을 알아야 계산(에퀴티)을 하고, 계산이 되어야 추정(레인지)·보드 해석으로 넘어가며, 카드 변화(아웃츠·취약성)는 그 위에 쌓인다. 하나를 누르면 카드들이 왼쪽 목록(폰·태블릿은 위쪽 가로 목록)으로 옮겨 가는 애니메이션(FLIP)과 함께 문제가 열리고, "← 전체"로 갤러리에 돌아간다. 문제는 훈련 게임과 같은 모양의 6인 테이블에 누가 어디서 어떻게 벳했는지(포지션·칩·액션 태그) 보여준다. 쉬움 = 상대 핸드 공개, 보통 = 상대 레인지 13×13(크게), 어려움 = 테이블 액션만. `족보 맞히기`는 보드·내 핸드·상대 핸드를 보고 둘의 족보를 탭으로 고르면 채점한다(TP 항목이 아니라 약점 점수에는 넣지 않고 `stalker.rankq`에 따로 기록).
  - **정답 설명(공용 컴포넌트 `whyHTML`)**: 학습 섹션 정답, 훈련 게임 채점, 복기 비교가 같은 설명을 쓴다. 보드 읽기·넛 우위 = 내 레인지 대 상대 레인지의 강도 구간(넛급/강한 메이드/중간/드로/에어) 비교 막대 + 차이가 큰 구간 강조 + 대표 콤보, 에퀴티 = 승/무/패 막대와 이기는·지는 상대 핸드 예(상대 핸드가 하나면 순위를 뒤집는 다음 카드), 유리·불리해지는 카드 = 해당 카드 목록, 레인지 추정 = 액션별로 좁혀지는 단계와 경계 핸드·그리드, 상대 성향·계획 = 관측 횟수와 수축 추정 근거, 족보 = 가장 센 다섯 장. 모두 `모의` 라벨을 단다.
  - 복기: 왼쪽에 훈련 게임과 같은 테이블, 오른쪽에 단계(포지션 → 핸드 → 프리플랍 → 플랍 → 턴 → 리버 → 쇼다운(있으면) → 비교). 포지션은 테이블 자리를 눌러 고를 수 있고, 각 스트리트는 포지션 순서대로 차례인 자리의 액션(폴드·체크/콜·벳/레이즈 사이즈·올인)을 테이블 아래 버튼으로 입력한다. 순서가 아닌 자리와 규칙에 맞지 않는 액션은 고를 수 없고, 칩·팟·폴드가 테이블에 바로 반영된다(되돌리기 가능). 끝나면 마지막 내 결정을 TP-GTO(모의)와 비교하고 비슷한 상황으로 훈련을 시작할 수 있다.
- 채점 정답은 **모의값**이다: 관측 통계의 수축 추정, 몬테카를로 에퀴티, 규칙 기반 혼합 전략. 실제 TP-GTO는 D3에서 연결한다(`docs/decisions/0009-tp-gto-design-proposal.md`).
- TP 항목 ID·등급·눈금·적용 조건은 TP v0.1(`docs/TP.md`, `stalker/tp/spec/tp_v0_1.json`)을 따른다. `TP` 키와 `TIERS[*].items`는 JSON과 정확히 같아야 하며 `tests/test_tp_spec.py::test_demo_matches_spec`이 검사한다. 명세가 바뀌면 이 파일의 `TP`·`TIERS`도 같은 PR에서 고친다.
- 모든 정답 화면(훈련 게임 채점·학습 섹션·복기)에 신뢰도 라벨 `모의`를 붙인다. 액션은 Q값이 없으므로 "모의 참고: TP-GTO(모의) 혼합 전략"으로만 보여주고 점수·약점에 넣지 않으며 EV 손실 수치도 내지 않는다(TP §5). `plan.pot`은 채점하지 않는 성찰 질문(중수·고수)이고, `opp.*`는 기회 수(N/A 기준은 JSON `na.min_opportunities`)가 모자라면 묻지 않는다.
- 결정당 입력 시간(내 차례 시작 → 제출. Quick은 액션을 확정한 `진행`·`분석 보기`까지)을 기록해 "내 약점" 화면에 P50/P95로 보여준다(브라우저 localStorage `stalker.itimes`, 최근 300회).
- **기록 옮기기**(#117): '내 약점'의 '기록 옮기기'에서 학습 기록(`weak`·`itimes`·`rankq`)을 JSON 텍스트로 보여주고 복사한다. 다른 기기에서 붙여넣어 가져온다. 파일 다운로드나 서버 동기화는 쓰지 않는다. 스키마는 `{schema: "stalker.demo.records", schema_version: 1, ...}`이고, 잘못된 입력에는 고치는 법이 담긴 오류를 보여준다. 가져오기는 한 번 더 눌러야 덮어쓴다(뷰어에 `confirm()`이 없음). 검사: `tests/test_demo_records.py`(node로 `parseRecords`), Gate U 왕복(내보내기 → 초기화 → 가져오기 → 같은 통계).
- 사용자에게 보여줄 때: 대화 세션이 `<!doctype>`·`<html>`·`<head>`·`<body>` 태그를 뺀 사본을 Claude Artifact(비공개)로 게시한다. 현재 게시본: https://claude.ai/artifact/LpQTDzYgZgTjcY5T4BwcZb

## e2e/ (Gate U, CI 잡 `web`)
```bash
cd web/e2e && npm ci && npx playwright install chromium && npm test
```
- `gate-u.mjs`: 시작(Quick 기본 확인) → 테이블 → 내 차례 Quick 한 결정이 입력 3개 이하(액션·사이즈·진행)로 끝남 → 다음 차례 Quick `분석 보기`(핵심 판단 1~3개, 액션 재질문 없음) → 비교 → 시작 화면에서 Guided로 바꿔 TP 카드(카드마다 첫 칩으로 답하고 다음, 액션은 폴드가 아닌 것 + 사이즈) → 제출 → 채점, 학습 갤러리 → 모듈 열기 → 1문제, 복기 단계(포지션 → 핸드 → 프리플랍 액션 → 비교)를 통과시키고, 화면마다 390×844·820×1180·1440×900 스크린샷(`web/e2e/screenshots/`, CI에서는 아티팩트 `web-screenshots`), 가로 스크롤, axe critical 위반을 검사한다.
- 내 차례 대기는 테스트 전용 `?speed=30`(속도 배수)으로 줄인다. 데모 기본 진행(1.5초)은 그대로다.
- 로컬에 Chromium이 이미 있으면 `CHROMIUM_PATH=/path/to/chrome npm test`.
- 아직 없음: 성능 예산.
