# web/ — 학습 서비스 웹앱

## demo/ (학습 서비스 화면, #337: 학습된 TP-GTO 연결)
- `demo/index.html` 한 파일(경로는 기록 호환 때문에 유지). 빌드 없음(글꼴만 Google Fonts). TP-GTO 엔진(`app/tpgto.js`)과 정책(`app/policy/`)을 `import()`·`fetch`로 불러오므로 **웹 서버로 연다**(`cd web && python -m http.server` → `http://localhost:8000/demo/`). 파일로 열면 정책을 못 불러온다는 안내와 함께 모의 정답으로 동작한다. 자산 경로는 `window.STALKER_APP_BASE`(기본 `../app/`)로 바꿀 수 있다(Artifact 사본은 `app/`).
- **캐시게임 · TP-GTO**(기본): 6인 100BB 노리밋, 매 핸드 모든 좌석을 100BB로 맞춘다(탑업·초과분은 세션 손익으로 적립해 정보 막대에 보인다). 고른 등급에 학습 정책이 있으면 상대 5명이 그 정책(`app/policy/<등급>-6.json`)을 표본으로 두고, 좌석 아래에 `TP-GTO <등급>`이 붙는다. 핸드는 `app/tpgto.js` 엔진에 거울처럼 함께 진행된다(같은 딜·보드·액션). 테이블과 엔진의 차례가 어긋나면 그 핸드만 거울을 끄고 모의 정답으로 돌아간다(콘솔 `[tpgto] mirror off`). 세 등급(초보·중수·고수) 모두 학습 정책이 있다(#360). 규칙 봇 상대와 모의 정답은 정책을 불러오지 못했을 때 '모의로 계속'을 고른 경우에만 쓰며, 시작 화면·헤더에 그렇게 표시한다. 토너먼트는 아직 학습 정책이 없어 모의다.
- **사람 입력은 완전한 노리밋**(#341): 벳·레이즈는 최소 레이즈부터 올인까지 아무 금액(슬라이더 + BB 숫자 칸, 0.1BB 단위). 프리셋 칩(프리플랍 2.2x·2.5x·3x·올인, 포스트플랍 팟 33·50·75·100·150%·올인, TP §6)은 빠른 선택일 뿐이며 모든 등급이 같다. 메뉴 밖 금액은 엔진이 가까운 메뉴 액션으로 해석해 상대 정책의 키·레인지 갱신에 쓰고, 비교 화면에 `AI 해석: 37.8BB를 올인 100BB로 간주`처럼 보인다.
- **정답 출처**: 모델이 낸 값에는 `TP-GTO · 학습 중간본` 라벨(마우스오버·줄에 `반복 N회 · LBR x±se bb/hand · run <id>`, 승인 상태 미검증)을, 나머지에는 `모의`를 붙인다. 모델이 내는 것: 액션 비교(내 실제 핸드의 정책 혼합 전략, 메뉴 액션별 %), `hand.equity`(상대 전원의 공개 레인지 — 각자 같은 정책으로 액션마다 베이즈 갱신 — 를 모두 이길 확률, 정책 키가 쓰는 값). 나머지 TP 항목(레인지 추정·보드 읽기·아웃츠·성향·폴드 에퀴티 등)과 판단 Top 3는 아직 모의다. Quick에서 `진행`만 눌러도 대기 패널에 액션 비교를 보여 준다.
- 정책 파일: `python -m stalker.tools.export_web_policy --ckpt … --summary … --run <id> --sha <sha> --out web/app/policy/<등급>-6.json`(#336) 후 `app/policy/index.json`(등급별 파일·메타)을 갱신한다. 현재: 초보 = run 40783153094(`e3-tp-beginner`, 2×10⁵회, LBR 1.13±0.22), 중수 = 파드 run 40851654734(`e3-tp-mid-pod`, 8×10⁵회, 평균 전략, LBR 0.66±0.24, #360), 고수 = 파드 run 40840669062(`e3-tp-pro-pod`, 2.18×10⁶회, 현재 전략, LBR 0.47±0.19, 19.5만 키 8.6MB·gzip 1.4MB라 3MB 상한 대신 `--max-bytes 10000000`, #360).
- 화면: 시작(설정 1/1-1/1-2/2, TP 등급, 플레이 모드) · 훈련 게임 · 학습 섹션 · 복기.
  - **플레이 모드**(TP §4.2, 등급과 별개 축, 기본 Quick): **Quick** = 내 차례에 액션(+사이즈)부터 고르고 `진행`하면 그 결정이 끝난다(입력 3개 이하). 원하면 `진행` 대신 `분석 보기`를 눌러, 고른 액션은 그대로 둔 채 이 스팟의 핵심 판단 1~3개만 답하고 `비교 보기`로 채점·TP-GTO(모의) 비교를 본 뒤 그 액션으로 진행한다. 묻는 판단은 데모의 `MODES` 상수(= 명세 `modes.quick`의 `max_judgments`·`rule`, `tests/test_tp_spec.py`가 같은지 검사)로 정한다: 스팟 유형(이번 스트리트에 상대 벳·레이즈를 마주함 = `facing_bet`, 아니면 `preflop`/`postflop`)의 목록 ∩ 등급 항목 ∩ 적용·N/A 필터, 최대 `max_judgments`개. **Guided** = 아래 카드 뉴스로 등급의 판단 전부와 액션을 묻는다.
  - 훈련 게임: 테이블 중앙, TP 패널 오른쪽(폰은 바텀 시트), 다른 플레이어 1.5초 진행. Guided의 TP 입력은 **카드 뉴스**: TP 단계(B 보드 읽기 → C 상대 읽기 → D 내 핸드 → E 계획 → F 액션)마다 카드 한 장, 이전/다음 버튼과 진행 점, 카드 사이 슬라이드 전환(`prefers-reduced-motion`이면 생략). 그 카드의 채점 항목을 다 답해야 다음으로 넘어가고, 마지막 카드에서 제출한다. 입력은 슬라이더 대신 탭: 등급 눈금 칩(초보 25 단위, 중수 10 단위, 고수는 10 단위 칩 + ±1/±5), 레인지는 프리셋·상위 % 칩(+ 중수 이상 ±1/±5, 고수는 칸 탭 편집). **내 차례(TP 패널이 열린 동안)에는 토너먼트 레벨 시계가 멈춘다**(`⏸ 정지` 표시). 채점 화면의 항목마다 "왜 이 답인가"를 펼쳐 볼 수 있다.
  - 학습 섹션: 처음엔 **배우는 순서**(족보 맞히기 → 에퀴티 → 레인지 추정 → 보드 → 유리해지는 카드 → 불리해지는 카드 → 준비 중 항목)로 놓인 갤러리. 순서는 `MODS` 배열(데이터)이 정한다. 근거는 학습자 커리큘럼 검토(#172, `docs/plans/2026-10-27-learner-curriculum-review.md` 단계 0–3)다: 규칙(족보)을 알아야 계산(에퀴티)을 하고, 계산이 되어야 추정(레인지)·보드 해석으로 넘어가며, 카드 변화(아웃츠·취약성)는 그 위에 쌓인다. 하나를 누르면 카드들이 왼쪽 목록(폰·태블릿은 위쪽 가로 목록)으로 옮겨 가는 애니메이션(FLIP)과 함께 문제가 열리고, "← 전체"로 갤러리에 돌아간다. 문제는 훈련 게임과 같은 모양의 6인 테이블에 누가 어디서 어떻게 벳했는지(포지션·칩·액션 태그) 보여준다. 쉬움 = 상대 핸드 공개, 보통 = 상대 레인지 13×13(크게), 어려움 = 테이블 액션만. `족보 맞히기`는 보드·내 핸드·상대 핸드를 보고 둘의 족보를 탭으로 고르면 채점한다(TP 항목이 아니라 약점 점수에는 넣지 않고 `stalker.rankq`에 따로 기록).
  - **정답 설명(공용 컴포넌트 `whyHTML`)**: 학습 섹션 정답, 훈련 게임 채점, 복기 비교가 같은 설명을 쓴다. 보드 읽기·넛 우위 = 내 레인지 대 상대 레인지의 강도 구간(넛급/강한 메이드/중간/드로/에어) 비교 막대 + 차이가 큰 구간 강조 + 대표 콤보, 에퀴티 = 승/무/패 막대와 이기는·지는 상대 핸드 예(상대 핸드가 하나면 순위를 뒤집는 다음 카드), 유리·불리해지는 카드 = 해당 카드 목록, 레인지 추정 = 액션별로 좁혀지는 단계와 경계 핸드·그리드, 상대 성향·계획 = 관측 횟수와 수축 추정 근거, 족보 = 가장 센 다섯 장. 모두 `모의` 라벨을 단다.
  - 복기: 왼쪽에 훈련 게임과 같은 테이블, 오른쪽에 단계(포지션 → 핸드 → 프리플랍 → 플랍 → 턴 → 리버 → 쇼다운(있으면) → 비교). 포지션은 테이블 자리를 눌러 고를 수 있고, 각 스트리트는 포지션 순서대로 차례인 자리의 액션(폴드·체크/콜·벳/레이즈 사이즈·올인)을 테이블 아래 버튼으로 입력한다. 순서가 아닌 자리와 규칙에 맞지 않는 액션은 고를 수 없고, 칩·팟·폴드가 테이블에 바로 반영된다(되돌리기 가능). 끝나면 마지막 내 결정을 TP-GTO(모의)와 비교하고 비슷한 상황으로 훈련을 시작할 수 있다.
- 모델이 없는 항목·설정의 정답은 **모의값**이다: 관측 통계의 수축 추정, 몬테카를로 에퀴티, 규칙 기반 혼합 전략.
- TP 항목 ID·등급·눈금·적용 조건은 TP v0.2(`docs/TP.md`, `stalker/tp/spec/tp_v0_2.json`)를 따른다. `TP` 키와 `TIERS[*].items`는 JSON과 정확히 같아야 하며 `tests/test_tp_spec.py::test_demo_matches_spec`이 검사한다. 명세가 바뀌면 이 파일의 `TP`·`TIERS`도 같은 PR에서 고친다.
- 모든 정답 화면(훈련 게임 채점·학습 섹션·복기)에 신뢰도 라벨(`TP-GTO · 학습 중간본` 또는 `모의`)을 붙인다. 액션은 Q값이 없으므로 혼합 전략을 참고로만 보여주고 점수·약점에 넣지 않으며 EV 손실 수치도 내지 않는다(TP §5). `plan.pot`은 채점하지 않는 성찰 질문(중수·고수)이고, `opp.*`는 기회 수(N/A 기준은 JSON `na.min_opportunities`)가 모자라면 묻지 않는다.
- 결정당 입력 시간(내 차례 시작 → 제출. Quick은 액션을 확정한 `진행`·`분석 보기`까지)을 기록해 "내 약점" 화면에 P50/P95로 보여준다(브라우저 localStorage `stalker.itimes`, 최근 300회).
- **초보 에퀴티 질문 = 순위형**(TP v0.2, ADR 0011 #263, #315): 질문 형태 실험이 꺼져 있으면 초보의 `hand.equity`는 "내 핸드는 이 상대 상황에서 내 레인지의 상위 몇 %인가?"(`RANK_Q`, 명세 `question_forms.beginner`와 같은 문구)를 형태 B 칩 5개(상위 20% … 하위 20%)로 묻고, 명세 `share_better`(TP §4.1)의 정답 칩과 비교해 채점한다(막대 위치 = (4 − 칩) × 25로 약 → 강, 결과 줄에 `참값 모의` 칩과 기준 노트). 정답 칩은 실험 형태 B와 달리 **내 레인지** 안에서 센다. 모의 근사: 내 레인지 = 데모의 내 레인지 모의값(`heroRangePct`, 프리플랍은 전체) 상위 클래스의 콤보를 균등 가중한 것이고, 그중 60콤보 표본(형태 B와 같은 시드 처리)으로 비율을 낸다. 이 채점은 `eqab` 기록에 넣지 않는다. 중수·고수는 이길 확률 칩 그대로다. 실험을 켜면 등급과 무관하게 A/B 배정이 우선한다.
- **질문 형태 실험**(#262, Gate E 예비, 기본 끔): 시작 화면 토글을 켜면 훈련 게임의 `hand.equity` 질문이 결정마다 (A) "상대가 이렇게 플레이할 때 내가 이길 확률" 또는 (B) "내 핸드는 이 상황에서 상위 몇 %" 5단계 칩으로 무작위 배정된다. 배정 난수는 훈련 세션(테이블에 앉기)마다 시드를 하나 고정한다(`?abseed=N`으로 지정 가능). TP 패널 제목에 형태(`형태 A · 이길 확률`/`형태 B · 상위 %`)가 보인다. 이 답은 채점·약점에 넣지 않고, 결정마다 `{f, ms, a, t, seed}`(형태, 질문이 화면에 뜬 뒤 마지막 칩 탭까지 ms, 답 칩, 정답 칩 0–4)를 localStorage `stalker.eqab`(최근 300건)에 익명으로 남긴다. 정답 칩(모의): A = 모의 에퀴티의 20%p 구간, B = 같은 상대 레인지에 대해 내 핸드보다 에퀴티가 높은 핸드 비율(무작위 60핸드 표본, 게임 난수와 분리)의 20% 구간. 학습 섹션 아래 표에 형태별 기록 수·P50·P95 입력 시간·정답률이 보인다. 끄면 화면과 채점이 이전과 같다.
- **기록 옮기기**(#117): '내 약점'의 '기록 옮기기'에서 학습 기록(`weak`·`itimes`·`rankq`·`eqab`)을 JSON 텍스트로 보여주고 복사한다. 다른 기기에서 붙여넣어 가져온다. 파일 다운로드나 서버 동기화는 쓰지 않는다. 스키마는 `{schema: "stalker.demo.records", schema_version: 2, ...}`이고(v2에서 `eqab` 추가, v1 텍스트도 `eqab` 없이 가져온다), 잘못된 입력에는 고치는 법이 담긴 오류를 보여준다. 가져오기는 한 번 더 눌러야 덮어쓴다(뷰어에 `confirm()`이 없음). 검사: `tests/test_demo_records.py`(node로 `parseRecords`), Gate U 왕복(내보내기 → 초기화 → 가져오기 → 같은 통계·같은 질문 형태 표).
- 복기: 캐시게임 6인 100BB 핸드면 입력한 액션을 엔진으로 재생해 마지막 내 결정을 학습 정책과 비교한다(에퀴티·액션에 모델 라벨, 다른 좌석 카드는 공개 키에 들어가지 않으므로 몰라도 된다). 다른 조건은 모의 비교. 복기 기본값은 캐시 100BB.
- 사용자에게 보여줄 때: 대화 세션이 `<!doctype>`·`<html>`·`<head>`·`<body>` 태그를 뺀 사본을 Claude Artifact(비공개)로 게시한다. 현재 게시본: https://claude.ai/artifact/LpQTDzYgZgTjcY5T4BwcZb

## app/ (E3 TP-GTO 브라우저 이식, #335)
- `app/tpgto.js`: 의존성 없는 ES 모듈. E3 게임 규칙, TP 키(초보·중수·고수), 공개 레인지 갱신, 에퀴티를 Python(`stalker/e3/`, `stalker/e2/eq_view.py`)과 정확히 같게 계산한다. 그래서 학습된 정책 표(키 → 액션 확률)를 정적 페이지가 그대로 쓴다. API는 파일 첫머리 주석에 있다(`newHand`·`legal`·`apply`·`decisionKey`·`actionProbs`·`updateRanges`·`betRange`·`translateBet`·`applyBet`).
- 프리플랍 에퀴티 표 `app/assets/hu_equity.json`을 먼저 넣는다: `await loadEquityTable(url)` 또는 인라인 객체로 `setEquityTable(obj)`.
- 실제 노리밋: 사람 좌석은 최소 레이즈부터 올인까지 아무 금액이나 낸다(`applyBet`). 칩은 실제 금액으로 움직이고, 메뉴 밖 금액은 가까운 두 메뉴 크기 사이의 의사 조화 매핑(결정적, 확률 0.5 이상인 쪽)으로 메뉴 액션에 대응시켜 기록·키·레인지 갱신에 쓴다. 팟 오즈·SPR 단계는 실제 칩으로 계산한다. AI 좌석은 메뉴 액션만 고른다.
- 검사: `python -m stalker.tools.web_vectors`(벡터·자산 다시 쓰기) 후 `node --test web/app/test/tpgto.test.mjs`. 결정 1천여 개의 legal·공개 키·1326 콤보 단계 배열·키·레인지 합이 모두 같아야 하고, 결정당 시간 P50/P95를 출력한다. `tests/test_web_vectors.py`가 벡터가 최신인지 확인하고 node가 있으면 이 테스트를 돌린다(CI 잡 `web` 연결은 후속 harness-change 이슈).

- `gate-u.mjs`는 `web/`을 내장 정적 서버로 띄워 연다(정책 `fetch`·엔진 `import()`가 `file://`에서 막히므로). 시작(Quick·캐시게임 기본, 헤더에 `학습 중간본`, 화면에 '데모' 문구 없음, 모델 상태 표시) → 테이블(정보 막대 `상대 TP-GTO`) → 내 차례 Quick 한 결정이 입력 3개 이하(액션·**금액 칸에 프리셋이 아닌 금액 직접 입력**·진행)로 끝나고 대기 패널에 TP-GTO 혼합 전략 비교(모델 라벨) → 다음 차례 Quick `분석 보기`(핵심 판단 1~3개, 액션 재질문 없음) → 비교 → 시작 화면에서 Guided로 바꿔 TP 카드(카드마다 첫 칩으로 답하고 다음, 액션은 폴드가 아닌 것 + 사이즈) → 제출 → 채점, 질문 형태 실험 켬 → Guided 결정 3회(패널 제목 형태·칩 5개·결과의 A/B 줄) → 학습 섹션 표(형태별 기록 합 3·P50·P95·정답률). 배정은 URL `?abseed=1`로 고정해 B·A·B가 나오므로 매 실행이 두 형태를 다 돌고, B 결정에서 `eqabTruth("B")`가 게임 난수 `rngState`를 그대로 되돌리는지(켬/끔 사이 딜 순서 불변)와 B 기록의 정답 칩 0–4·표 B 행 기록 수 > 0을 확인한다, 학습 갤러리 → 모듈 열기 → 1문제, 복기 단계(포지션 → 핸드 → 프리플랍 액션 → 비교)를 통과시키고, 화면마다 390×844·820×1180·1440×900 스크린샷(`web/e2e/screenshots/`, CI에서는 아티팩트 `web-screenshots`), 가로 스크롤, axe critical 위반을 검사한다.

## 정책 파일 (`stalker/tools/export_web_policy.py`, #336)
`{schema: "stalker.web.policy", schema_version: 1, tier, players, k, depth, iterations, run_id, sha, lbr_bb, lbr_stderr_bb, field_worst, job, q: 255, min_visits, keys, keys_dropped, policy}`. `policy[key]`는 0..q 정수 배열이다(합 q, 상태의 합법 액션 순서). 확률은 값/q로 구한다. 확률 > 0인 액션은 최소 1을 보장한다. 파일에 없는 키(드물게 갱신돼 잘라낸 키)는 균등 분포로 둔다.
