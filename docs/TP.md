# Thinking Process (TP) 명세 — v0 초안 (보호 문서 — `referee-change` 절차로만 수정)

- 상태: **v0 초안** (2026-10-27, 방향 전환 세션). 사용자 예시(`docs/ORIGIN.md`)를 보완했다. D2 단계에서 포커 이론 조사·판별력 측정 후 **v1로 확정**한다(ADR 필요).
- 역할: TP는 AI(TP-GTO)·채점·웹 UI·학습 섹션이 공유하는 **단일 계약**이다. 기계 판독본은 `stalker/tp/spec/tp_v<N>.json`(D1에서 생성)이며 이 문서와 어긋나면 안 된다.
- 원칙: (1) 실전에서 사람이 몇 초 안에 할 수 있는 판단만 둔다. (2) 각 항목은 의미가 정의돼야 한다(시뮬레이터 안에서 "정답"을 계산하거나 학습 목표로 고정할 수 있어야 한다). (3) 조건 축은 유형 버킷으로 묶어 둔감하게 만든다(§4).

## 1. 결정 지점의 흐름
게임의 시작부터 끝까지 결정 지점마다 아래가 반복된다. 이전 핸드·이전 스트리트의 공개 정보(같은 `game_id` 안)는 모두 다음 판단의 입력이다.

```
[주어진 사실] 포지션 · 스택(BB) · 팟 · SPR · 합법 액션 · (토너먼트) 단계/페이점프
     ↓
(포스트플랍) B. 보드 읽기
     ↓
상대 액션(있으면, 주어짐) → C. 상대 읽기 → D. 내 핸드 평가 → E. 계획 → F. 액션
     ↓
상대 액션(주어짐) → 필요하면 C~F 반복
```

## 2. 항목 (ID는 고정, 추가·삭제·의미 변경은 버전업)
척도는 모두 0–100 정수. 화면에는 등급별 눈금(§3)으로만 입력받는다.

| ID | 단계 | 질문 | 척도 / 형식 | 종류 | 의미 정의(시뮬레이터 정답 또는 학습 목표) |
|---|---|---|---|---|---|
| `opp.loose` | C | 상대는 루즈한가? | 0 타이트 – 100 루즈 | 판단 | 이 게임에서 관측한 상대의 자발적 참여 성향(VPIP류)의 수축 추정. 관측 핸드 < n(명세 상수, v0 n=10)이면 "정보 부족"으로 표시하고 모집단 기본값을 쓴다 |
| `opp.aggr` | C | 상대는 공격적인가? | 0 패시브 – 100 공격적 | 판단 | 베팅·레이즈 대 콜 비율의 수축 추정 |
| `opp.foldy` | C | 상대는 압박에 잘 접는가? | 0 안 접음 – 100 잘 접음 | 판단 | 베팅을 마주했을 때 폴드 비율의 수축 추정 |
| `opp.range` | C | 상대 핸드 레인지 | 13×13 표(대각선 위 수딧, 아래 오프수트, 대각선 페어), 칸마다 가중치 0–100 | 판단 | 상대 행동 이력이 주어졌을 때 상대 홀카드의 사후 분포(시뮬레이터에서는 상대 정책으로 정확히 계산 가능) |
| `opp.bluff` | C | 방금 상대 액션은 블러프인가 밸류인가? | 0 블러프 – 100 밸류 | 계산 | `opp.range` 중 내 콜링 기준보다 강한 핸드의 비율 |
| `board.adv` | B | 이 보드는 누구에게 유리한가? | 0 나 – 100 상대 | 계산 | 내 레인지 대 `opp.range`의 레인지 에퀴티(넛 비율 가중) |
| `hand.equity` | D | 상대 레인지 대비 내 승률 | 0–100 | 계산 | 내 핸드 대 `opp.range`의 쇼다운 에퀴티 |
| `hand.future` | D | 다음 카드들이 누구에게 유리한가? | 0 나 – 100 상대 | 계산 | 다음 스트리트 카드별 에퀴티 변화의 기대 부호·크기(드로·취약성) |
| `plan.pot` | E | 팟을 키울 것인가? | 0 억제 – 100 증가 | 판단 | 남은 스트리트에서 정책이 기대하는 팟 성장 의도 |
| `plan.icm` | E | (토너먼트) 칩을 잃는 위험이 얼마나 무거운가? | 0 가벼움 – 100 무거움 | 계산 | 리스크 프리미엄: ICM 기대상금 기준 콜에 필요한 에퀴티 − 칩EV 기준 필요 에퀴티 |
| `act.choice` | F | 액션 | 폴드 / 체크 / 콜 / 벳·레이즈(사이즈 버킷 §4) / 올인 | 결정 | TP-GTO의 혼합 전략. 채점은 선택 액션의 정책 확률과 EV 손실로 한다 |
| `act.foldprob` | F | (벳·레이즈 시) 상대가 접을 확률 | 0–100 | 계산 | `opp.range`와 `opp.foldy`로 본 그 사이즈에 대한 폴드 비율 |

- **판단** 항목은 TP-GTO가 학습으로 내놓는 값이다. **계산** 항목은 앞 항목 값과 공개 사실로 결정되는 값이다.
- **연쇄 채점**: 계산 항목은 두 번 채점한다. ① 사용자가 입력한 앞 항목 값으로 계산한 값과 비교(계산 실수), ② TP-GTO 값과 비교(앞 단계 판단 오차의 전파). 그래야 "레인지는 맞혔는데 에퀴티 감각이 틀렸다"를 구분할 수 있다.
- **TP 경유(Gate T)**: `act.choice` 분포는 TP 항목 값 + 주어진 사실만의 함수다. TP 값을 고정하고 그 밖의 관측을 바꿔도 액션 분포가 같아야 한다.

## 3. 등급 (학습자 수준별 차등)
| 등급 | 묻는 항목 | 입력 눈금 | 레인지 입력 |
|---|---|---|---|
| 초보 | `opp.loose`, `opp.range`, `hand.equity`, `act.choice` | 5단계(0/25/50/75/100) | 상위 X% 슬라이더 하나 |
| 중수 | + `opp.aggr`, `opp.bluff`, `board.adv`, `hand.future`, `plan.pot`, `plan.icm`, 벳 사이즈 | 11단계(10 간격) | 상위 X% + 칸 덧칠 보정 |
| 고수 | + `opp.foldy`, `act.foldprob`, 세분 사이즈 | 0–100 | 13×13 가중치 직접 편집 |

- 등급마다 **그 등급 TP로 제한된 최적 정책**(TP-GTO-초/중/고)을 따로 학습한다. 초보 등급 정답은 "고수 AI의 값을 반올림한 것"이 아니라 "초보 TP만으로 둘 때 최선인 값"이다(ADR 0009).
- 채점 허용 오차는 등급별 눈금의 반 칸이다(초보 ±12.5, 중수 ±5, 고수 ±3, v0 값). 허용 오차 밖은 오차 크기에 비례해 감점한다.

## 4. 유형 버킷 (둔감성 — Gate S)
아래 조건 축은 버킷 안에서 TP 값이 크게 변하지 않아야 한다(v0 경계, D2에서 판별력 측정 후 확정).

| 축 | 버킷 경계 |
|---|---|
| 유효 스택 (BB) | ≤5 · 5–10 · 10–15 · 15–25 · 25–40 · 40–60 · 60–100 · 100+ |
| 벳·레이즈 크기 (팟 비율) | ≤33% · 33–60% · 60–85% · 85–120% · 120%+ · 올인 |
| 프리플랍 레이즈 크기 (BB) | ≤2.5 · 2.5–3.5 · 3.5–5 · 5+ · 올인 |
| 인원(액션에 남은 사람) | 헤즈업 · 3인 · 4인+ |
| 포지션 | 블라인드 · 얼리 · 미들 · 레이트(CO·BTN) |
| 토너먼트 단계 | 초반 · 중반 · 버블 근처 · 머니인 · 파이널 테이블 |

- 같은 버킷 안의 섭동: 판단 항목 변화 ≤ 등급 눈금 한 칸, 액션 분포 총변이거리 ≤ τ(v0 τ=0.15).
- 버킷 경계에서 값이 급변(절벽)하는 것도 막는다: 경계 양쪽 인접 값의 변화량은 버킷 간 평균 변화량의 2배를 넘지 않는다.
- 사이즈 버킷: 프리플랍 2.2x·2.5x·3x·올인, 포스트플랍 33%·50%·75%·100%·150%·올인. 사용자가 고른 사이즈는 가장 가까운 버킷으로 채점한다.

## 5. 학습 섹션 난이도 (항목별)
같은 항목도 주는 정보로 난이도를 나눈다. 예: `board.adv`
- 쉬움: 상대 핸드와 내 핸드를 보여준다.
- 보통: 상대 레인지와 내 핸드를 보여준다.
- 어려움: 상대의 이전 액션 흐름만 보여준다(예: 프리플랍 6BB 3벳, 플랍 체크, 턴 체크).

## 6. 열린 질문 (D2 연구 대상)
- 멀티웨이 팟에서 `opp.*`를 상대별로 물을지, "가장 위험한 상대" 하나만 물을지.
- `plan.pot`의 의미 정의를 정책 내부 의도로 둘지, 다음 액션의 기대 팟 성장으로 계산형으로 바꿀지.
- 캐시게임 전용 항목(예: 스택 깊이 플레이)과 토너먼트 전용 항목(`plan.icm`)의 분기.
