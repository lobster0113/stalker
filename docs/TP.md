# Thinking Process (TP) 명세 — v0.3 (보호 문서 — `referee-change` 절차로만 수정)

- 상태: **v0.3 중간본** (2026-10-30: 블로커 항목 `hand.block` 신설, `hand.outs`·`hand.vuln`의 무늬 인식·카드 제거·백도어 정의 명시 — #395, ADR 0019 §3.1 B1. 2026-10-30: §6 사이즈 버킷을 실전 사이즈로 넓히고 메뉴 밖 사이즈 번역 규칙을 정함 — #382. 2026-10-29: 초보 `hand.equity` 질문 형태를 순위형으로 — ADR 0011 #263 결정. v0.1 2026-10-27). v0(사용자 예시 보완)에 설계 리뷰(`docs/research/2026-10-27-design-review.md`, ADR 0010)를 반영했다. **v1은 E1·장난감 게임 실험과 판별력 측정 뒤 ADR로 확정**한다. 아래 수치(허용 오차·버킷 경계·기회 수)는 모두 초기안이다.
- 역할: TP는 AI(TP-GTO)·채점·웹 UI·학습 섹션이 공유하는 **단일 계약**이다. 기계 판독본은 `stalker/tp/spec/tp_v<버전>.json`이며 이 문서와 어긋나면 안 된다.
- 원칙
  1. 실전에서 사람이 몇 초 안에 할 수 있는 판단만 **묻는다**. 계산은 화면이 대신 보여준다.
  2. 항목마다 정의식·조건·N/A·가정·신뢰도가 있다. 정의가 하나로 정해지지 않는 항목은 **채점하지 않는다**.
  3. 정답은 "공개 관측 + 명시한 가정" 아래의 **조건부 값**이다. 실제 숨은 카드는 정답 계산에 쓰지 않는다(§2).

## 1. 세 층: 사실 · 판단 · 결정
| 층 | 내용 | 사용자 입력 | 정책에서의 위치 |
|---|---|---|---|
| **사실 (DecisionContext)** | 이미 공개돼 있거나 공개 정보로 기계적으로 계산되는 값 | 없음(화면이 자동 표시) | 액션 헤드에 직접 입력 가능 |
| **판단 (TP Judgments)** | 훈련할 가치가 있는 추정·판단 | 있음(등급·모드에 따라) | 액션 헤드에 TP 값으로 입력 |
| **결정 (Decision)** | 합법 액션과 사이즈 | 있음 | 액션 헤드의 출력 |

### 1.1 DecisionContext v0.1 (허용 사실 목록, 버전 관리)
스트리트, 내 포지션, 버튼 대비 위치, 행동 가능한 상대 수와 각자의 포지션, 이번 스트리트 공격자(마지막 벳·레이즈한 좌석), 프리플랍 공격자, 합법 액션과 콜 금액·최소/최대 레이즈, 팟, 유효 스택(BB), SPR, **필요 에퀴티(팟 오즈)**, 올인 여부, 공개 보드, 내 홀카드, (토너먼트) `tournament_public_summary`(§1.2).
- 이 목록에 없는 정보는 액션 헤드가 TP를 거쳐서만 받는다(Gate T1). 목록에 필드를 추가하는 것은 "TP 우회 통로가 되지 않는가"를 검토하는 TP 버전업이다.

### 1.2 tournament_public_summary (공개 가능한 항목만)
`total_entries`, `remaining_players`, `paid_places`, `payout_vector`, `blind_level`, `next_blind_change`(남은 핸드 또는 가상 시간), 내 순위, 스택 분포 요약(9분위, 라운드 시작 시점). 타 테이블 개인의 액션 이력은 넣지 않는다.

## 2. 정보 계약 (정답이 무엇을 근거로 하는가)
| 계약 | 담는 것 | 쓰는 곳 |
|---|---|---|
| `PublicObservation` | 내 홀카드, 공개 보드, 공개 액션·스택·포지션, 같은 `game_id` 안의 공개 쇼다운, 공개 대회 요약 | 정책 입력, 사용자 화면 |
| `TeacherContext` | 가정한 상대 정책(ID·버전), 시뮬레이터 설정 | **오프라인** 정답 레이블·검증 |
| `PrivateWorldState` | 타인 실제 홀카드, 덱·RNG 상태 | **엔진 전용**(정산·정합성 검사) |

- `opp.range` 정답 = P(상대 핸드 | `PublicObservation`, `TeacherContext`의 상대 정책). 실제 숨은 카드는 카드 제거에도 쓰지 않는다.
- 숨은 카드·덱만 다르고 `PublicObservation`과 상대 정책 가정이 같으면, 정책 출력과 TP 정답 레이블은 같아야 한다(Gate L7).
- 실사용 복기처럼 상대 정책을 모르는 경우에는 정답 레인지가 아니라 **가정별 추정 레인지 + 불확실성**을 보여준다.

## 4. 등급과 상호작용 모드 (서로 다른 축)
### 4.1 등급 = 지식 깊이
| 등급 | 묻는 판단 | 눈금 | 레인지 입력 |
|---|---|---|---|
| 초보 | `opp.loose`, `opp.range`, `hand.equity`, (포스트플랍) `board.adv`, `hand.outs` | 5단계(0/25/50/75/100) | 프리셋(타이트/보통/루즈) 또는 상위 X% |
| 중수 | + `opp.aggr`, `opp.value`, `hand.vuln`, `hand.block`, `plan.foldeq`, `plan.icm` | 11단계 | 상위 X% + 칸 보정 |
| 고수 | + `opp.foldy`, `board.nut` | 0–100 | 프리셋 + 보정(Quick), 169칸 편집은 Deep만 |

- 등급별 별도 정책을 바로 학습하지 않는다. 먼저 **한 정책 + 등급별 TP 양자화**를 비교하고, 분리 학습이 EV와 교육 효과에서 확실히 나을 때만 나눈다(ADR 0010).
- 채점 허용 오차 초기안: 등급 눈금의 반 칸(초보 ±12.5, 중수 ±5, 고수 ±3).
- 질문 형태(v0.2): 초보의 `hand.equity`는 순위형(내 레인지의 상위 몇 %, 5단계)으로 묻는다. 명세 `items[hand.equity].question_forms.beginner`. 중수·고수와 `hand.eq_call`은 이길 확률(형태 A).
  - 정답: `share_better`(§3.1 `hand.equity` 행). 0 = 레인지 최상위.
  - 척도: 구간 경계 `bands` = 0.2·0.4·0.6·0.8, 칩 = `min(4, floor(share_better × 5))`(구간은 [하한, 상한)) → 칩 0 "상위 20%", 1 "20–40%", 2 "40–60%", 3 "60–80%", 4 "하위 20%".
  - 채점: 칩 c를 0–100 위치 (4 − c) × 25(약 → 강, 초보 눈금 `steps`)에 놓고 초보 허용 오차 ±12.5로 채점한다 — 같은 칩만 만점, 한 칸 차이는 오차 25.

### 4.2 모드 = 상호작용 방식
| 모드 | 쓰는 곳 | 묻는 것 | 측정 |
|---|---|---|---|
| Quick | 게임 중 매 결정 | 핵심 판단 1~3개 + 액션(등급별 선택 규칙은 TP JSON에 고정) | 결정당 입력 시간 P50/P95, 중단율 |

- 사용자가 액션을 먼저 고르고 나중에 분석을 요청하는 흐름도 지원한다.

## 5. 채점 원칙
- 판단·계산 항목: 오차 ≤ 허용이면 100, 아니면 오차에 비례해 감점. N/A·채점 제외 항목은 점수에 넣지 않는다.
- 정책이 낸 계산 항목과 정의식 재계산의 허용 오차(Gate T2, 명세 `grading.t2_tolerance`): 0–100 척도 1점(정수 반올림 0.5점 + 참조 표의 몬테카를로 오차 여유), `risk_premium_pp` 0.5%p.
- **연쇄 채점**: 계산 항목은 ① 사용자가 입력한 앞 항목 값으로 다시 계산한 값과 비교(계산 실수), ② 정답과 비교(앞 판단 오차의 전파). 약점은 ①이 낮으면 그 항목, ②만 낮으면 앞 판단 항목에 기록한다.
- **액션**: 대안 액션별 반사실적 가치 Q(s,a)가 있을 때만 EV 손실로 채점한다. 최선 대비 EV 차이가 허용치(초기안 팟의 1%) 이하인 액션은 모두 만점(혼합 전략 존중). Q가 없으면 "EV 손실 미산출"로 표시하고 점수 대신 참고 정보만 준다. 단일 핸드에 빈도 감점은 없다. 빈도는 같은 유형을 반복한 **누적 분포**로만 비교한다.
- **신뢰도 라벨**: 모든 정답 화면은 정답 출처의 승인 상태를 표시한다 — `모의`(규칙 기반 대체) / `검증 중`(SIM_VALIDATED·BENCHMARKED) / `검증 완료`(PEDAGOGY_APPROVED). `referee/GATES.md` "모델 승인 상태".

## 6. 유형 버킷과 민감성 (Gate S)
- 둔감해야 할 조건 축(초기안 경계): 유효 스택 ≤5·5–10·10–15·15–25·25–40·40–60·60–100·100+ BB / 벳 크기 ≤33·33–60·60–85·85–120·120%+·올인 / 프리플랍 레이즈 ≤2.5·2.5–3.5·3.5–5·5+ BB·올인 / 인원 헤즈업·3인·4인+ / 포지션 블라인드·얼리·미들·레이트 / 토너먼트 단계 초반·중반·버블 근처·머니인·파이널 테이블.
- **민감 예외**: 버킷이 같아도 ① 합법 액션 집합이 다름, ② 올인 여부·콜 가격이 스택의 임계(예: 콜하면 남는 스택 < 1BB)를 넘음, ③ 페이점프·버블 상태가 바뀜, ④ 독립 기준(앵커·솔버)에서 최선 액션의 EV 우위가 임계 이상 바뀜 — 이면 값이 바뀌어도 된다. 이런 지점은 "민감해야 할 골든 스팟"으로 모아 지나친 평탄화도 실패시킨다.
- 사이즈 버킷(실전 사이즈, #382): 소유자 결정(2026-10-30) — 사이즈는 실전과 같아야 하며 계산 비용 때문에 줄이지 않는다. 학습 메뉴 `real`(`stalker/e3/game.py`, 웹 거울 `web/app/tpgto.js`)이 이 목록 그대로다. 모든 사이즈는 최소 레이즈 이상이고, 칩이 같아지는 사이즈는 한 번만 둔다.
  - **금액 기준(#412)**: 모든 ×N·BB 사이즈는 **레이즈 투(raise-to)**, 즉 그 스트리트에 낸 총액이다(레이즈 바이 아님). 오픈 3 BB = 총 300칩. 3벳·4벳 ×N = N × 현재 벳(2.5BB 오픈에 3x 3벳 = 총 7.5BB, 2.5 + 7.5 아님). 포스트플랍 레이즈 ×N = N × 현재 벳(1BB 벳에 3x = 총 3BB). 포스트플랍 벳 % = 그 스트리트에 이미 낸 칩 + 팟 × 비율(최소 1BB). 검사: `tests/test_e3_legal_vs_menu.py`, `web/app/test/tpgto.test.mjs`.
  - 프리플랍 오픈: 2·2.2·2.5·3·3.5·4·5·6·8·10 BB·올인. 림퍼가 있으면 각 오픈 + 림퍼당 1 BB(아이솔레이션, 스몰 블라인드 컴플리트도 림프).
  - 프리플랍 3벳(오픈에 대해): 2.5·3·3.5·4·5x·올인.
  - 프리플랍 4벳(3벳에 대해): 2·2.2·2.5·3x·올인.
  - 프리플랍 5벳 이상: 올인만(실전에서 대개 그렇다 — 소유자). **학습 메뉴 규칙**이다(아래).
  - 포스트플랍 벳: 20·33·50·75·100·150·200·300% 팟·올인.
  - 포스트플랍 레이즈(벳·레이즈에 대해): 2.5·3·4·5·7·10x·올인.
  - **학습 메뉴 규칙 ≠ 합법 규칙(#412)**: ① 프리플랍 5벳 이상은 올인만, ② 최소 레이즈를 메뉴 사이즈로 따로 두지 않음(×N 금액이 최소 레이즈보다 작을 때만 최소 레이즈로 올린다), ③ 레이즈 상한이 없는 스트리트에서 스택의 80%(`ALLIN_MERGE`) 이상인 레이즈는 올인으로 합침, ④ 스트리트당 레이즈 상한 — 이 넷은 정책이 고르는 **메뉴**만 줄인다. 사람(과 봇)은 언제나 노리밋 합법 금액 아무것이나 낼 수 있고(올인 아닌 5벳, 최소 레이즈, 스택의 80–99% 레이즈, 상한을 넘은 레이즈 포함, `G.apply_to`·웹 `applyBet`), 그 금액은 아래 번역으로 메뉴 라벨로 읽힌다.
  - 합법 금액(노리밋, TDA·PokerKit과 같다): 현재 벳 + 마지막 **풀 레이즈** 이상, 올인 이하. 그보다 적은 올인도 합법이다. 풀 레이즈에 못 미치는 올인은 베팅을 다시 열지 않는다 — 이미 액션한 플레이어는 콜·폴드만 할 수 있고, 아직 액션하지 않은 플레이어의 최소 레이즈는 현재 벳 + 마지막 풀 레이즈다. Gate R(`referee/gate_r/e3_suite.py`의 `EDGE_CASES`)이 이 경우들을 PokerKit과 대조한다.
- 메뉴 밖 사이즈 번역(`stalker/e3/translate.py`): 사람이든 봇이든 최소 레이즈부터 올인까지 아무 칩이나 낼 수 있다. 사이즈를 x = (낸 금액 − 현재 벳) / (팟 + 콜 금액), 즉 콜한 뒤 팟 대비 비율로 재고, 이웃한 두 메뉴 사이즈 A < B(비율 a < b) 사이에서 의사 조화 매핑(pseudo-harmonic, Ganzfried & Sandholm 2013)으로 A에 확률 f = (b − x)(1 + a) / ((b − a)(1 + x)), B에 1 − f를 준다.
  - 메뉴 사이즈와 정확히 같으면 그 사이즈, 가장 작은 메뉴 사이즈보다 작으면 그 사이즈, 올인은 올인이다. 가장 큰 사이즈와 올인 사이는 올인을 B로 쓴다. 합법 액션만 후보다(레이즈 상한에 닿은 스트리트는 올인만 남는다).
  - 채점: 결정적 확률 분할. 사용자 액션의 점수 = f × (A로 본 점수) + (1 − f) × (B로 본 점수). 같은 입력이면 같은 점수이고, 난수에 따라 점수가 갈리지 않는다.
  - **번역 오차 큼(#417, `stalker/e3/translate.high_translation_error`, 웹 `translationError`)**: 사전 등록 규칙이며, 아래 둘 중 하나면 그 사이즈의 분할은 믿을 만한 읽기가 아니다.
    - 이웃 하나만 올인이고(다른 이웃은 올인이 아님) 낸 금액이 스택의 **80%**(`ALLIN_MERGE` = 0.8) 미만이다. 올인으로 읽으면 다음 좌석이 할 수 있는 일이 바뀌므로 가중치와 무관하게 표시한다.
    - 두 이웃 모두에서 멀고(**0.2 < f < 0.8**, `F_BAND`) 두 이웃의 팟 비율이 **2배**(`GAP_HIGH` = 2.0)보다 크게 벌어져 있다. 근거: 이 간격이면 같은 핸드가 A와 B에 다르게 답하는 비율(응답 TV)이 **0.25**(`TV_HIGH`) 이상이었다.
    - 표시된 사이즈는 **근사로 채점한다**: 분할 가중 점수를 그대로 만점으로 주지 않고 `근사(번역)`·`≈` 표시와 두 이웃의 비중·각 이웃의 정책 빈도를 함께 보여준다. 규칙 자체는 바꾸지 않는다. 지도(사이즈별 f·응답 TV·표시 여부): `python -m stalker.tools.translation_map --policy web/app/policy/mid-6.json`.
  - AI가 사용자 사이즈를 읽을 때(히스토리 라벨·키·레인지 갱신): 같은 분할에서 **명시 시드 `numpy.random.Generator`로 하나를 뽑는다**. 고정 임계값(예: f ≥ 0.5)은 경계 바로 너머 사이즈로 큰 벳의 반응을 싸게 사는 착취가 가능하다. 시드가 같으면 핸드가 그대로 재현된다.
  - "가장 가까운 버킷" 규칙은 폐기한다. 심판 LBR의 착취 탐색(`referee/e3/lbr.py`)은 평가 도구라 가장 가까운 사이즈를 그대로 쓴다(그 문서 참고).
