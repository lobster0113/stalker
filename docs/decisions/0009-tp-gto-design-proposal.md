# ADR 0009 (제안): TP-GTO 학습 설계 — 개념 병목 정책 + 둔감성 정규화

- 상태: **제안** (2026-10-27, 방향 전환 세션). D2에서 Researcher 조사와 소규모 실험으로 검증한 뒤 채택/수정한다. 채택 전에는 이 문서의 수치를 근거로 쓰지 않는다.
- 근거: `docs/CHARTER.md`, `docs/TP.md`, `referee/GATES.md`.
- **2026-10-27 ADR 0010 보완**: 항목 의미 고정은 실제 숨은 카드가 아니라 `TeacherContext`(가정한 상대 정책)로 한다. 액션 헤드 입력은 TP + DecisionContext. PPO는 기본 가설이고 장난감 게임·E1에서 CFR/PSRO와 대조한다. 등급별 정책은 "한 정책 + 양자화" 비교 뒤에만 분리한다. 첫 환경은 E0(장난감)·E1(헤즈업 푸시/폴드).

## 문제
행동이 TP 항목을 거쳐서만 결정되고(Gate T), 항목 값이 이름대로의 의미를 가지며(Gate T2), 조건 버킷 안에서 둔감하고(Gate S), 그 제약 아래에서 가능한 한 강한(Gate Q) 정책을 학습해야 한다.

## 선택지
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 개념 병목 RL | 관측 → (자유 인코더) → TP 항목 헤드 → 액션 헤드(TP 값 + 주어진 사실만 입력). Self-play로 학습 | 멀티웨이·토너먼트·게임 내 적응까지 한 구조로 | 항목이 이름과 다른 의미로 표류할 수 있다 |
| B. 솔버 증류 | 솔버(TexasSolver·자체 CFR)로 스팟을 풀고 TP 구조 모델로 증류 | 헤즈업에서 이론적으로 강하다 | 멀티웨이·게임 내 적응을 못 다루고 스팟 생성 비용이 크다 |
| C. 혼합(추천) | B로 헤즈업·프리플랍 교사 데이터를 만들어 A를 초기화하고, A를 self-play로 미세조정 | 두 장점 | 파이프라인이 길다 |

## 추천 구조 (C)
1. **항목 의미 고정(표류 방지)**: 시뮬레이터 안에서는 상대 정책을 알므로 "계산" 항목과 `opp.range`의 정답을 정확히 계산할 수 있다. 항목 헤드에 이 정답을 보조 지도 손실로 건다. 액션 헤드는 지도 대상이 아니라 RL 목적함수로만 학습한다.
2. **병목의 기계적 강제**: 액션 헤드는 TP 벡터와 주어진 사실만 입력받는 별도 모듈로 만들어, 구조상 다른 관측을 볼 수 없게 한다(Gate T1이 테스트한다).
3. **둔감성**: 조건 축을 `docs/TP.md` §4 버킷의 부드러운 원-핫(경계 근처 보간)으로 인코딩하고, 버킷 내 섭동 쌍에 대한 일관성 손실(TP 값·액션 분포 차이 패널티)을 둔다.
4. **등급별 정책**: 초보·중수·고수 TP마다 묻지 않는 항목을 병목에서 제거하고 눈금을 양자화한 정책을 따로 학습한다(같은 인코더 사전학습 공유 가능).
5. **환경 분리**: `env_id`(캐시 인원·스택 깊이, 토너먼트 구조 클래스)마다 정책을 따로 둔다. 첫 환경은 연산이 작은 것부터: ① 6max 캐시 100BB, ② 9인 SNG 표준 구조.
6. **게임 내 정보**: `opp.loose/aggr/foldy`는 `GameMemoryStore` 통계의 베이지안 수축(ADR 0006 AI-1)으로 시작한다. 순서 메모리(GRU)는 Gate Q 제거 실험으로 정당화될 때만 넣는다.

## D2에서 확인할 것
- 시뮬레이터 처리량(핸드/초)과 1환경 학습에 필요한 핸드 수 추정 → 연산 비용(ADR 0004 다시 산정, NEEDS_HUMAN).
- 작은 환경(헤즈업 푸시/폴드, 헤즈업 리버 1스트리트)에서 병목 정책이 내시 앵커에 얼마나 근접하는가(복잡성 비용의 첫 측정).
- `plan.pot` 등 판단 항목이 의미 있게 학습되는지, 아니면 계산 항목으로 바꿔야 하는지.
