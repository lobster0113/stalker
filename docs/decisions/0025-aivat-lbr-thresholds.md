# ADR 0025: 웹 정책 LBR 판정을 AIVAT 보정 열로 (`lbr_thresholds_v3.json`)

- 상태: 제안 → 이 PR 머지로 채택 (Builder 추천안으로 진행, `harness/PROTOCOL.md` §9)
- 이슈: #792 (#785·#781 후속). ADR 0020·0024를 웹 정책 LBR 결과에 한해 개정한다. 합격선 값·핸드 수는 바꾸지 않는다.
- 수치는 모두 `docs/research/2026-11-lbr-variance-reduction.md` 「CI 측정」 절의 CI 값(run 43111293721, `ops:cloud/results/43111293721.json`, 시드 8개)이다.

## 문제
웹 정책 LBR(`stalker.web.policy-lbr`) 판정은 기존 열 `lbr_bb`를 읽는다. 시드 간 sd가 커서 v2는 3–6인에 시드 2개(`min_seeds.lbr` 1·2·2·2·2)를 요구하고, 그래도 D 2–5인(#384) 판정이 시드 운에 흔들린다. #781이 같은 핸드에서 분산을 줄인 AIVAT식 보정 열 `aivat_lbr_bb`(schema 2, `--aivat-samples 8`)를 결과에 더했고, #785가 CI로 그 효과를 쟀다.

- sd 비율은 9칸 모두 0.27–0.59(중앙 0.35). 평균 차는 9칸 중 7칸 |t|<1.5, |t|>2인 두 칸(2인 끔 −2.11, 5인 켬 +2.29)은 부호가 반대다.
- k = ⌈(2·sd/여유)²⌉(ADR 0024와 같은 식)는 보정 열에서 모든 칸이 1이다. 시드 8개 sd는 상대 ±26%라 대략치지만, 가장 작은 여유/sd(5인 끔 2.99)도 k=1 경계(2)를 넘는다.

## 선택지
- **(a) 판정 열만 보정 열로, 선·핸드는 v2 그대로, `min_seeds.lbr`는 모두 1.**
- (b) (a) + 평균 차만큼 선을 옮김(2인 −0.69, 5인 +0.40). 시드 8개로는 편향이 0.3bb보다 작다고도, 그 부호가 안정하다고도 말할 수 없어(위 표 se 0.18–0.33) 잡음을 선에 새기게 된다.
- (c) 유지(v2, 기존 열). sd 1/3 효과를 버리고 시드 2개 비용을 계속 낸다.

## 결정 (추천: a)
1. **판정 열.** `referee/e3/lbr_thresholds_v3.json`에 `"column": "aivat_lbr_bb"`를 둔다. `referee/e3/thresholds.py:judge`는 표의 `column`(없으면 `lbr_bb`)을 읽는다. v1·v2는 바이트 그대로이며 `column`이 없어 기존 열을 읽는다.
2. **선·핸드·`min_seeds`.**

   | 인원 | `lbr_max` | `lbr_average_max` | `hands` | `min_seeds` lbr / lbr_average |
   |---|---|---|---|---|
   | 2 | 9.0 | 8.7 | 2000 | 1 / 2 |
   | 3 | 6.4 | 5.2 | 2000 | 1 / 2 |
   | 4 | 4.0 | 3.7 | 600 | 1 / 2 |
   | 5 | 3.1 | 3.0 | 600 | 1 / 2 |
   | 6 | 2.7 | 2.7 | 1000 | 1 / 2 |

   - 선·핸드는 v2와 같다. 선은 회귀 가드(ADR 0020)이고, 보정 열은 같은 양의 다른 추정량일 뿐이라 기준값을 바꿀 이유가 없다. 핸드를 그대로 두는 것은 se·sd 표가 이 핸드 수에서 잰 값이기 때문이다.
   - `min_seeds.lbr` 1: 위 표 k 보정이 모든 칸 1이다(서비스 칸: 2–5인 켬, 6인은 레거시 끔).
   - **평균 차의 반영(선 여유로 흡수).** 5인 켬은 보정 열이 +0.40 ± 0.18 높아 여유가 1.55→1.15로 준다. 그래도 여유/sd 7.5이고, 평균 차를 2 se까지 더 키워도(+0.76) 여유 0.79가 남아 현재 정책이 잡음으로 fail할 위험은 작다. 2인 끔은 보정 열이 −0.69 ± 0.33 낮아 가드가 기존 열 기준으로 최대 약 1.35bb(2 se 포함) 느슨해진다. 2인 끔은 진단 칸이고 서비스 칸 2인 켬의 차는 −0.29 ± 0.32(잡음 범위)이며, 선 9.0 대비 회귀를 잡는 목적에는 이 정도 느슨함을 받아들인다. 따라서 선을 옮기지 않는다(선택지 b 기각 이유와 같다).
3. **`lbr_average`에도 같은 열.** 표 하나에 열 하나(`column`)로 둔다. 같은 표 안에서 종류마다 다른 추정량을 쓰면 두 종류의 선 비교가 어긋난다. 지금 웹 잡은 현재 정책 LBR만 재므로 `lbr_average`는 칸이 없어 `insufficient`(실패 아님)이고, 시드 수 근거(보정 열 sd)가 없으므로 `min_seeds.lbr_average`는 2로 둔다.
4. **보정 열이 없는 입력은 오류.** v3 표로 판정하는 칸(판정 핸드 수와 같은 칸)에 `aivat_lbr_bb`가 없으면(schema 1 결과) `ThresholdError`를 낸다: "`--aivat-samples 8`(schema 2)로 잡을 다시 돌리거나 `--thresholds v2`로 판정하라". `insufficient`로 두면 잘못된 입력이 "시드 부족"처럼 보여 알아채기 어렵다. `record()`는 이 오류도 파일의 `error`로 남기고 예외를 던지지 않으므로 CI 판정은 계속 기록 전용이다.
5. **적용 범위.** v3는 웹 정책 LBR 결과의 기본 표다. 웹 결과에는 설계상 `job`·`by_players`가 없으므로(`stalker/tools/web_policy_lbr_job.py` 문서) `--job ... --results-dir`로는 잡히지 않는다. 그래서 `python -m referee.e3.thresholds <ops:cloud/results/<run>.json>`에 웹 결과를 직접 주면 서비스 칸(백오프 켬, `legacy_pages`는 끔)을 시드별 요약으로 풀어(`from_web_result`) v3로 판정한다(`--thresholds v1|v2|v3`로 표 선택 가능). 학습 요약(`by_players`, `--job`, 런처 `record`)은 보정 열이 없으므로 기본 표가 v2 그대로다.

## 결과
- run 43111293721 결과를 v3로 판정하면 서비스 칸 2–6인 모두 pass(보정 평균 5.781·4.677·2.646·1.950·0.766, 시드 8). `tests/test_lbr_thresholds.py`가 이 결과(판정 키만 남긴 고정 파일 `tests/fixtures/web_policy_lbr_43111293721.json`)로 고정한다.
- 웹 잡(`web_policy_lbr_job.plan`)의 시드 수와 결과의 `pass`는 지금도 v2(기존 열)를 읽는다. 잡 변경은 이 ADR 범위 밖이며, 잡의 `min_seeds`를 v3로 낮추는 것과 런처가 웹 결과의 v3 판정을 `ops:cloud/verdicts/`에 남기는 것(하네스 경로)은 후속이다.

## 되돌리는 조건
다음 중 하나면 v3 판정을 멈추고(`--thresholds v2`로 판정) 새 측정 뒤 새 버전 파일로 정한다.
- 서비스 칸 하나에서 시드 8개 이상 쌍 비교의 평균 차(보정−기존)가 |0.5|bb를 넘고 |t|>3.
- 보정 열 sd 비율이 서비스 칸에서 0.8을 넘는다(분산 감소 효과가 사라짐).
- `referee/e3/lbr.py`의 보정 추정량(`lbr_hands`)이나 `aivat_samples` 기본값이 바뀐다.
- v3 fail이 났는데 같은 결과의 v2 판정이 pass면, 정책을 되돌리기 전에 시드 8개로 다시 재서 위 두 조건을 먼저 확인한다.
