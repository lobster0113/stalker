# ADR 0014: RunPod 잡 결과 회수 — 토큰 경로 HTTP 당겨 오기

- 상태: 제안 → 이 PR 머지로 채택
- 이슈: #184

## 문제
- 런처(#20)는 파드를 만들고, 감시하고, 종료한 뒤 비용만 기록한다. 파드가 만든 결과(요약 JSON, 정책 파일)는 돌려받지 않는다.
- CPU 학습은 `train.yml`(GitHub Actions, #222)로 옮겨 결과가 아티팩트·ops로 바로 회수된다. 남은 것은 GPU가 필요한 RunPod 잡이다(#264가 이 이슈에 막혀 있다).
- 제약: 파드에 GitHub 토큰을 주지 않는다. RunPod 키는 Secret에만 있다. 리포·아티팩트·로그는 공개다.

## 결정
**(a′) 런처가 RunPod HTTP 프록시로 결과를 당겨 온다.**
1. 스펙 선택 키 `result_path`(결과 JSON 경로). 설정 시 런처가 실행마다 `secrets.token_hex(16)` 토큰을 만들어 파드 env로 넘기고 `8000/http` 포트를 연다. 토큰은 명령·로그·원장에 쓰지 않는다.
2. 파드 명령을 감싼다. 잡 명령 → 결과 복사 → `status.json`(종료 코드)을 원자적으로 쓴다 → `/<토큰>/` 아래 두 파일만 `http.server`로 내놓고 대기한다. 빈 `index.html`을 두어 디렉터리 목록을 막는다. 그래서 토큰을 모르면 파일 이름에 닿을 수 없다.
3. 런처는 감시 루프에서 `status.json`을 폴링한다. 종료 코드가 0이면 `result.json`을 받는다. 상한+1 바이트만 읽고, UTF-8 JSON과 비밀 패턴을 검사한 뒤 저장한다. 그다음 파드를 종료한다. 프록시 요청에는 인증 헤더를 붙이지 않는다.
4. `cloud.yml`이 결과를 아티팩트 `cloud-result-<run id>`로 올린다. 원장 end 줄에 크기와 sha256을 남긴다.

## 대안
- (a) 로그 API로 stdout 끝부분 받기: RunPod REST v1에 파드 로그 엔드포인트가 문서화돼 있지 않다. 로그는 크기 제한과 줄 깨짐이 있어 정책 파일에는 맞지 않는다.
- (b) 파드가 GitHub Release에 업로드: 파드에 쓰기 토큰이 필요하다. 이미지나 명령이 오염되면 리포가 노출된다. 기각.
- (c) 네트워크 볼륨: 데이터센터에 고정되고 월 저장 비용이 든다. 회수하려면 또 다른 파드나 S3 호환 API 키가 필요하다. 체크포인트가 상한을 넘을 만큼 커지면 다시 검토한다.

## 위험과 대응
- 토큰 경로는 결과가 나온 뒤 파드가 종료될 때까지(폴링 간격 30초 + 다운로드 시간) 공개 URL로 열려 있다. 토큰은 128비트이고 어디에도 기록하지 않는다. 결과는 어차피 공개 아티팩트가 되므로 노출 위험이 더 커지지 않는다.
- 이미지에 `python3`가 없으면 서버가 뜨지 않는다. 그러면 `max_minutes`에 `timeout`으로 끝난다(비용 상한 안). `jobs/README.md`에 요구 사항을 적었다.
- 결과를 내놓은 뒤 파드는 대기 상태로 과금된다. 런처가 다음 폴링(≤30초)에 회수하고 종료하므로 추가 비용은 그만큼이다.
- 실제 RunPod 프록시 동작은 가짜 전송 테스트로만 검증했다. 감싼 셸 스크립트는 테스트가 실제 bash와 `http.server`로 실행해 확인한다. 첫 GPU 잡(#264)이 실측 검증이다.

## 후속
