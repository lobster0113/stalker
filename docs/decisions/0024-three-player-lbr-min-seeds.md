# ADR 0024: 3인 `min_seeds.lbr` 1→2 (`lbr_thresholds_v2.json`)

- 상태: 제안 → 이 PR 머지로 채택 (Builder 추천안으로 진행, `harness/PROTOCOL.md` §9)
- 이슈: #768 (#762 후속). ADR 0020을 일부 개정한다(3인 `min_seeds.lbr`만). 합격선·핸드 수는 바꾸지 않는다.
- 수치는 모두 `docs/research/2026-11-c1-web-export.md` 「evalnoise8」 절의 CI 값(run 42992919047, `ops:cloud/results/42992919047.json`)이다. 직접 돌린 값은 없다.

## 문제
ADR 0020은 3인 현재 LBR을 시드 1개로 판정하게 했다(2–3인 sd ≪ se라는 시드 3개 자료 근거). 서비스 설정(백오프 켬)을 시드 8개로 재면 3인 켬 sd는 .818, 여유(선 6.4 − 평균 4.779) 1.621, 여유/sd 1.98이다. 시드 하나의 값이 평균에서 2 sd 가까이 벗어날 수 있어(최소 k = ⌈(2·sd/여유)²⌉ = 2) 시드 1개 판정으로는 부족하다. 켬 칸의 시드별 값: 4.578 3.787 5.190 5.680 4.563 5.650 3.503 5.278.

## 선택지
- **(a) 3인만 1→2 (켬 기준)** — 서비스 판정에 쓰는 켬 칸에서 k가 현재 값보다 큰 것은 3인뿐이다(켬: 2인 1·4인 1·5인 1, 모두 현재 값 이하).
- (b) 끔 칸까지: 2인 1→2(k=2)·4인 2→3(k=3)도 올림. 끔은 진단용 칸이라 판정에 쓰지 않는다. 비용만 늘어난다.
- (c) 유지: 3인 판정이 시드 하나의 운에 좌우된다.

## 결정 (추천)
**(a).** 3인 `min_seeds.lbr`을 2로 올린다. 값이 sha256 고정인 v1은 바이트 그대로 두고 새 파일 `referee/e3/lbr_thresholds_v2.json`(차이는 `players.3.min_seeds.lbr` 하나)을 `THRESHOLDS`가 가리키게 한다. 끔 칸 기준(b)은 범위 밖이다.

## 결과
- 3인 웹 LBR 잡의 시드가 1→2로 는다(`web_policy_lbr_job.plan`이 `max(min_seeds.lbr, --seeds)`개를 만든다). 3인 한 태스크는 2000핸드(끔·켬 각각)라 태스크가 3인에서만 2→4개가 된다. 8시드 잡이 6.33분(cpu5c, $0.12)이었으므로 증가분은 분 단위·센트 단위다.
- `e3_web_lbr` 지표: 결과 JSON의 3인 시드가 1개뿐이면 `summarize`가 `pass: null`(판정 불가)을 내고, `all_pass_on`은 `pass`가 모두 `True`여야 하므로 `False`가 된다. 지표는 깨지지 않고 "아직 판정 불가"로 읽힌다(`tests/test_metrics.py`로 고정). 시드 2개 이상 결과가 들어오면 다시 `True`가 될 수 있다. 필요하면 웹 LBR 잡 재디스패치는 후속 이슈.
