# ADR 0002: STALKER의 "AI"는 공개 솔버 조합 + 자체 공백 메우기로 구성한다

- 상태: 채택 (2026-10-24, 부트스트랩 세션). **ADR 0003에 의해 부분 대체** — 핵심 AI는 RL 정책, 솔버는 참조기·참조 봇·교사·앵커 역할. 근거: `docs/research/2026-10-24-public-poker-ai-survey.md`
- 맥락: 헌장 7 — 충분히 강한 공개 AI가 있으면 쓴다. 조사 결과 토너먼트용으로 그대로 쓸 공개 AI는 없다. 강한 상용 도구는 API가 없고 사람의 구매·설치가 필요하다.

## 결정
STALKER의 AI = **"오라클 계층(GTO 기준선)" + "적응 계층(정보 누적 착취)"** 으로 구성하고, 각 계층은 공개 도구를 우선 사용한다.

1. **규칙·상태·기록**: PokerKit을 게임 엔진으로 채택(자체 엔진 개발 중단). 토너먼트 진행(멀티테이블, 블라인드 레벨, 탈락·순위, 페이아웃)만 그 위에 얇게 구현. 기록은 PHH 호환 + STALKER 확장 필드.
2. **오라클 — 프리플랍(토너먼트)**: 공개 대안이 없으므로 직접 만든다. 단계적으로:
   (a) ICM 반영 푸시/폴드 내시(N인, 앤티) → (b) 오픈/3벳/올인 추상 트리의 CFR(ICM·FGS 페이오프) → 결과를 스팟 라이브러리로 사전계산.
   검증: 공개 차트·문헌 수치, 가능하면 HRC/ICMIZER 공개 출력 사례와 대조.
3. **오라클 — 포스트플랍 헤즈업**: TexasSolver 콘솔(Linux, AGPL, 개인 사용)로 스팟을 풀어 혼합전략 라이브러리화. ICM은 페이오프 변환(리스크 프리미엄) 근사로 시작하고, 오차를 측정하는 연구 이슈를 둔다.
4. **오라클 — 멀티웨이 포스트플랍**: 공백. 초기엔 휴리스틱(에퀴티 실현 + 레인지 추론) 기반 근사 정책으로 처리하고 "근사"로 표시하여 유형화 시 신뢰도를 낮춘다. 3인 스팟 솔빙은 연구 과제.
5. **적응 계층(핵심 차별점)**: 직접 만든다. 상대 모델(베이지안 스탯 + 레인지 추론) → 오라클 전략의 노드 고정/재솔브 또는 제한된 최적응답(안전한 착취)으로 이탈. 기록에는 항상 **오라클 정책과 적응 정책을 둘 다** 남긴다(적응의 크기와 이유가 학습 내용이 되므로).
6. **처리량**: 실시간 풀 솔브 대신 **사전계산 전략 라이브러리 + 조회/보간**. 토너먼트 시뮬레이션 중 결정은 라이브러리 조회(빠름), 라이브러리 미싱 스팟은 기록하고 배치로 풀어 채운다. 데이터 충분성 미달 셀이 솔브 우선순위를 정한다.
7. **강도 측정**: 헤즈업 구성요소는 Slumbot API로 벤치마크(외부 신호). 토너먼트 전체는 심판의 이론 앵커(푸시/폴드 내시, 솔버 대비 EV 손실) + 챔피언 리그.
8. **상용 도구**: 의존하지 않는다. 사용자가 구매한다면 검증용 기준(ground truth)으로만 추가 가능(별도 ADR).

## 결과
- 로드맵 Phase 1은: PokerKit 통합 → 토너먼트 러너 → 기록 스키마 → 프리플랍 오라클(a) → TexasSolver 통합 → 적응 계층 v0 순.
- 기존 시드 코드(`stalker/core` 평가기·에퀴티)는 빠른 MC 계산용으로 유지한다.
- 모든 오라클 출력에는 트리·추상화·에퀴티 모델(칩EV/ICM/FGS)·솔버 버전·정확도(exploitability)를 기록한다.
