# ADR 0011: TP v1 — 고수 단계까지 쓰이는 Thinking Process

- 상태: **제안(proposed)**. 항목마다 아래 "검증" 실험 결과(CI)가 나온 뒤 채택한다. 채택된 항목만 `docs/TP.md` v1과 `stalker/tp/spec/tp_v1.json`(referee-change)으로 옮긴다.
- 근거:
  - 조사: `docs/research/2026-10-27-tp-expert-review.md`(고수 개념 23종 대조, 이하 "조사").
  - E1 결과: `docs/research/2026-10-e1-tp-pushfold.md`(#114, #169).
  - 사용자 결정·지적(2026-10-27 대화 세션): 레인지 모양 #159, 통계 처리, 프리플랍 에퀴티, 묻는 순서, `plan.icm` 문구, 재레이즈 대응 계획.
- 영향: `docs/TP.md`, `stalker/tp/spec/`, 데모(`web/demo`), Gate T·S·F 판정 대상, 학습자 커리큘럼(#172).

## 문제
TP v0.1은 고수 단계에서 단순해진다.
- 등급 차이가 눈금의 촘촘함뿐이다.
- 고수가 실제로 쓰는 판단(레인지 모양, 블로커, 사이즈를 고른 이유, 익스플로잇 방향, 빈도)이 빠져 있다. 조사 대조표 기준으로 23종 중 11종이 없다.
- 정의가 실전과 어긋나는 항목이 있다.
  - E1에서 SB의 "무작위 핸드 대비 에퀴티"는 고수 눈금으로도 손실이 남았다.
  - 등간격 초보 눈금은 착취 가능성이 0.24 bb/핸드였다.
- 사용자 지적도 있다. 묻는 순서가 생각의 흐름과 다르다(액션 전에 폴드 확률을 묻는다). `plan.icm` 문구가 추상적이다. 프리플랍 에퀴티의 기준이 모호하다.

## 결정 (제안)

### D1. 구조
1. **묻는 순서 = 생각의 흐름**: 읽기(B 보드 → C 상대 → D 내 핸드) → F 액션(사이즈 포함) → **G 액션 점검**. G에서는 고른 액션에 맞는 근거만 묻는다.
   - 벳·레이즈: 그 사이즈의 `plan.foldeq`, 프리플랍이면 `plan.vs_raise`.
   - 콜: `plan.icm`(토너먼트), 필요 에퀴티 대비 `hand.equity`.
   - 폴드: 없음.
2. **사실층 확장(표시만)**: 알파·MDF·균형 블러프 비율·기하 사이즈·팟 오즈를 표시한다. 모두 공개 정보의 함수다. DecisionContext 버전업과 Gate T1 검토 대상이다.
3. **검토층(결정 뒤, 액션 헤드 입력 아님)**: `rev.freq`, `rev.why_size`, `rev.adjust`, `rev.oppmistake`. 정답이 정책 출력에 의존해도 순환이 없다. 모델 승인 상태가 `BENCHMARKED` 미만이면 채점하지 않는다.
4. **등급 = 항목별 숙련도의 묶음**: 최근 30회 중 90% 이상 맞히면 그 항목은 묻지 않고 표시한다. 70% 미만으로 떨어지면 다시 묻는다. 고수 Quick 모드의 질문 수는 3개 이하로 유지하고, 질문 종류가 추정에서 해석·이유로 바뀐다.

### D2. 항목 변경
| 항목 | 결정 | 근거 |
|---|---|---|
| 눈금 | 판단 항목 눈금을 **분위(순위형)** 로 한다. 초보 5칸, 중수 11칸, 고수 연속 | E1(#169): 콜당했을 때 기준 초보 0.244 → 0.019, 중수 0.037 → 0.0038, 고수 0.0015 → 0.0005 bb/핸드 |
| `hand.pct`(신규) | "내 핸드는 (이 포지션·이 라인의) 내 레인지에서 상위 몇 %인가" | 순위형 질문이 답하기 쉽고, E1에서 분위 눈금과 같은 값 |
| `hand.equity` | 멀티웨이는 남은 **모든** 상대를 이겨 팟 전체를 가져갈 확률(+분할 몫)이다. v0.1과 같고, 화면에 명시한다. **프리플랍 일반 결정에서는 묻지 않는다.** 포스트플랍, 그리고 프리플랍 올인 결정·짧은 유효 스택에서만 묻는다 | 깊은 스택 프리플랍은 실현 에퀴티·포지션·플레이 쉬움이 결과를 좌우한다(사용자 질문) |
| `hand.eq_call`(신규) | 공격 결정에서 상대 계속(콜·레이즈) 레인지 대비 에퀴티 | E1: SB 기준을 이것으로 바꾸면 고수 0.009 → 0.0015 bb/핸드 |
| `opp.range` | 너비 → 모양(선형·폴라·캡드·좁은 밸류) → 5구간 강도 분포(EMD 채점). 초보는 너비, 중수는 모양, 고수는 분포 | 사용자 지적 #159 |
| `opp.loose/aggr/foldy` | 초보: 다루지 않음. 중수: **표시**. 고수: **숨기고 관찰 문제로 출제** | 사용자 결정: 실전에는 HUD가 없다. 관찰력이 고수의 실력이다 |
| `plan.icm` | 질문 형식: "칩만 보면 필요 승률 X%(표시). 상금 구조까지 생각하면 몇 %가 필요한가?" 정의(리스크 프리미엄)는 v0.1과 같다 | 사용자 지적: "위험의 무게"는 추상적이다 |
| `plan.foldeq` | 결정 뒤 G에서 고른 사이즈로 묻는다. 고수는 두 사이즈를 묻는다(탄력성) | 사용자 지적: 순서 |
| `plan.vs_raise`(신규) | 프리플랍에서 "재레이즈(3벳·4벳)가 오면 폴드/콜/다시 레이즈" 계획. 실제 재레이즈 뒤 계획과의 일관성도 기록 | 사용자 제안, 조사 §8.2 |
| `plan.purpose`(신규) | 벳 목적: 밸류 / 블러프 / 디나이얼. `plan.pot`을 대체한다 | 조사 §4.2 |
| `hand.block`, `opp.bluffgap`(리버), `opp.icm`, `board.nut` 중수 하향, `hand.realize`(참고) | 조사 §4.1–4.2대로 | 조사 |
| `plan.pot` | 삭제 | 정의 순환. `plan.purpose`·`rev.freq`로 대체 |

### D3. 화면 원칙
- 정답마다 **왜 그런지** 근거를 보여준다. 강도 구간 비교 막대, 대표 콤보, 아웃츠 카드 목록, 계산식 등이다. 학습 섹션·훈련 게임·복기가 같은 해설 컴포넌트를 쓴다(사용자 요청, #165).
- 입력은 탭 위주로 한다. 슬라이더는 꼭 필요할 때만 쓴다(#164).

## 대안과 기각 이유
- **v0.1 유지 + 눈금만 더 촘촘히**: E1에서 정의가 잘못된 항목은 눈금을 촘촘히 해도 손실이 남았다. 고수의 차이는 해상도가 아니라 질문의 종류에서 나온다.
- **169칸 레인지 직접 입력**: 너무 느리다(사용자 지적). Deep 복기에서만 쓴다.
- **고수에게도 통계 표시**: 실전 관찰 능력을 훈련하지 못한다(사용자 결정).

## 열린 질문
조사 §7을 따른다. 추가로 G 단계 항목을 Gate T에서 어떻게 다룰지가 남아 있다. 정책 내부에서는 후보 사이즈별 계산값으로 쓸 수 있지만, 사용자 입력은 결정 뒤에 받는다.
