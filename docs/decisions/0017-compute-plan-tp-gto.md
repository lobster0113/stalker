# ADR 0017 (제안): TP-GTO 학습 연산 계획 — E3·E4(D3 첫 환경) 비용 재산정

> **학습 순서·비용 계획은 [ADR 0019](0019-training-plan-realistic-game.md)가 대체한다**(2026-10-30, #390). 소유자 결정으로 실전 사이즈·좌석별 스택·2–6인·토너먼트를 학습하고, 이 문서의 v1 메뉴·100BB 균등 스택 기준 체인은 멈춘다. §8 파드 실측은 ADR 0019의 입력으로 그대로 쓴다. 아래 §4 표는 `compute_plan.py` 출력과 묶여 있어 바꾸지 않는다.

- 상태: **제안 — 사용자 결정 대기**(NEEDS_HUMAN). 결정되면 "채택"으로 바꾸고 선택안을 적는다.
- 이슈: #314. 대체: ADR 0004(ADR 0008로 보류된 RL 기준 연산 계획).
- 계산: `stalker/tools/compute_plan.py`(`python -m stalker.tools.compute_plan`). 이 문서의 표 값은 그 출력이며, `tests/test_compute_plan.py`가 표와 출력이 같은지 확인한다.

## 1. 결론 (추천)
- **돈보다 직렬 체인의 벽시계 시간이 먼저 막힌다.** 6인 캐시·9인 SNG의 초보·중수 정책은 무료 `train.yml` 이어 달리기만으로 각각 하루 이내, 5–7일 안에 학습된다. 이 정도면 유료 연산은 필요 없다.
- 고수 정책은 시드 하나의 체인이 45일(6인), 67일(9인)이 걸린다(가정 포함). 전체 연산량 1.2만 시드·시간은 무료 러너 20개면 약 25일 분량이다. 그러니 부족한 것은 코어 수가 아니라 **한 체인을 여러 코어로 나누는 병렬 MCCFR**이다.
- RunPod에서 같은 일을 하면 약 $722(전 등급·두 환경)이 든다. 월 상한 $100으로는 한 달에 1,667 시드·시간밖에 못 산다. 무료 CI가 하루에 내는 480 시드·시간의 3.5일 치다. **상한 $100 유지, 지금은 CPU에 유료 연산을 쓰지 않는 것**을 추천한다. 병렬 MCCFR을 만들고, #264 실측이 나온 뒤 다시 산정한다.
- ADR 0004의 "표준" 승격(월 $700–930)은 지금 근거가 없다. GPU(신경망 가치 근사, E5) 단계에서 다시 판단한다.

## 4. 계산 (근거 → 계산식 → 결과)
계산식:
- 반복 = 키 × 58.3(만 단위 반올림)
- 체인 일수 = 반복 ÷ it/s ÷ 86,400
- 시드·시간 = 반복 ÷ it/s ÷ 3,600 × 4
- 조각 = ⌈반복 ÷ (it/s × 300분 × 60)⌉
- RunPod $ = 시드·시간 ÷ 속도 배수 ÷ 2 × $0.12

| 환경 | 등급 | 반복 | it/s | 조각 | 체인(일) | 시드·시간 | RunPod $(대기 #264) |
|---|---|---|---|---|---|---|---|
| 6인 캐시 100BB | 초보 | 100,000 | 6.83 | 1 | 0.2 | 16.3 | 0.98 |
| 6인 캐시 100BB | 중수 | 2,570,000 | 6.0 | 24 | 5.0 | 475.9 | 28.56 |
| 6인 캐시 100BB | 고수 | 17,490,000 | 4.5 | 216 | 45.0 | 4318.5 | 259.11 |
| 9인 SNG | 초보 | 100,000 | 4.55 | 2 | 0.3 | 24.4 | 1.46 |
| 9인 SNG | 중수 | 2,570,000 | 4.0 | 36 | 7.4 | 713.9 | 42.83 |
| 9인 SNG | 고수 | 17,490,000 | 3.0 | 324 | 67.5 | 6477.8 | 388.67 |
| **합계** | | | | | 최장 67.5 | **12026.8** | **721.61** |

- 무료 CI: 하루 최대 20 × 24 = 480 시드·시간이다. 체인을 완벽히 병렬로 나눌 수 있다면 합계는 약 25.1일 분량이다. 지금은 시드 하나가 직렬 체인이라 고수의 벽시계는 45–67.5일이다.
- RunPod: 월 $100이면 $100 ÷ $0.12 × 2 = 1,666.7 시드·시간이다. 전체의 14%이고, 무료 CI 3.5일 치다.

## 8. 실측 갱신 (2026-10-29, #333) — 위 §2–§6 표는 실측 전 계산이다
근거는 cloud.yml run 로그와 결과 아티팩트(결과 JSON)다. 비용은 run 로그의 `pod … completed: N min, $X` 줄이다. `ops:budget/ledger.jsonl`의 `end`는 중수 두 run이 실제 비용($1.53·$1.48)과 같고, 고수 run 40840669062는 #351 이전 워크플로라 마지막 원장 푸시가 충돌해 reaper가 예약액 $6.40으로 닫았다(실제 $3.92보다 크게, 보수적으로 남겨 둠). §4 표는 `compute_plan.py` 출력과 묶여 있으므로 그대로 두고, 가정을 실측으로 바꾼 재계산은 이 절의 수치를 입력으로 하는 후속 PR에서 한다.

| 항목 | 실측 | 출처 |
|---|---|---|
| 병렬 벤치(참고) | 32 vCPU에서 중수 705 it/s, 효율 0.52, 동기화 9%, $0.96/h | cloud run 40816203961 |
| 실제 학습 처리량(중수 6인) | 146.7 it/s(벤치의 약 1/5), 학습 90분에 8×10⁵회, $1.53 | cloud run 40851654734 |
| 실제 학습 처리량(중수 9인) | 118 it/s, 학습 90분에 6.4×10⁵회, $1.48 | cloud run 40851659171 |
| 실제 학습 처리량(고수 6인) | 151 it/s, 학습 240분에 2,176,000회, 키 195,084개(NUT_K=5), $3.92 | cloud run 40840669062 |
| 고수 품질(1회차) | LBR 현재 전략 0.466±0.189 / 평균 0.774 bb/hand, 필드 최악 0.0(모든 상대 ≥ 0) | 같은 run |
| 속도 배수 | vCPU 1개 ≈ CI 코어 1개, 파드 1개(32 vCPU) ≈ CI 4코어 잡의 약 8배 | 위 run들과 CI e3-tp-*-w4 비교 |

결과:
- §3의 코어당 고수 처리량 가정(4.5 it/s)은 실측(151 ÷ 32 ≈ 4.7 it/s/vCPU)과 거의 같다. 틀린 것은 "RunPod 속도 배수 1.0"과 "파드당 단일 코어 시드 체인 2개"다. 병렬 MCCFR(#318)로 체인 하나가 32코어를 쓰므로 **고수 벽시계가 45일에서 수일 단위로 줄어든다**.
- 고수 키는 NUT_K=5에서 2.18M회에 195k개로, §3 가정(300k)보다 작다. 키당 58회 가정을 쓰면 약 1.1×10⁷회다. 4시간 run당 2.18×10⁶회이므로 약 5회(회당 약 $4, 합계 약 $20)다. 반복이 늘면 키도 늘어 처리량과 필요 반복이 바뀔 수 있으니, 2회차 결과의 키 수·it/s로 다시 잰다. 이어 달리기(#354)로 체인을 잇는다.
- 월 상한 $100 안에서 고수 6인 체인과 중수·9인 체인을 함께 돌릴 수 있다. 상한 변경은 실제로 필요할 때 harness-change로 한다.
