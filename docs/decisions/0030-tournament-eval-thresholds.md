# ADR 0030: 토너먼트 평가 record-only → 판정 전환: 지표·임계값·min_seeds

- 상태: 제안 → 이 PR 머지로 채택 (Builder 추천안으로 진행, `harness/PROTOCOL.md` §9)
- 이슈: #958 (#385 기준 4 "LBR and field in CI"). 캐시 쪽 ADR 0025(AIVAT·LBR 임계값, min_seeds)에 대응한다. 관련: ADR 0026(보상 = ICM + 버블 보정 λ), ADR 0027 결정 4·F4, ADR 0028 결정 1.
- **이 PR에서 직접 돌린 수치는 없다.** 수치는 `ops:cloud/results/<run>.json`의 run id를 출처로 적었다. 출처가 없는 수치는 **가정**이라고 표시했다. 코드·심판은 바꾸지 않는다.

## 맥락
토너먼트 평가는 지금 전부 record-only다: #911 시뮬 상금·ICM·보정 에퀴티(`referee/e3/tournament_eval.py`), #917 `lbr_icm`(`--lbr-hands`), #902 `gate_t_pass_rate`(`referee/metrics.py`). F5·F6·F7 결과가 모였으니 무엇을 어떤 임계값·시드 수로 판정에 쓸지 정한다.

## 근거 (출처 있는 수치)
**1. 학습자 시뮬 상금 − ICM 에퀴티, 웜(B) − 콜드(A)** (`primary`, 단위 = 상금 풀 비율, 9칸 = 3 layout × 3 profile, 칸당 400게임, 9인 SNG 50/30/20, 4명 남음, 시드 10001). #937 쌍 1–3:

| run | mean | se | 95% CI | verdict |
|---|---|---|---|---|
| 43882446641 | +0.00128 | 0.00285 | [−0.00432, +0.00687] | A |
| 44000780867 | +0.00072 | 0.00282 | [−0.00480, +0.00625] | A |
| 44005595416 | −0.00189 | 0.00289 | [−0.00755, +0.00377] | A |

- 세 CI 모두 0을 포함한다. 여기서 "쌍"은 **학습 쌍**(A·B 체크포인트 한 벌)이다. 세 run의 평가 시드는 모두 10001로 같고 다른 것은 학습 쌍뿐이다. 학습 쌍 간 sd(3개 평균)는 약 0.0017로 쌍 안 se(≈0.0029)보다 작아, 학습 쌍 사이 추가 변동이 보이지 않는다(표본 3개라 대략치). **평가 시드 간 변동은 측정한 적 없다(가정).**
- 같은 쌍의 칸별 `diff_b_minus_a` se는 세 run 27칸에서 0.0059–0.0097(400게임 1칸; 예: 43882446641 = 0.0088, 0.0085, 0.0096, 0.0092, 0.0097, 0.0084, 0.0064, 0.0077, 0.0081). 9칸 평균 se는 0.0029다(≈ 0.0087/√9).

**2. 버블 ICM 보정 λ 선택** (run 43778587487, F7a, 정책 1개, 게임 1000, layout 3, 시드 10001): 후보 λ ∈ {0, 0.05, 0.1, 0.2, 0.35, 0.5}, 버블 칸 `bubble_mean_rel` 0.0225·0.0195·0.0178·0.0169·0.0184·0.0221, 유의 칸 수 2·2·3·3·3·6, 선택 λ = 0.0. 같은 run λ=0 칸의 상대 격차 `max_abs_diff_rel` 최댓값은 칸 8(skewed, layout 2) 0.0752(`max_abs_z` 16.92, significant=true), 다음이 칸 6(skewed, layout 0) 0.0577(z 13.46, significant=true)이다. 0.0151(z 3.03, 칸 4)은 유의하지 않은 칸 중 최댓값이다. skewed 칸 2개가 유의하게 크지만 이 ADR의 판정 지표(근거 1, 시뮬 상금 − ICM)와 δ는 `bubble_mean_rel`·λ 칸 격차를 쓰지 않으므로 결정에 영향이 없다(λ 선택은 ADR 0026 소관).
- 같은 시뮬 상금 − ICM 지표에서 콜드 정책 A·B의 버블 칸 대칭 검사 `bubble_mean_rel`은 0.0255–0.0335(위 3개 run `symmetric_summary`), 유의 칸 2–3/9.

**3. F5 run 43735226442** (`ops:cloud/results/43735226442.summary.json`, 4인 mid c1, 20000 iter): 이 요약에는 `lbr_icm`이 **없다**. 있는 것은 칩 LBR `lbr` 3.161bb(se 0.671, 600핸드), `lbr_average` 2.966bb, `lbr_offmenu` 3.125bb뿐이다(단위가 달라 토너먼트 판단에 못 쓴다 — `referee/GATES.md` §ICM 단위 LBR). → **`lbr_icm`의 임계값 근거 수치는 없다(가정도 만들지 않는다).**

## 선택지
- **(a) record-only 유지.** 지표가 잡음 범위(위 CI 3개가 0 포함)여서 지금 임계값을 정하면 잡음을 선에 새길 수 있다. 하지만 토너먼트 회귀를 CI가 못 잡는 상태가 계속되고 #385 기준 4가 닫히지 않는다.
- **(b) 시뮬 상금 − ICM 한 지표만 비열등 판정으로 전환.** 근거 수치가 있는 유일한 지표다. `lbr_icm`은 record-only로 둔다.
- **(c) (b) + `lbr_icm` + `bubble_mean_rel` 전부 판정.** `lbr_icm`은 근거 분포가 없고(근거 3), `bubble_mean_rel`은 λ 선택 지표로 설계돼 정책 간 비교 용도(근거 2)라 선을 정할 수 없다.

## 결정 (추천: b)
1. **판정 지표.** `learner sim prize − ICM equity` (상금 풀 비율, 9칸 평균). 후보 정책(B)이 기준 정책(A: 직전 채택 정책 또는 콜드)보다 나쁘지 않은지 **비열등** 검사로 본다: 판정 규칙은 결정 3(3쌍 평균 CI 하한 > −δ)이 정한다.
   `lbr_icm`·`bubble_mean_rel`·`gate_t_*`는 record-only 유지(아래 후속 3에서 재검토).
2. **임계값 δ와 도출.** δ = 0.0075 (상금 풀 비율). 도출: 쌍 se 최댓값 0.00289 × 2.6 ≈ 0.0075 (단측 99.5%에 가까운 선, 세 run 중 CI 하한이 가장 낮은 −0.00755와 같은 크기). 즉 지금 관측된 세 쌍은 모두 비열등으로 통과하되, 평균이 −0.0075 아래로 내려가는 회귀는 잡는다. 이 δ는 **관측 se에서의 도출이지 정책 강도 기준이 아니다**(0.0075 = 상금 풀의 0.75%, 900칩 풀에서 약 6.8칩). 가정: se는 칸 수 9·게임 400에서 같다고 본다.
3. **min_seeds / 평가 게임 수.** 평가 한 번 = 위 설정(9칸 × 400게임, 시드 10001 고정). 판정은 **독립 학습 쌍 3개**(쌍 = 학습 쌍 (i), 평가 시드는 10001 고정)의 평균으로 한다: 평균의 se ≈ 0.00289/√3 ≈ 0.0017(가정: 학습 쌍 간 독립). 한 쌍 `ci_low > −δ`가 아니라 3쌍 평균 CI 하한이 −δ 위면 pass. 근거 1에서 학습 쌍 간 변동이 쌍 안 se보다 작았으므로 3쌍이면 보수적이다. 평가 시드를 바꿀 때의 변동은 근거가 없어 가정이며, 되돌리는 조건에서 검사한다. 시드 1쌍은 `insufficient`(실패 아님).
4. **경로와 후속 이슈** (모두 `referee-change`, 이 ADR 채택 후 Planner가 만든다; 각 수용 기준 초안):
   - **후속 1 [referee] 판정 표 `referee/e3/tournament_thresholds_v1.json` + `judge`.** 기준: δ·`min_seeds`(3)·지표 키가 파일에 있다; 3쌍 입력에서 pass/fail/insufficient를 내는 단위 테스트; 이 ADR의 run 3개(학습 쌍 3개, 평가 시드 10001)를 고정 입력으로 쓴 테스트(전부 pass); `primary.mean = −0.0075` 합성 입력은 fail; `--thresholds` 없는 기존 출력은 바이트 동일.
   - **후속 2 [referee/ci] history 키.** 기준: `ops:metrics/history.jsonl`에 `tournament_primary_ci_low`·`tournament_verdict`를 남긴다(CI 전용); 값이 없으면 `None`+`error` 메모; 이전 행과 호환 테스트.
   - **후속 3 [referee] `lbr_icm` 분포 수집 후 임계값 ADR.** 기준: F5 후속 run에서 `--lbr-hands`를 켠 요약 `lbr_pool`을 시드 3개 이상 모아 ADR에 인용(현재 없음, 근거 3); 그때까지 record-only.
   - **후속 4 [ci] 되돌리는 조건 검사.** 기준: 쌍 간 sd와 쌍 안 se를 비교하는 스크립트(`ops:metrics/history.jsonl`의 `tournament_primary_*` 키 사용)가 새 3쌍 입력에서 sd > 2×se이면 `recheck` 출력; 합성 입력 단위 테스트 2개(경계 안/밖).

## 결과
- 이 PR은 문서만 바꾼다. 판정은 후속 1·2가 머지돼야 켜진다. 그 전까지 `gate_t_*`·`primary`는 record-only 그대로다.
- 판정이 켜져도 #385 기준 4의 "LBR" 부분은 후속 3 전까지 열려 있다.

## 되돌리는 조건
- 새 시드 3쌍의 평균 CI가 서로 겹치지 않거나, 쌍 간 sd가 쌍 안 se의 2배를 넘으면(잡음 모델이 틀림) δ와 min_seeds를 새 측정으로 다시 정한다.
- ADR 0026의 λ·보상 정의, 또는 `tournament_eval`의 지표 정의가 바뀌면 새 버전 파일로 판정한다.
