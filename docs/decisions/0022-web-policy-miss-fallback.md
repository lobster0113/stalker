# ADR 0022: 웹 정책 표 미적중 때 대체 행동 — 런타임 거친 키 백오프

- 상태: 제안 → 이 PR 머지로 채택 (Builder 추천안으로 진행, `harness/PROTOCOL.md` §9)
- 이슈: #618 (#611·#616 후속, 추적 #384). 이 PR은 측정 도구와 문서만 바꾼다. `web/app/tpgto.js`·export 형식은 후속 이슈에서.
- **수치는 모두 로컬 참고용**(`docs/research/2026-11-web-policy-backoff.md`, mid-2..5 각 1,000핸드, 시드 611). 채택 뒤 구현 이슈가 CI 수치로 다시 확인한다.

## 문제
페이지 AI 좌석은 실제 c1 키에 표 행이 없으면 균등 분포로 행동한다(`tpgto.js actionProbs`, 복기 화면은 "학습 표본이 없어 균등 분포"). #616은 이것이 결정의 97% 이상이라고 봤지만, 그 도구는 v1 메뉴·무작위 깊이로 핸드를 돌려 real 메뉴 표와 합법 메뉴 칸이 어긋났다. 페이지 규칙(파일의 메뉴, 100BB)으로 다시 재면:

| 인원 | 비-`call\|` 정밀 적중 | 플랍 정밀 | 플랍 미적중(L2 뒤에도) |
|---|---|---|---|
| 2 | 81.4% | 29.0% | 33.9% |
| 3 | 81.9% | 29.1% | 34.6% |
| 4 | 77.4% | 27.3% | 54.4% |
| 5 | 72.8% | 32.3% | 61.2% |

미적중은 이제 **포스트플랍에 몰려 있다**. 균등 행동은 큰 벳·올인을 아무 손으로나 고르므로 상대가 "학습된 AI"로 보이지 않고, 그 행동으로 갱신한 공개 레인지(`updateRanges`)도 이후 결정의 키를 흐린다.

## 선택지

수준 정의: L1 = b1 손 칸(outs·vuln·block) 제거 + 스택 칸 `s*`, L2 = L1 + 공개 사실(`u`·`h`·`g`)·SPR `*` (`stalker/tools/web_hit_rate.py` `coarse_key`). 같은 거친 키의 행 평균, 행 길이가 다르면 합치지 않음.

| | 비-`call\|` 행 있음 (2/3/4/5인) | 파일 크기 | 구현 비용 | TP 계약(`docs/TP.md`) |
|---|---|---|---|---|
| A. 균등 유지 | 81.4 / 81.9 / 77.4 / 72.8% | 0 | 0 | 행동이 어떤 TP 항목과도 무관 — 학습된 정책이 아니다 |
| **B. 런타임 거친 키 백오프** (정밀 → L1 → L2 → 균등) | 92.0 / 92.0 / 87.4 / 87.1% | 0 (페이지가 로드 때 한 번 평균, 키 ≤ 36,523개) | `tpgto.js` 함수 2개(`coarseKey`, 표 로드 때 거친 표) + Python 짝(`web_hit_rate.coarse_key`) 대조 테스트 | 거친 행도 공개 정보 + 에퀴티 단계만 읽으므로 조건 둔감(Gate S 의미)은 유지. 다만 L1/L2 행은 손 칸·스택·공개 사실에 **반응하지 않는** 근사이므로 정답(채점)으로 쓰면 안 된다 |
| C. 페르소나·휴리스틱 기준 행동 | 100% (정의상) | 0 | 큼: 메뉴 사이즈별 휴리스틱을 새로 만들고 인원·스트리트별로 맞춰야 함 | 학습 정책이 아닌 규칙 — "TP-GTO 상대"라는 약속과 다르고, 레인지 갱신이 정책 가정과 어긋남 |
| D. export 때 백오프 행을 미리 넣기 | B와 같음 | +L1 5,405 / 9,683 / 7,339 / 4,931키 × 약 64–70바이트 → mid-3 약 3.23MB로 3MB 예산(`export_web_policy.MAX_BYTES`) 초과, 맞추려면 `min_visits`를 올려 정밀 적중을 깎아야 함 | export·스키마 변경 + 페이지 키 탐색 변경 | B와 같음 |

## 결정
**B. 런타임 거친 키 백오프**, 마지막 단계는 균등 그대로.
- 근거: 파일 크기 0으로 비-`call|` 미적중의 절반 이상(비-`call|` 미적중 2–3인 18–19% → 8%, 4–5인 23–27% → 13%)을 덮는다. D는 같은 적중률에 크기 예산만 쓴다. C는 학습 정책이라는 서비스 약속과 맞지 않는다.
- 조건: 거친 행은 **AI 좌석 행동과 레인지 갱신에만** 쓴다. 복기·채점 화면은 `fromTable`을 수준(`"exact"|"L1"|"L2"|false`, #645 뒤 `"L3"` 추가)으로 받아, L1/L2(/L3)면 "비슷한 상황 평균(근사)"으로 표시하고 지금의 균등과 같이 점수에서 뺀다.
- 남는 미적중(4–5인 플랍 54–61%)은 백오프로 안 풀린다: 다인 포스트플랍 학습 커버리지 문제다. #617 CI의 `min_visits` 0 적중률(필터 전)로 커버리지와 필터를 가른 뒤 학습 쪽 이슈로 다룬다.

## 후속 구현 이슈 초안
**[service c1] 표 미적중 때 거친 키 백오프: AI 좌석 행동·레인지 갱신 (ADR 0022)** — `area:service` `kind:feature` `P2`
- 목표: 페이지 AI 좌석이 정밀 키 미적중 때 L1 → L2 → 균등 순으로 행을 찾는다.
- 수용 기준
  - [ ] `tpgto.js`에 `coarseKey(key, level)`·`coarseTables(policy)`(같은 거친 키 행 평균, 길이 다르면 따로)와 그것을 쓰는 `policyRow` 백오프. `actionProbs`·`seatProbs`(레인지 갱신)가 같은 백오프를 쓴다. `fromTable`은 `"exact"|"L1"|"L2"|false`.
  - [ ] Python 짝 대조: `stalker/tools/web_hit_rate.coarse_key`와 `tpgto.js coarseKey`가 키 표본(각 깊이·`call|` 포함)에서 같은 문자열을 낸다(기존 Python↔JS 대조 테스트 방식).
  - [ ] 복기 화면: L1/L2 행이면 "비슷한 상황 평균(근사)" 표시, 점수 제외(지금의 균등과 같음). Gate U 스크린샷 3종.
  - [ ] `web_hit_rate --backoff --play-backoff`(이름 자유): 백오프로 플레이한 궤적의 수준별 적중률을 CI export 요약에 기록, mid-2..5 비-`call|` 균등 비율이 A 대비 줄었음을 CI 수치로 보인다.
- 범위 밖: 재학습, export 형식, `min_visits` 변경, 초보·고수 표(c1 아님).

## 갱신 (#645): L3 = L2 + 자리 → 자리 묶음
- 근거: #638(PR #642) — L2 뒤에도 균등인 플랍 결정은 수백 개의 꼬리 L2 키(키당 2–7회)에 흩어져 학습·문턱으로는 잘 안 줄고, 자리 필드 하나만 풀면 6인 미적중의 최대 75%·3·4인 36–41%가 L2 행을 찾는다(상한, `docs/research/2026-11-c1-web-export.md` 「L2 미적중 원인 (#638)」).
- 정의: L3 = L2 키의 c1 자리 이름(`tp_key.C1_POSITIONS`, 필드 0; 고수 `p|` 키는 필드 1)을 그 인원(`n<players>`)에서의 `tp_key.position_group`(early / late = 블라인드 앞 두 자리 / blind)으로 바꾼 키. 인원 필드는 남으므로 인원이 다른 행은 섞이지 않는다. `call|` 키(자리 없음)와 초보 `b|` 키(이미 묶음)는 L2와 같다. 백오프 순서: 정밀 → L1 → L2 → **L3** → 균등. `fromTable`은 `"exact"|"L1"|"L2"|"L3"|false`. 구현: `stalker/tools/web_hit_rate.py` `coarse_key(key, 3)`·`LEVELS`, `web/app/tpgto.js` `coarseKey(k, 3)`·`BACKOFF_LEVELS`(대조 `tests/test_web_backoff.py`).
- 헤즈업은 두 자리 모두 blind 묶음이라 L3가 BTN·BB 행을 합친다. 2인은 L2 뒤 미적중에서 자리를 풀어 적중하는 비율이 9%로 가장 작아(#638 표) 영향이 작다.
- 조건 둔감 유지: 자리 묶음은 모든 좌석이 보는 공개 정보이고, 초보 키(`tp_key.public_key` basic, TP.md §4.1 초보 깊이)가 이미 쓰는 같은 정의다. L3 행도 L1/L2처럼 AI 좌석 행동·레인지 갱신에만 쓰고, 내 결정이 L3로 답해지면 복기는 "비슷한 상황 평균(근사)"으로 표시하고 점수에서 뺀다(`web/demo/index.html` `nearOf`, `games.js` `verdict`).
- 범위 밖: L3 뒤에도 남는 미적중의 에퀴티 이웃 단계 L4(별도 판단), 정책 파일 교체·재학습.
