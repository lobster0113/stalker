# ADR 0018 (제안): 정책 서빙 — 서버 추론으로 테이블을 내보내지 않는다

- 상태: **제안 — 사용자 결정 대기**(NEEDS_HUMAN). 결정되면 "채택"으로 바꾸고 고른 호스팅·출시 시점을 적는다.
- 이슈: #352. 관련: #335(PR #342, `web/app/tpgto.js`), #336(PR #340, 정책 내보내기), #337(PR #344, 서비스 화면 연결), #355(PR #357), #360(PR #363, 고수 정책 연결).
- 범위: 구조·API·보호·비용의 결정만. 서버 구현·배포·외부 공개는 하지 않는다(배포와 외부 공개는 에이전트 권한 밖).

## 1. 결론 (추천)
- **서버 추론**을 고른다. 정책 테이블은 서버 메모리에만 두고, 브라우저에는 지금 스팟의 답만 보낸다. 키 계산(`stalker/e3/tp_key.py`), 공개 레인지 추적, AI 좌석 행동, 채점도 서버가 한다.
- 서버는 **Python으로 `stalker/e3`를 그대로 쓴다.** 학습기와 같은 코드라 키가 어긋날 일이 없다. `web/app/tpgto.js`는 클라이언트에 남는다. 합법 액션·칩 계산을 즉시 보여주고, 서버 응답과 대조하는 테스트에 쓴다.
- 핸드 상태는 **서버가 보관**한다(서명된 상태 토큰이 아니다). 숨은 카드와 레인지를 클라이언트에 줄 수 없고, 토큰은 되감아 같은 스팟을 여러 번 물어보는 수집 경로가 된다(§5.3).
- 막을 대상은 **테이블 전체 수집**이다. 스팟별 답을 보여주는 것은 서비스의 목적이다. 인증, 계정·IP별 속도 제한, 대량 조회 탐지로 수집 비용을 사람의 플레이 속도보다 훨씬 비싸게 만든다(§6).
- 호스팅은 **2 vCPU · 4GB VM 한 대**로 출시한다. 측정한 결정당 계산은 ms 단위라(§3), 동시 사용자 수백 명까지는 메모리가 먼저 정한다. 월 €19.99(Hetzner CPX22)–$24(AWS Lightsail 4GB) 추정이다(§7). 어느 회사를 쓸지는 주 사용자 지역에 따라 사용자가 고른다.
- **공개 리포가 먼저 막힌다.** 리포가 public이라 `web/app/policy/*.json`, CI 아티팩트, 학습 코드를 누구나 받을 수 있다. 서버 추론만으로는 막을 수 없다. 출시용 테이블은 공개 리포 밖에 둬야 한다(§6.5, 사용자 결정 D4).

## 2. 문제
- 지금 서비스 화면(`web/demo/index.html` + `web/app/tpgto.js`)은 고른 등급의 정책 테이블 JSON 전체를 받아, 브라우저가 키를 계산하고 행을 찾는다. 테이블은 개발자 도구에서 그대로 복사된다.
- 사용자 지적(2026-10-29): 상용 GTO 서비스는 솔루션을 서버에 두고 현재 스팟의 답만 내려준다. 공개 출시 전에 이 구조가 필요하다.
- 비공개 확인용 Artifact(#337)는 지금 방식을 그대로 쓴다(이슈 범위 밖). 이 ADR은 공개 출시 경로만 정한다.

## 4. 대안 비교
| | A. 서버 추론(추천) | B. 클라이언트 테이블(현행) | C. 하이브리드 |
|---|---|---|---|
| 구성 | 서버: 테이블·키·레인지·AI·채점. 클라이언트: UI·입력 | 등급 테이블 전체를 내려받아 브라우저가 전부 계산 | 초보 테이블은 클라이언트, 중수·고수는 서버가 공개 노드 단위 조각(그 공개 키의 단계별 행 k ≤ 17개)을 내려준다 |
| 테이블 노출 | 결정당 내 핸드 행 1개(+ 상대 액션 표본). 수집하려면 수십만 회 이상 결정이 필요(§6.2) | **전체**(첫 로드에 통째로) | 초보 전체 + 방문한 공개 노드의 모든 단계 행. 같은 결정 수로 A보다 최대 17배 빨리 모인다 |
| 지연 | 네트워크 RTT + 서버 계산(측정 P95 ≤ 6ms/결정, 한 번의 요청에 AI 최대 5결정 + 내 결정 ≈ 36ms 이하) | 첫 로드 gzip 0.3MB(중수)–1.4MB(고수), 이후 0 | 조각 요청마다 RTT. 레인지 갱신은 클라이언트라 조각을 자주 요청 |
| 서버 비용 | VM 1대 월 약 €20–$24부터(§7) | 정적 호스팅(0에 가깝다) | A와 비슷(서버 필요) |
| 구현량 | 새 서버 패키지 + API + 인증·제한 + 화면 전환. 이슈 5–6개(§9) | 0(이미 있음) | A의 서버 + 클라이언트 조각 캐시 + 두 경로 유지. A보다 많다 |
| 키 일치 | 학습기와 같은 Python 코드. 어긋날 수 없다 | JS 이식, 벡터 테스트로 강제(#335) | 둘 다 |
| 오프라인·비공개 확인 | 불가(서버 필요) | 가능 | 초보만 가능 |

- B는 출시용으로 쓸 수 없다. 테이블이 곧 제품이다.
- C는 서버를 두면서도 노출을 A보다 크게 늘린다. 클라이언트가 레인지를 추적하려면 상대 좌석의 모든 콤보 행이 필요하고, 그것이 곧 공개 노드의 행 전부이기 때문이다. 얻는 것은 RTT 일부뿐이다.
- 그래서 A를 고른다. 레인지 추적을 서버로 옮기는 것이 노출을 결정당 1행으로 줄이는 핵심이다.

## 5. 구조
### 5.1 담당
| 서버(Python, `stalker/e3` 재사용) | 클라이언트(브라우저) |
|---|---|
| 정책 테이블 적재·보관(파일은 서버 디스크에만) | 화면·입력(테이블, TP 패널, 학습 섹션, 복기) |
| 딜(시드 `numpy.random.Generator`, 서버 비밀 시드), 숨은 카드 | 내 홀카드·공개 보드 표시 |
| 키 계산 `stalker/e3/tp_key.py`, 실제 금액 → 메뉴 번역 | `tpgto.js`로 합법 액션·`betRange`·칩 이동을 즉시 계산해 입력을 미리 거른다 |
| 공개 레인지 추적(모든 좌석, 액션마다 베이즈 갱신) | 서버가 보낸 이벤트를 `tpgto.js` 거울 상태에 적용하고, 서버의 `legal`·`pot`·`stacks`와 대조한다. 어긋나면 서버 값을 따르고 오류를 기록한다 |
| AI 좌석 행동(정책 표본) | 연출(1.5초 진행, 애니메이션) |
| 채점(`hand.equity` 등 모델 정답, TP §5 규칙), 내 스팟 혼합 전략 | 결과 표시, 신뢰도 라벨, 로컬 기록(`stalker.weak` 등) |
| 인증·속도 제한·조회 기록(§6) | 로그인 토큰 보관 |

- `tpgto.js`는 정책 없이도 합법 액션과 칩을 계산한다. 그래서 공개 출시 화면에서도 쓰고, 정책 파일만 빠진다. `web/app/test/tpgto.test.mjs`의 Python 벡터 대조는 그대로 두고, 서버 응답과 `tpgto.js` 거울의 대조 테스트를 서버 구현 이슈에 추가한다.
- 키 문자열·콤보별 단계 배열·상대 좌석 행은 응답에 넣지 않는다(§6.3).

### 5.2 핸드 상태: 서버 보관 (서명된 상태 토큰 대신)
| | 서버 보관(선택) | 서명된 상태 토큰 |
|---|---|---|
| 숨은 정보 | 상대 홀카드·덱·AI 난수가 서버에만 있다 | 서명은 위조만 막는다. 숨은 카드를 넣으려면 암호화(JWE)까지 필요하다 |
| 크기 | 요청에 `hand_id`·`seq`만 | 레인지 6 × 1326 float = 64KB(압축해도 수십 KB)를 매 요청 왕복 |
| 수집 저항 | `seq`가 하나씩만 전진한다. 같은 스팟에서 다른 액션·다른 답을 물을 수 없다 | 예전 토큰을 다시 보내 같은 스팟을 갈래로 반복 질의할 수 있다(되감기). 막으려면 결국 서버에 사용 기록이 필요하다 |
| 운영 | 프로세스 메모리 dict(핸드당 약 70KB, 동시 1,000핸드 ≈ 70MB). TTL 30분. 재시작하면 진행 중 핸드는 새로 시작 | 서버 무상태라 수평 확장이 쉽다 |
| 확장 | 1대에서는 문제없다. 여러 대면 세션 고정 라우팅 또는 공유 저장소(후속) | 쉽다 |

- 이유: 숨은 카드를 서버 밖에 둘 수 없고, 되감기 질의가 바로 테이블 수집 경로다. 무상태의 장점(수평 확장)은 VM 1대 규모에서는 필요 없다.

### 5.3 학습 섹션·복기
- 복기는 사용자가 홀카드와 액션을 직접 입력한다. 즉 **스팟을 골라서 물을 수 있는 유일한 경로**다. 하루 할당량을 따로 작게 둔다(§6.1).
- 학습 섹션의 정책 기반 문제는 서버가 스팟을 골라 낸다(사용자가 고르지 않는다).

## 6. 테이블 보호
### 6.1 인증과 속도 제한
- 모든 정책 응답은 로그인 계정에만 준다. 방식(이메일 링크·OAuth)은 구현 이슈에서 정한다. 비로그인 체험은 초보 등급만, 같은 IP의 하루 결정 수를 작게 둔다.
- 제한(초기값, 운영하며 조정):

| 대상 | 계정당 | IP당 |
|---|---|---|
| 훈련 게임 결정(내 결정 기준) | 분당 30, 하루 2,000 | 분당 60, 하루 5,000 |
| 복기 질의(스팟 지정) | 하루 50 | 하루 100 |
| 세션 생성 | 시간당 30 | 시간당 60 |

- 근거: 사람은 결정 하나에 수 초가 걸리고, AI 좌석 연출만 좌석당 1.5초다. 하루 2,000결정이면 몇 시간 연속 플레이다. 초과하면 HTTP 429와 다시 열리는 시각을 준다.

### 6.2 수집 비용
- 결정 하나가 드러내는 것은 내 실제 핸드의 행 1개다. 키는 서버가 딜한 카드와 공개 레인지로 정해지므로 사용자가 고를 수 없다(복기 제외).
- 고수 195k 키를 모두 보려면 최소 195k결정이고, 방문 분포가 치우쳐 있어(중수 10⁵회 학습에서도 키 42%가 방문 10회 미만, ADR 0017 §2) 실제로는 그 몇 배다. 하루 2,000결정 한도면 계정 하나로 최소 약 98일이다. 수집자는 계정을 여러 개 만들어야 하고, 그 패턴이 §6.3의 탐지 대상이다.

### 6.3 응답 최소화
- 응답에는 해당 스팟의 정보만: 상대 액션(확률이 아닌 실제로 고른 액션), 내 실제 핸드의 메뉴 액션별 확률(1% 단위로 반올림), 채점 결과, 모델 메타(반복·LBR·run).
- 넣지 않는 것: 키 문자열, 콤보별 단계 배열, 다른 콤보·다른 좌석의 행, 테이블 파일 경로.
- 상대 공개 레인지를 보여주는 TP 정답(`opp.range`)은 스팟별 답이라 목적에 포함된다. 169칸 요약으로만 보내고 결정 할당량에 함께 센다.

### 6.4 대량 조회 탐지
- 계정별 일 지표를 남긴다: 결정 수, 새로 본 키 수와 비율, 결정 시간 분포, 복기 질의 수.
- 의심 신호: 결정 시간 P50 < 1초가 오래 지속, 새 키 비율이 같은 등급 사용자 분포의 상위 1% 밖, 한 IP·기기에서 여러 계정, 복기 할당량을 매일 소진.
- 신호가 나오면 그 계정의 한도를 낮추고 운영 기록에 남긴다. 자동 차단은 오탐 위험이 있어 하지 않는다(사람 확인 대상으로 올린다).

### 6.5 공개 리포 (출시 전 선행 조건)
- 리포가 public이다(`docs/HARNESS_DESIGN.md`, 사용자 결정 2026-10-24). 지금 `web/app/policy/*.json`이 커밋되어 있고, 학습 CI 아티팩트와 `ops:cloud/results/`도 공개 리포에 있다. 공개 리포의 Actions 아티팩트는 GitHub 계정만 있으면 받을 수 있다.
- 그래서 서버 추론을 해도 **출시용 테이블이 공개 리포에 있으면 보호가 없다.** 출시용 테이블의 저장 위치(비공개 리포·비공개 저장소 등)를 사용자가 정해야 한다(D4). 학습 코드가 공개라 재학습은 누구나 할 수 있지만, 고수 정책은 ADR 0017 기준 연산 수천 시드·시간이 든다. 이것은 막을 대상이 아니다.
- 공개 출시 자체가 `docs/HARNESS_DESIGN.md`의 "개인 전용: 외부 배포·상업화 없음" 전제를 바꾼다. 출시 결정이 나면 같은 PR에서 그 문서를 고친다.

## 9. 후속 작업 (이 ADR 채택 뒤 이슈로)
1. `stalker/serve/` 핵심: 세션·핸드 상태(TTL), AI 좌석, 채점, 응답 스키마 `stalker.api` `schema_version` 1. `tpgto.js` 거울과 같은 legal·pot·stacks를 내는지 대조 테스트.
2. HTTP API(§10) + 인증 + 속도 제한 + 조회 지표. 새 의존성은 그 이슈에서 이유와 함께 정한다(표준 라이브러리 우선).
3. 화면 전환: `window.STALKER_API_BASE`가 있으면 서버 모드, 없으면 현행 정적 모드(비공개 Artifact용). 서버 모드에서는 정책 파일을 받지 않는다. Gate U에 서버 모드 경로를 추가.
4. 출시용 테이블 저장소(D4 결정 뒤).
5. 배포 절차 문서와 부하 측정(CI 또는 일회 잡에서 P95 확인, D2 결정 뒤).

## 10. API (v1 초안)
모든 요청·응답은 JSON, `Authorization: Bearer <token>`. 칩은 정수(BB = 100). 응답에는 `schema: "stalker.api"`, `schema_version: 1`.

`POST /v1/sessions` — 세션 생성
```json
{"tier": "mid", "players": 6, "format": "cash100", "mode": "quick"}
```
→ `{"session_id": "s_…", "model": {"tier": "mid", "iterations": 100000, "lbr_bb": 0.721, "lbr_stderr_bb": 0.224, "run_id": "40780486937", "label": "TP-GTO · 학습 중간본"}}`

`POST /v1/sessions/{session_id}/hands` — 새 핸드. 내 차례까지 AI가 둔다.
→ 핸드 응답(아래)

`POST /v1/hands/{hand_id}/actions` — 내 액션 제출
```json
{"seq": 3, "action": "r", "to": 1250, "tp_answers": {"hand.equity": 60}}
```
- `action`은 `f`·`c`·`r`·`a` 중 하나, 벳·레이즈면 `to`(이번 스트리트 총액)를 함께 보낸다. `seq`는 서버가 마지막에 준 값이어야 한다(다르면 409와 현재 `seq`).

핸드 응답(새 핸드와 액션 제출 공통):
```json
{
  "hand_id": "h_…", "seq": 4,
  "hero": {"seat": 3, "position": "BTN", "hole": ["As", "Kd"]},
  "board": ["Qh", "7c", "2s"],
  "events": [
    {"seat": 3, "action": "r", "to": 1250, "translated": {"action": "r", "prob": 0.71}},
    {"seat": 4, "action": "f"},
    {"seat": 5, "action": "c", "to": 1250},
    {"street": 1, "board": ["Qh", "7c", "2s"]}
  ],
  "decision": {
    "acts": ["f", "c", "r", "a"],
    "probs": [0.00, 0.62, 0.35, 0.03],
    "chosen": "r"
  },
  "grading": {
    "items": {"hand.equity": {"answer": 60, "truth": 54, "score": 88}},
    "label": "TP-GTO · 학습 중간본"
  },
  "next": {"to_act": 3, "legal": ["c", "r", "a"], "bet_range": {"min": 900, "max": 10000},
           "pot": 2950, "stacks": [10000, 9850, 9000, 8750, 10000, 8750]},
  "done": false,
  "result": null
}
```
- `decision`은 방금 제출한 내 결정의 혼합 전략이다(내 실제 핸드 행만, 1% 반올림). 액션은 Q값이 없으므로 참고로만 보여주고 점수에 넣지 않는다(TP §5).
- `events`의 AI 액션은 고른 액션만 있다(확률 없음). `translated`는 내 메뉴 밖 금액의 해석이다(`tpgto.js` `translateBet`과 같은 값).
- `done`이면 `result`에 좌석별 손익과 쇼다운 카드가 들어간다.
- 오류: 400(규칙 위반, 고치는 법 포함), 401(로그인 필요), 404(핸드 만료, 새 핸드 시작), 409(`seq` 불일치), 429(한도 초과, 다시 열리는 시각).

`POST /v1/review` — 복기 질의(할당량 별도)
```json
{"tier": "mid", "players": 6, "hero_seat": 3, "hole": ["As", "Kd"], "history": ["0:f", "1:f", "2:r", "3:c"], "board": []}
```
→ `{"decision": {"acts": [...], "probs": [...]}, "grading": {...}, "quota": {"left": 49}}`

`GET /v1/models` — 등급별 메타(`web/app/policy/index.json`의 메타 부분). 테이블은 없다.
