# ADR 0012: E2 학습 환경 — 헤즈업 25BB 노리밋 홀덤(칩 EV, 고정 베팅 추상화)

- 상태: **채택(위임)** 2026-10-27, 대화 세션. 사용자가 "결정사항은 너가 결정해서 진행"하라고 위임했다. 계획서 v1.1 §3.4는 E2를 "헤즈업 캐시 100BB 또는 명시적 토너먼트 숏스택 스팟 중 하나(D2 ADR)"로 남겨 두었다.
- 근거: E1 결과(#114·#169·#174), ADR 0009·0010·0011, 계획서 §3.3–3.4·§6.
- 영향: 다음 이슈들(아래 "작업"), 유료 연산 사용 시작(사용자 결정: 학습 준비가 끝나면 사용).

## 결정
**E2 = 헤즈업 노리밋 홀덤, 유효 스택 25BB, 한 핸드, 칩 EV, 고정 베팅 추상화.**
- 프리플랍 액션: 폴드 / 콜(체크) / 레이즈(오픈 2.5BB, 3벳 3배, 4벳 2.2배) / 올인.
- 포스트플랍 액션: 체크 / 벳 33%·75% / 올인. 벳을 받으면 폴드 / 콜 / 레이즈(3배) / 올인.
- 레이즈 횟수 상한: 스트리트당 3회(초과 시 올인만).
- 카드는 추상화하지 않는다. 정책의 상태 축약은 **TP 병목 자체**가 한다(TP 벡터 + DecisionContext).

## 이유
1. **E1과 이어진다**: 25BB는 E1(1–15BB, 25BB까지 앵커 격자)의 바로 위다. 푸시/폴드 영역을 벗어나 포스트플랍이 처음 생기는 가장 작은 실전 환경이다. 같은 판정 체계(정확 BR → 근사 BR)를 단계적으로 넓힐 수 있다.
2. **트리가 작다**: 스택이 얕아 SPR이 작아서, 추상화한 게임 트리가 100BB보다 몇 자릿수 작다. 그래서 CPU MCCFR로 시작해 처리량을 재고 유료 연산 규모를 정할 수 있다.
3. **서비스와 맞닿는다**: 토너먼트 중후반 숏·미들 스택(15–30BB) 상황이 초중급 학습자에게 가장 흔하고, 오류 비용도 크다. 캐시 100BB 헤즈업은 그 다음(E3 후보)으로 둔다.
4. **강도 판정 경로가 있다**: 리버·턴 서브게임은 TexasSolver로 풀 수 있다(Q2 앵커, `stalker/oracle/texassolver.py`). 추상화 게임 안의 착취 가능성은 근사 최선 응답(LBR)으로 하한을 잰다(Q3, "발견된 착취 이득"으로만 보고).

## 학습 방식 (사용자 요구: 정책끼리 경쟁하며 발전)
- **기준(무제약)**: 추상화 게임에서 외부 표본 MCCFR(자기 대전). 카드 정보는 그대로다.
- **TP 병목 정책**: 같은 MCCFR을 TP 요약 상태 위에서 돌린다(E0·E1과 같은 방식). TP 값은 각 시점 상대 정책의 평균 전략으로 계산한 레인지 기준이다. 이후 신경망 TP 헤드 + 자기 대전(ADR 0009 안 C)으로 넓힌다.
- **평가**: LBR(근사 최선 응답) 착취 하한, 기준 정책 대비 직접 대결(duplicate), TexasSolver 리버 스팟 대조.

## 단계와 Go/No-Go
| 단계 | 내용 | 통과 조건 |
|---|---|---|
| E2-0 | 추상화 게임 엔진 + 규칙 검사(Gate R 항목) + 결정 수 세기 | 엔진 3자 일치(기존 Gate R 방식), 트리 크기 보고 |
| E2-1 | 무제약 MCCFR(CPU) + LBR 평가기 | LBR 착취 하한이 반복에 따라 줄어듦, 재현(같은 시드 = 같은 결과) |
| E2-2 | **처리량 측정**(로컬 CPU → RunPod CPU 소형) | 반복/초, 결정/초, 비용 표 → 학습 규모 결정 |
| E2-3 | TP 병목 MCCFR, 복잡성 비용(무제약 대비 LBR·직접 대결 차이) | 등급별 표, E1과 같은 경향인지 |
| E2-4 | 유료 연산 본 학습(월 $100 상한) | 수렴 곡선, Gate T·S 판정 |

## 작업 (이슈)
E2-0 엔진, E2-1 MCCFR + LBR, E2-2 처리량 측정과 RunPod 잡 명세, E2-3 TP 병목 MCCFR.

## 대안
- **헤즈업 캐시 100BB**: 트리가 너무 커서, 처리량을 재기 전에는 유료 연산 규모를 정할 수 없다. E3 후보.
- **명시적 토너먼트 스팟 묶음**(특정 보드·스택만): 학습 서비스의 "실전 게임" 흐름과 연결이 약하다. 학습 섹션 문제 은행용으로는 계속 쓴다.
