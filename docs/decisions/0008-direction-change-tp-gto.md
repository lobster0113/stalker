# ADR 0008: 방향 전환 — "ICMizer를 넘는 토너먼트 AI"에서 "따라 할 수 있는 GTO(TP-GTO)와 학습 서비스"로

- 상태: 채택 (2026-10-27, 사용자 지시 — `docs/ORIGIN.md` 개정, 대화 세션)
- 대체: ADR 0003(핵심 AI = RL 정책, ICMizer 상회가 최소 성공 기준)을 대체한다. ADR 0002·0004·0006·0007은 아래 표대로 처리한다.

## 맥락
사용자가 원문 요구사항을 다시 썼다. 새 원문의 핵심:
1. 기존 GTO는 조건에 민감하고 과정을 보여주지 않아 사람이 따라 할 수 없다. 따라 할 수 없는 답은 무용하다.
2. GTO의 학습 방식은 계승하되, 사람이 이해할 수 있는 **Thinking Process(TP)** 를 거쳐서만 행동하고 **조건에 둔감한**(복잡성 제약) 최적 전략을 만든다.
3. 제품은 Training Game(실전형 + TP 입력 + 즉시 채점), 학습 섹션(TP 항목별·난이도별), 복기용 Training Game이다. 캐시게임과 토너먼트 모두 다룬다(환경 분리).
4. 개발 순서: ① AI 없는 데모 사이트(UI·UX 매우 중요) ② GTO 설계·학습 준비·예상 비용·정확한 시뮬레이터 ③ 학습.

## 결정
1. 헌장(`docs/CHARTER.md`)과 성공 게이트(`referee/GATES.md`)를 새 원문 기준으로 다시 쓴다. 성공 정의는 Gate R·L(기반) → T·S·Q·F(따라 할 수 있는 GTO) → E(학습 효과).
2. TP 명세를 단일 계약으로 둔다(`docs/TP.md`, 보호 경로). AI·채점·UI·학습 섹션이 모두 이 명세를 따른다.
3. 로드맵을 D0~D4로 바꾼다(`docs/HARNESS_DESIGN.md` §8). D1 데모 사이트가 다음 초점이다.
4. 하네스(L1/L2) 구조와 프로토콜은 유지한다. 역할 지침의 초점·리뷰 항목·라벨만 바꾼다.
5. 기존 코드는 지우지 않는다. 재사용할 것과 은퇴할 것을 나누고(아래), 은퇴는 Planner가 이슈로 처리한다.

## 결과
- ops의 진행 중 이슈 중 은퇴 대상(유형화 충분성, RL 붕괴 탈출, ICMizer 클라이언트)은 닫는다. NH-2(ICMizer 구독)는 무효, NH-1(연산 자원)은 D2 비용 산정 후 다시 묻는다.
- 위험: TP 명세 v0의 항목 정의가 학습 가능한지 아직 모른다 → D2의 첫 연구 과제(ADR 0009).
