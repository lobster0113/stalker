## 2. 검토 의견 (반영하며 보완한 점)

### 2.1 ICMizer 접근성 — Gate A의 실행 가능성
ICMizer는 공개 API가 없고, 이용약관(2024-03-08)은 자동 데이터 조회·봇·서버 요청 증가를 금지하며 위반 시 계정 차단을 명시한다(https://www.icmizer.com/terms-of-service/).
**사용자 결정(2026-10-24): ICMizer를 결제하고, 약관 위험(계정 차단)을 감수하고 요청을 자동 전송해 결과를 받아온다.**
- Gate A 기준선 = **실물 ICMizer 출력**(자동 클라이언트). 자격증명은 GitHub Secret에만 두고 클라이언트는 CI(Actions)에서만 실행 → 에이전트는 자격증명을 보지 않고, 수치는 CI가 산출(심판 원칙 유지).
- 계정 보호: 요청 속도 제한·영구 캐시(같은 스팟 재요청 금지)·배치 크기 상한·실패 시 지수 백오프. 차단 징후(401/403/캡차) 감지 시 즉시 중단하고 `ops:NEEDS_HUMAN.md`에 기록.
- ICMizer-등가 참조기(자체 구현)는 ① 실물과의 교차검증 ② 계정 차단 시 대체 ③ 대량 스팟(레이트 리밋 초과분) 용도로 유지.
- 요청 형식은 공개 문서가 없으므로, 사용자 구독 후 1회 트래픽 캡처로 파악한다(사용자 PC의 ICMizer 앱 또는 웹 세션).

### 2.2 Gate A의 상대 가정이 결과를 결정한다
푸시/폴드 내시 균형은 상대도 내시로 둘 때 이탈 이득이 없다(헤즈업 제로섬에서는 정확히, 다인 ICM에서는 근사적으로). 즉 **상대가 내시를 두는 평가에서는 AI가 ICMizer를 "상회"하기가 원리적으로 거의 불가능**하다. AI가 ICMizer를 이기는 원천은 (a) 현실적 비내시 상대에 대한 착취(게임 내 기억 = Gate C의 가치), (b) ICMizer 모델의 단순화(포스트플랍 무시, FGS 깊이 한계, 단일 콜러 가정)다.
**결정:** Gate A 평가 상대군을 사전 고정하고 버전 관리한다: ① 내시 상대(동등 이상이면 통과 = 비열등성 검정), ② 현실적 상대 풀(nit/TAG/LAG/콜링스테이션/과잉 셔버 등 비내시 프로파일) 대상 우위(우월성 검정). 두 결과를 함께 보고한다.

### 2.3 Gate B 참조 봇의 비-ICMizer 구간
"그 외 포스트플랍·깊은 스택 상황에는 사전에 고정한 별도 전략"이 미정이다. 이 선택이 Gate B 결과를 좌우하므로 심판 자산으로 고정한다: 참조 봇 v1 = ICMizer-등가 참조기(푸시/폴드 구간) + 표준 오픈/3벳 차트 + 포스트플랍 에퀴티 기반 규칙 정책(이후 솔버 라이브러리로 업그레이드 시 v2로 버전업, 이전 버전 결과 보존).

### 2.4 "요약만" 입력과 ICM
ICM은 전체 스택 분포가 필요할 때가 많다. 실제 MTT에서 로비의 칩 카운트는 공개 정보인 경우가 많으므로, **개인 행동 로그가 아닌 "스택 분포의 고정 길이 요약"(분위수·히스토그램)** 은 U2 위반이 아니다. 관측 계약에 `stack_distribution_summary`를 포함하고, 요약 해상도별 성능 차이를 실험으로 측정한다(보고서 3.1의 "근사 한계 평가" 요구 이행).

### 2.5 통계 검정력 — 필요한 토너먼트 수
9인 SNG 순ROI의 토너먼트당 표준편차는 대략 1.3~1.6 바이인이다(지급 구조에 따라 다름, 추정). 비짝지은 비교에서 ROI 3%p 차이를 검정력 0.8, α=0.05로 검출하려면 군당 약 7.84·σ²/δ² ≈ **1.5만~2.2만 토너먼트**가 필요하다. 좌석·난수 교환(duplicate) 평가로 분산을 줄여도 수천 단위다. → 시뮬레이터 처리량이 성공 판정의 병목이다.
**사용자 결정(2026-10-24): "표본이 충분한 게 낫다. AI 성능이 가장 중요하다(비용 제약 내 최적화는 필요)."** → 표본 수는 검정력 0.9로 사전 등록하고 채우기 전에는 성공 선언 금지. duplicate 평가는 표본 절감이 아니라 정확도 향상 수단, 조기 중단은 가망 없는 후보를 버릴 때만(`referee/GATES.md` 표본 정책). 처리량 최적화는 표본을 줄이는 대신 시뮬레이터·추론 속도를 높이는 방향으로 한다.

### 2.6 강화학습의 연산 자원 — 사람의 결정이 필요한 유일한 영역
보고서의 초기 RL 단계(32~64코어, GPU 1~4장)는 Claude 루틴 VM이나 GitHub Actions 무료 러너로 감당할 수 없다. 프로토타입·환경·심판(P0~P2)은 현 인프라로 가능하지만, **P3(신경망 Self-play) 착수 전에 학습용 연산 자원이 필요**하고 이는 비용·하드웨어 결정이므로 사용자 결정 사항이다. → 하네스는 `ops:NEEDS_HUMAN.md`에 근거(처리량 실측, 비용 추정)를 갖춘 요청을 기록하고, 그동안 다른 작업을 계속한다. 이것이 사람에게 돌아가는 유일한 종류의 결정(돈·하드웨어·라이선스)이다.

### 2.7 ADR 0002(솔버 조합)와의 관계
보고서는 "강화학습 에이전트"를 핵심으로 한다. ADR 0002의 솔버 조합은 폐기가 아니라 역할이 바뀐다:
- **핵심 정책** = 게임-경계 인식 재귀 정책(RL, 보고서 6장).
- **솔버/내시 계산기** = ① Gate A의 ICMizer-등가 참조기, ② Gate B 참조 봇, ③ RL 부트스트랩 교사(보고서 6.3 Bootstrap: "사용권 확보된 전문가 데이터" — 우리 솔버 출력은 사용권 문제가 없다), ④ 이론 앵커.
- RL 이전 단계에서도 학습용 기록(2·3 과정)의 파이프라인은 참조 정책으로 미리 구축·검증해 둔다.

### 2.8 학습 목적(유형화)과의 정합
사용자가 공부할 대상은 결국 이 AI의 수다. 그래서 기록에는 **같은 결정 시점의 AI-0(기억 끔)과 AI-1/2(기억 켬) 정책 확률을 함께** 남긴다. 둘의 차이가 "이 상대에게는 이렇게 바꾼다"는 학습 내용이고, 이는 데이터 충분성 기준 S3과 직접 연결된다.
