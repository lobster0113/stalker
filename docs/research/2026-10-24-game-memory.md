# 게임 내 누적 기억(AI-1/AI-2) 설계 연구 — 2026-10-24

이슈 #9. 범위: 설계와 실험 계획. 구현 없음. 근거 문서: 헌장 3, `docs/OBSERVATION.md`, ADR 0003, `referee/GATES.md`(Gate C·L).

> **출처 표기 주의.** 이 실행은 외부 웹을 열람하지 않았다. 아래 문헌은 알려진 서지를 기억에 의존해 적었고, 세부 주장에 설계가 기대는 곳에는 "확인 필요"를 붙였다. 구현 전에 후속 이슈 F1에서 원문을 확인한다. 수치는 §7.2의 **로컬 계산(참고용)** 이다.

## 1. 문제 정의
한 게임(game_id) 안에서 상대의 공개 행동만으로 정책을 바꾸고, 게임이 끝나면 전부 버린다. 제약:
- **표본이 적다.** 한 판에서 특정 상대의 컨텍스트별 "기회"는 몇 번~수십 번이다.
- **관측은 공개 정보뿐.** 폴드한 핸드의 카드는 모른다. 쇼다운은 드물고 레인지 상단으로 편향된다.
- **착취는 위험하다.** 적은 표본에 과반응하면 균형 정책보다 손해다.

## 2. 상대 통계의 베이지안 수축 (AI-1의 핵심)
### 2.1 모델
상대 `p`의 컨텍스트 `c`(관측 계약의 `pre_open / pre_facing / post_open / post_facing`)에서 액션 `a ∈ {fold, call, raise}` 빈도를 Dirichlet-다항(이진이면 Beta-이항)으로 둔다.
- 사후 평균 `θ̂_a = (α0·π_a + n_a) / (α0 + N)`. `N`=기회 수, `n_a`=액션 횟수, `π`=사전 빈도, `α0`=사전 강도(유사 표본 수).
- "2번 3벳 당하고 과반응" 방지: 사전 3벳 빈도 0.07, `α0=40`이면 기회 2에서 2회를 봐도 사후 평균은 0.114(기회 10에서 2회: 0.096, 50에서 5회: 0.087, 200에서 15회: 0.074. 로컬 계산).
- **불확실성도 입력한다.** 평균만 주면 "N=2의 0.114"와 "N=200의 0.114"를 구별할 수 없다. 특징은 `(θ̂, log(1+N), 사후 분산)`. `GameMemoryStore`가 컨텍스트별 기회 수·액션 횟수를 이미 보관하므로 원료는 있다.

### 2.2 사전의 출처 — 가장 중요한 설계 선택
- **P-flat**: 균등 사전. 단순하나 초기 과반응.
- **P-pop**: 모집단 평균(포지션·스택·버블별). 일반 지식이 가중치 안에 있는 것이므로 게임 간 리셋 규칙과 충돌하지 않는다.
- **P-hier**: P-pop 위에 "이 테이블 전체의 성향"을 계층 사전으로 둔다. 같은 game_id 안의 정보라 Gate L 경계 안이다. 상대 풀이 이질적이면 오히려 편향이므로 제거 실험 대상.
- 추천: P-pop으로 시작, P-hier는 변형으로 Gate C에서 비교. `α0`는 손으로 정하지 않고 시뮬레이션 상대 풀에서 경험적 베이즈(Efron–Morris식 수축)로 컨텍스트별 추정.

### 2.3 관측 편향
- 기회 수 분모는 "그 결정을 할 수 있었던 횟수"여야 한다(오픈 기회 = 앞사람 전원 폴드). 현재 `pre_open/pre_facing` 구분이 근사한다.
- 쇼다운 정보는 해당 액션 레인지의 일부만 보여준다. 액션 빈도와 쇼다운 레인지를 별도 특징으로 두고 쇼다운 수를 함께 넣는다.

## 3. 컨텍스트별 통계 (포지션·스택·버블)
세분화는 정보를 늘리지만 표본을 쪼갠다 → **계층 수축**.
- 레벨 0: 상대 전체(VPIP, PFR, 3벳, 폴드-투-3벳, c-bet, 폴드-투-c-bet).
- 레벨 1: 포지션 그룹(EP/MP/LP/블라인드) × 스택 구간(≤12bb, 12–25, 25+) × 버블 여부.
- 레벨 2: 위를 곱한 칸. 각 칸의 사전은 한 단계 위의 사후.
- 정책에는 레벨 0·1을 항상 주고 레벨 2는 `N`이 충분한 칸만 마스크를 풀어 준다(마스크도 입력).
- 버블 효과는 한 게임 안에서 표본이 매우 적으므로 기본은 모집단 사전의 버블 보정, 개인 편차는 표본이 쌓일 때만 반영.
- 컨텍스트 칸 정의는 `referee/DATA_SUFFICIENCY.md`의 셀과 정렬해야 한다. 정의를 두 곳에서 따로 정하지 않도록 한 모듈로 모은다(F2).

## 4. 최근 K 액션 시퀀스 인코딩 (AI-2 입력)
`recent_actions`는 `(hand_id, player_id, street, action, amount)` 목록이다.
- 토큰: `[상대 좌석 슬롯 | street | action 원-핫 | 금액(BB, 팟 비율) | 현재 핸드와의 거리]`.
- **식별은 `player_id`가 아니라 본인 기준 좌석 슬롯 또는 게임 내 로컬 인덱스.** 학습이 특정 player_id를 외우면 게임 간 누출 경로가 된다.
- K 후보 {16, 64, 256}. K를 넘는 과거는 AI-1 통계로만 남는다(통계=장기, 시퀀스=단기 기억).
- 추론 비용: 선형 투영 + 1층 GRU(은닉 128)는 CPU에서 결정당 수십 µs~수백 µs 규모로 **추정**(구현 전 측정 필요).

## 5. 은닉 상태(GRU)와 게임 경계
- 은닉은 `game_id` 경계에서 0으로 초기화, 핸드 경계에서는 **유지**(상대 성향은 핸드를 넘어 누적), 핸드 입력 상태만 재설정.
- 학습: trajectory를 game_id로 자르고 첫 스텝에서 은닉 초기화(ADR 0003 결정 2). BPTT 청크 사이로 은닉을 이월(그래디언트는 차단)하되 **청크가 게임 경계를 넘지 않도록** 샘플러가 보장 → 테스트로 고정(F3).
- GRU가 통계에 없는 정보(순서·추세·태도 변화)를 잡을 때만 AI-2 > AI-1. 이득이 없으면 AI-1 채택(`GATES.md` 제거 실험 규정).
- 정보 병목: GRU가 통계를 재학습하느라 용량을 쓰지 않도록 AI-2 입력에 AI-1 통계를 함께 넣고 GRU는 잔차 정보를 맡긴다.

## 6. 안전한 착취
### 6.1 문헌 요지 (확인 필요)
- **Restricted Nash Response** — Johanson, Zinkevich, Bowling, NeurIPS 2007: 상대 모델을 믿는 정도 `p`로 착취 이득과 최악 손실을 교환.
- **Data-Biased Response** — Johanson & Bowling, AISTATS 2009: 상대 데이터 양에 따라 믿음을 정함. 우리의 `N` 의존 수축과 같은 철학.
- **Safe Opponent Exploitation** — Ganzfried & Sandholm, EC 2012 / TEAC 2015: 균형 보장값 이상을 보장하는 착취.
- **Bayes' Bluff** — Southey et al., UAI 2005: 상대 전략 사후 위의 최선응답.
- **Pluribus** — Brown & Sandholm, Science 2019: 6인 포커에서 상대 모델링 없이 블루프린트+탐색으로 강함 → AI-0 기준선이 높다.
- 신경 쪽: GRU — Cho et al. 2014; PPO — Schulman et al. 2017; 순환 모델-프리 RL이 메타-RL 기준선으로 강함 — Ni et al., ICML 2022(확인 필요).

### 6.2 우리 설계에 주는 함의
- 외부 RNR 솔버를 돌리지 않고, **훈련 상대 풀**(nit/TAG/LAG/콜링스테이션/과잉 셔버/내시 근사)을 에피소드마다 섞어 정책이 통계로 상대를 추정해 반응하게 학습한다(메타-RL 형태). 안전성은 두 곳에서 측정:
  1. 착취 이득: 비내시 풀에서 AI-1/2 − AI-0 ROI.
  2. 착취가능성: 정책의 적응을 역이용하는 적대적 풀(미끼 후 반전)에서의 손실. Gate C 보고의 별도 열(통과 조건 아님, 레벨 2 견고성의 전초).
- **명시적 혼합(AI-1s) 후보**: `π = (1−λ(N))·π_AI0 + λ(N)·π_adapted`, `λ(N)=N/(N+N0)`. 같은 시점 AI-0 확률과의 차이가 곧 기록 재료(ADR 0003 결정 6)라 해석이 쉽다.

## 7. Gate C 실험 설계
### 7.1 가설과 비교
- H1: AI-1 − AI-0 > 0 (ROI). H2: AI-2 − AI-0 > 0. H3(제거): AI-2 − AI-1 > 0이면 AI-2 채택, 아니면 AI-1.
- 통과 조건은 "AI-1 또는 AI-2" → 다중비교. 추천: **사전 등록으로 주 가설 1개 지정**(나머지는 탐색적), 대안은 Bonferroni.
- 상대 풀과 구조는 사전 고정·버전 관리. (a) 훈련에 쓴 유형, (b) **훈련에 없던 유형(OOD)** 을 따로 보고. 기억의 가치는 (b)에서 가장 잘 드러난다.
- 같은 시드·좌석·카드 순서로 AI-0/1/2를 돌리는 **대응(duplicate) 설계**로 분산을 줄인다(정확도 향상 목적, 표본 절감 목적 아님 — 리뷰 §2.5).

### 7.2 필요 표본 수 (로컬 계산, 참고용)
가정: 양측 α=0.05, 검정력 0.9, 비대응 두 군 `n_군 = 2·(1.960+1.282)²·σ²/δ²`. σ=토너먼트당 순이익 표준편차(바이인 단위, 1.3~1.6 추정). 대응 설계에서 쌍 상관 ρ이면 `(1−ρ)`배.

| 검출 ROI 차 δ | σ=1.3 군당 | σ=1.6 군당 | ρ=0.5 (σ=1.3) | ρ=0.7 (σ=1.3) |
|---|---|---|---|---|
| 1%p | 355,150 | 537,978 | 177,575 | 106,545 |
| 2%p | 88,787 | 134,495 | 44,394 | 26,636 |
| 3%p | 39,461 | 59,775 | 19,731 | 11,838 |
| 5%p | 14,206 | 21,519 | 7,103 | 4,262 |

**리뷰 §2.5와의 차이**: 리뷰는 3%p에 "군당 1.5만~2.2만"을 적었다. 이는 `7.84σ²/δ²`(검정력 0.8, 한 군 분산만)에 해당하고, 여기서는 두 군 분산 모두·검정력 0.9로 계산했다(대응 ρ=0.5이면 3%p에 약 1.97만으로 리뷰 값과 비슷해진다). 사전 등록 전에 정의를 한 곳으로 통일해야 한다(F4).
- 결론: 실제 효과가 2%p 이하이면 수만 판이 필요하고 1%p면 대응 설계+고속 엔진 없이는 불가능하다.
- **최소 의미 효과(MCE)** 를 사전 정의해야 한다. 추천 2%p(대응 ρ=0.5, σ=1.3 기준 군당 약 4.4만 판).

### 7.3 분산 감소 후보
- 대응 좌석·카드 교환(필수).
- 불완전정보 평가용 분산 감소(AIVAT, Burch et al. AAAI 2018 — 확인 필요). 토너먼트(ICM)에 맞는 보정 항 설계는 연구 과제(F4 스파이크).
- 조기 중단은 가망 없는 후보를 버릴 때만(`GATES.md` 표본 정책).

## 8. AI-0 / AI-1 / AI-2 설계안
| | AI-0 | AI-1 | AI-2 |
|---|---|---|---|
| 상대 입력 | 없음(현 핸드 공개 정보) | 컨텍스트별 사후 평균·N·분산(계층 수축) | AI-1 입력 + 최근 K 시퀀스 → GRU |
| 게임 경계 | 해당 없음 | `end_game`에서 폐기 | 통계 폐기 + 은닉 0 초기화 |
| 학습 | 같은 아키텍처, 메모리 입력 마스킹 | 통계 입력 on | 시퀀스 on |
| 비용 | 기준 | 상태 몇 KB | 은닉 128~256 float, 순환 추론 |
| 기록 | policy_version, logprob | + AI-0 확률(같은 시점) | + AI-0, AI-1 확률 |

AI-0/1/2를 **공유 가중치 + 메모리 입력 확률적 마스킹**으로 학습하면 같은 결정 시점의 AI-0/1/2 확률을 추가 추론으로 얻어 ADR 0003 결정 6의 기록 요구에 맞는다. 대안은 별도 모델 3개(비용 3배, 비교는 더 깨끗). 추천: 공유 가중치 + 주기적 별도 모델 검증.

## 9. Gate L 경계와 제약 점검
| 위험 | 대응 |
|---|---|
| 게임 간 누출(통계·은닉 잔존) | `end_game` 폐기(구현됨), 은닉 0 초기화, 같은 입력을 새/이월 상태로 돌려 출력 동일 확인(F3) |
| player_id 암기 | 슬롯/로컬 인덱스만 입력, 훈련 시 ID 셔플 |
| 비공개 카드 | 관측 빌더가 유일한 출입구(기존 누출 테스트 유지) |
| 시퀀스 시간 누출 | K 윈도는 현 결정 시점까지로 절단, 테스트 |
| CPU 처리량 | 추론 0.2 ms/결정·150 결정/판이면 추론만 판당 약 30 ms(추정). 엔진 비용은 ADR 0005 벤치. 수만 판은 다코어 필요 → 평가를 CI 병렬 job으로 분할(F4) |

## 10. 위험과 미해결
1. 효과가 2%p 미만이면 현 인프라로 Gate C 판정이 어렵다 → NH-1(연산 자원)과 연관.
2. 상대 풀 설계가 결과를 좌우한다(착취 가능한 상대가 많을수록 기억 가치 과대).
3. GRU 학습 불안정(긴 지평, 희소 보상) → 보조 손실(상대 액션 예측)이 흔한 처방(확인 필요).
4. 일부 문헌은 서지 확인 필요(F1).
