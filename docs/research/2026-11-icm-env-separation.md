# ICM·토너먼트 환경 분리 기준 (Phase E 사전 조사)

> 웹 검색(표준 모드) 기반 1차 조사. 아래 수치는 모두 **외부 문헌·강좌의 값이며 CI 결과가 아니다.** 블로그·상업 사이트는 방법론 불명이라 근거로 쓰지 않았고, 확인하지 못한 논문은 인용하지 않았다.

## 질문
1. 토너먼트 환경(`env_id`, CHARTER 불변 4)에서 칩 가치를 어떻게 모델링해야 하는가 — ICM만으로 충분한가?
2. `plan.icm`(TP.md: 리스크 프리미엄 = ICM 필요 에퀴티 − 칩EV 필요 에퀴티)을 정확 ICM·근사 중 무엇으로 계산할까?
3. 캐시와 토너먼트를 한 정책으로 묶지 말고 분리해야 하는 조건의 최소 목록은?

## 핵심 발견
- **ICM = Harville(1973) 순위 확률 + Malmuth(1987) 포커 적용.** 스택·페이아웃으로 각자 상금 에퀴티를 낸다. 정확 계산은 인원에 대해 팩토리얼이라 선수가 많으면 몬테카를로 근사를 쓴다. ([arXiv 2506.00180 서론](https://arxiv.org/html/2506.00180v2))
- **실증: ICM은 대체로 맞지만 스택 크기별 편향이 있다.** 대규모 토너먼트 데이터 검증에서 숏/빅 스택 구간에서 체계적 차이가 보고됨. → ICM은 "정답"이 아니라 기준 모델이다. ([Empirical Validation of the Independent Chip Model](https://arxiv.org/pdf/2506.00180))
- **리스크 프리미엄/버블 팩터는 같은 현상의 두 표현.** 버블 팩터 = 칩 손실 비용 ÷ 칩 이득 가치, 리스크 프리미엄 = 칩EV 손익분기 위에 필요한 추가 에퀴티. 머니 버블·파이널 테이블에서 크고(출처별 5~20%p로 편차 큼, 방법론 불일치), 초반엔 작다. ([PokerStrategy Future Game Simulation](https://www.pokerstrategy.com/strategy/sit-and-go/2380/1/))
- **Future Game Simulation(FGS):** 리스크 프리미엄이 낮은 환경에서는 스택이 작아도 향후 수익성이 높고, 높은 환경에선 위험 회피가 지배한다 — ICM이 놓치는 "남은 게임에서의 스택 기술 우위"를 보정하는 개념(같은 출처). 현 ADR 0002가 이미 ICM·FGS 페이오프를 언급함.
- 딥RL에 학습형 ICM 모듈을 붙이자는 제안이 있으나 **제안서 수준, 결과 없음**([Technion CRML](https://crml.eelabs.technion.ac.il/?p=5615)). 근거로 삼지 않는다.

## STALKER에 대한 함의
- `plan.icm`은 TP.md 설계대로 **콜·올인 결정 한정 리스크 프리미엄**이 맞다. 생존 ≤9명이면 정확 ICM(9! ≈ 36만, 캐시 가능), 초과 시 몬테카를로/요약 추정 + "추정 ICM" 표시 — 현 명세와 일치, 변경 불필요.
- 보상 설계: 토너먼트 환경의 학습 보상은 칩 변화가 아니라 **ICM(또는 ICM+FGS 보정) 에퀴티 차이**여야 한다. 칩EV 보상으로 학습하면 버블 구간 정책이 구조적으로 틀린다.
- 평가: ICM 자체의 편향(위 실증) 때문에 Gate의 토너먼트 승부는 ICM 에퀴티뿐 아니라 **실제 시뮬레이션 상금 기대값**(페이아웃 적용)도 함께 기록해야 편향 순환을 피한다.
- **환경 분리 최소 키(제안):** 페이아웃 구조(상금권 비율·가중), 블라인드 증가 속도(핸드/레벨 대비 스택 BB), 인원/잔여 인원, 앤티·BB앤티 유무, (PKO 등 바운티 있으면 별도 환경 — ICM과 바운티는 반대 방향 힘). `env_id`에 이 키의 해시/명시 필드를 넣는다.

## 위험
- 정확 ICM을 학습 루프 보상에 매 핸드 호출하면 속도 병목 — 정체 인원 ≤9로 캐시하거나 스택 구간 양자화 필요.
- FGS는 문헌상 정량 정의가 제각각(출처 블로그 중심). 구현 시 단순 파라미터(리스크 프리미엄 하한) 하나로 시작하고 효과를 CI로 검증해야 한다.
- 이번 조사는 학술 근거가 얕다(검증된 논문 1편). 심화는 별도 이슈.

## 측정 도구
- `stalker/tools/icm_calibration.py`(#834): 같은 중간 상태에서 생존자별 ICM 에퀴티와 시드 고정 시뮬레이션 상금 평균·sd·차이(sim − icm)를 JSON으로 낸다.
- 실행 예: `python -m stalker.tools.icm_calibration --players 6 --remaining 3 --stack-profile skewed --games 200 --seed 0 --out icm.json`
- `--agents persona:NAME`(#843, 기본 `random`): 모든 좌석을 같은 페르소나(`PersonaAgent`, `persona_params`의 이름)로 채워 대칭 실력을 유지한다. 출력(`schema_version` 2)의 `diff_se`(= `sim_prize_sd/√games`)·`z`(= `diff/diff_se`, se 0이면 0)로 차이가 표본 오차인지 가른다.
- 이 도구로 얻는 수치는 로컬 참고값이며 CI 결과가 아니다(합격선 없음).
