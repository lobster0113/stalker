# RunPod CPU flavor: cpu3c vs cpu5c, 32 vCPU (#373)

목적: E3 파드 체인(`jobs/e3-tp-*-pod32.yaml`)에 달러당 반복이 더 많은 CPU flavor를 고른다. cpu3c는 같은 값($0.96/h)에 EPYC 9655·9654·9754·7713 호스트로 떨어지고 it/s 차이가 2.2배다(#373 코멘트, ADR 0019 §6).

## 방법
- 잡 `jobs/e3-tp-mid9-c5-pod32.yaml`(PR #394): `e3-tp-mid9-pod32`와 같은 명령(중수 9인, 워커 32, 90분, batch 500, seed 1, 새 학습)이고 `cpu_flavor: cpu5c`, `hourly_usd: 1.6` 상한만 다르다.
- `cloud.yml` `mode=run` 2회(ref main, 2026-10-30~31: 1회차 095f6af, 2회차 ab1d186). 단가·분·비용은 `ops:budget/ledger.jsonl` end 줄, it/s·CPU는 `ops:cloud/results/<run>.summary.json`의 `iters_per_s`·`machine.cpu_model`.
- 지표: **반복/달러** = `iters_per_s × 3600 / cost_per_hr`. 설치·평가 시간도 돈이 들지만 두 flavor가 같은 명령이라 비율에는 거의 영향이 없다.

같은 잡(중수 9인) cpu3c 두 run의 평균은 89 it/s, **반복/$ 334천**이다. 다른 잡의 cpu3c 호스트별 it/s(같은 $0.96/h): 중수 6인 146.7(9655)·71.2(7713)·129.65(9654)·154.96(9655P, run 40968157300), 고수 6인 151(9655)·67.7(9754). cpu3c 8개 run 중 3개(38%)가 느린 호스트(7713·9754, 빠른 호스트의 약 0.45배)였다.

## 해석
- cpu5c는 두 번 다 같은 EPYC 9575F 호스트 계열에 떨어졌고 it/s가 161.14·161.79로 거의 같다(편차 0.4%). 두 run은 반복 수(880,000)와 LBR(0.4576 bb)도 같았다.
- 단가는 $1.12/h로 cpu3c($0.96/h)보다 17% 비싸다. 상한 $1.60 안이라 요금 검사에 걸리지 않았다.
- **반복/$**: cpu5c 519천(평균) vs cpu3c 같은 잡 평균 334천 → **1.55배**. cpu3c가 빠른 호스트(9655)에 걸렸을 때(442천)보다도 1.17배다. 즉 cpu3c는 운이 좋아도 cpu5c보다 비싸고, 느린 호스트(7713, 225천)에 걸리면 cpu5c의 0.43배다.
- 같은 반복을 사는 시간도 cpu5c가 짧다(161 vs 평균 89 it/s). 체인 벽시계가 줄어든다.
- 용량: cpu3c는 10-29 저녁 HTTP 500 no-instances가 10회 이상 났지만, cpu5c는 이번 두 번 다 바로 만들어졌다(표본 2).

주의(참고 수준):
- cpu3c 기준 run은 10-29의 이전 커밋이고 cpu5c run은 095f6af·ab1d186이다. 그 사이 E3 엔진·메뉴 변경(#388·#412·#431 등)이 있었으므로 같은 커밋 비교가 아니다. 같은 호스트 계열(9655P)의 중수 6인 it/s가 146.7(10-29 오전) → 154.96(10-30, 9bb64ec)로 비슷했으므로, 코드 변경이 it/s를 크게 바꾸지는 않은 것으로 본다.
- 표본이 run 2개다. cpu5c도 다른 호스트로 떨어질 수 있다(이번에는 두 번 다 9575F). 체인에서 결과 JSON의 `machine.cpu_model`을 계속 본다.
- 비용: 두 run 실제 합계 $3.53(예약 $8.00), 10월 원장 종료분 합계 $29.86(상한 $100).
- 성능 판정 근거는 CI(여기서는 cloud.yml run 결과) 수치뿐이다. 위 표는 모두 cloud.yml 결과에서 옮긴 값이다.

## 결정
**cpu5c가 이긴다.** 체인 잡의 기본 flavor를 cpu5c로 바꾼다.
- 후속(이 PR 범위 밖, Planner 이슈화 요청): `jobs/e3-tp-pro-pod32.yaml`·`jobs/e3-tp-mid-pod32.yaml`·`jobs/e3-tp-mid9-pod32.yaml`의 `cpu_flavor`를 `cpu5c`로, `hourly_usd`를 1.6(이번 상한, 실제 1.12)으로 바꾼다. vCPU는 32 그대로라 이어 달리기(`resume_run`)와 워커 수가 맞는다. 최악 예약은 run당 `1.6 × max_minutes / 60`으로 커지므로(고수 320분이면 $8.53) 월 상한 대비 예약을 다시 본다.
- ADR 0019 §6의 flavor 대체 목록 제안(harness-change)은 순서를 **cpu5c 먼저, cpu3c 대체**로 한다. cpu5c가 용량 부족일 때만 cpu3c로 내려간다.
