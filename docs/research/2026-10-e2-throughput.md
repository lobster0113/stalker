# E2 처리량 측정 (#179, ADR 0012 E2-2)

목적: 유료 연산(사용자 허용: 학습 준비가 끝나면 사용)의 규모를 정하기 전에, E2 무제약 MCCFR의 반복/초와 비용을 잰다.

## 로컬 (Windows 노트북, 1코어 Python, 참고값)
`python -m stalker.e2.mccfr --iters N --seed 1`. 결정/초는 트리 노드 방문 수(`_walk` 호출)를 센 값이다. 테이블은 regret·평균 전략 배열의 바이트다.

| 반복(누적) | 반복/초 | 결정/초 | 정보 집합 수 | 테이블 |
|---|---|---|---|---|
| 500 | 32.7 | 2,791 | 5,553 | 0.31 MB |
| 2,000 | 30.4 | 2,348 | 12,756 | 0.64 MB |
| 5,000 | 30.6 | 2,699 | 20,898 | 0.96 MB |

- 측정 중 다른 평가가 같은 CPU를 쓰고 있었다. 단독 실행 때는 약 49 반복/초였다(첫 측정: 500회 10.2초, 2,000회 41.2초).
- 반복 하나는 딜 1회 × 두 좌석 순회(외부 표본)이고, 약 80개 결정 노드를 방문한다.
- **메모리**
  - 정책 테이블은 작다. 정보 집합 2만 개에 약 1 MB이고, 100만 회 티어 정책(1.6–3.6만 정보 집합, 로컬)도 수 MB다.
  - 메모리를 지배하는 것은 보드별 강도표 캐시(`ehs_table`)다. 보드당 1,326 × 8바이트 ≈ 10.6 KB이고, 현재 상한은 20,000 보드(≈ 0.2 GB, #187로 머지됨)다. 그 전 상한 200,000 보드에서는 최악 약 2.1 GB였다. 10-27 밤 로컬 장기 실행의 여유 메모리 경보가 그 때문이었다.
- 병목: 순수 Python 트리 순회와 보드별 강도표 계산이다. numba 선택 커널(#241, PR #237 머지)이 강도표를 빠르게 하고, 효과는 아래 CI 수치에 있다.

## CI 측정 (`train.yml`, GitHub Actions 무료 러너)
#222(#184) 이후 CPU 학습은 RunPod이 아니라 무료 `train.yml`에서 돈다(`jobs/README.md`). RunPod은 GPU가 필요한 단계에서만 쓴다. 요약은 ops `training/e2-mccfr/<run id>.json`에 있다. #245 전의 요약에는 sha가 없어, 실행 커밋은 run id로 확인했다.

| run id | 커밋 (ref) | numba | 시드 × 반복 | 반복/초(평균) | LBR(bb/핸드, 400핸드) |
|---|---|---|---|---|---|
| 40612034924 | 31ab4da (main) | 없음 | 4 × 40만 | 69.6 | 1.31 (1.59 / 1.09 / 0.98 / 1.59) |
| 40624326818 | cec37fd (claude/201-fast-eval-main, PR #237) | 있음 | 2 × 2만 | 220.6 | 1.46 (2.31 / 0.61) — 2만 회라 학습 초기 |

- 반복/초는 약 3.2배 차이다. 원인은 numba 커널(#237, 머지 전 브랜치에서 측정)이다. 두 실행은 반복 수가 달라 초반(정보 집합이 적은 구간) 비중이 다르므로 정확히 같은 조건은 아니다.
- 로컬 단독 실행(약 49 반복/초)보다 CI 러너(69.6)가 빠르다.
| 40629217430 | ae8b068 (main) | 있음 | 4 × 100만 | 189.0 | 0.956 (0.73 / 1.10 / 1.02 / 0.98, SE 약 0.13) |
| 40634125088 | main (#201 작업 전) | 있음 | 2 × 2만 | 177.7 | 1.61 (2만 회라 학습 초기) |

- 100만 회 학습(run 40629217430)에서 LBR이 1.31(40만, numba 없음)에서 0.956bb/핸드로 내려갔다. 반복 수가 달라 같은 조건 비교는 아니다.
- 반복/초는 반복 수가 클수록 낮아진다(정보 집합이 늘면서 강도표 캐시 미스가 늘기 때문으로 추정, 미검증). 예산은 220이 아니라 약 190 반복/초로 잡는다.
- PR #201(미머지)의 랭크 쌍 강도표 커널은 2 × 2만 회에서 634 반복/초(run 40634826788)를 보였다. 머지 후 이 표를 갱신한다.

## 본 학습 예산안 (CI 수치 기준)
- numba가 있는 main에서 러너 1개는 약 190 반복/초(100만 회 실측)다. 10⁶회는 약 88분이고, LBR 4000핸드 평가가 더해진다. 잡 상한 340분 안에서 시드당 최대 약 3.5×10⁶회다.
- 병렬: 시드 매트릭스(최대 8)로 독립 시드를 돌려 평균한다. 공개 리포라 비용은 0이다.
- 회수: `train.yml`이 아티팩트(정책)와 ops 요약으로 돌려준다(#222).
- 결론: E2 본 학습(티어·에퀴티 view·리그)은 CPU 무료 러너로 충분하다. RunPod 유료 연산은 E2에서는 필요 없다.

## RunPod 소형 CPU 측정 (#179 수용 기준 2)
하지 않았다. CPU 학습이 무료 `train.yml`로 옮겨 간 뒤(#222) 같은 측정을 유료 파드에서 한 번 더 하면 비용만 들고 예산안(위)이 바뀌지 않는다. 유료 연산이 필요해지는 시점은 GPU 단계(E3 이후)이고, 그때의 처리량은 그 단계의 잡에서 잰다. 수용 기준 2는 Planner가 대체·삭제로 정리해야 한다.
