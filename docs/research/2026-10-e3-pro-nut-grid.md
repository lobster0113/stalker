# E3 고수 키: board.nut 학습 눈금 17 → 5 (#332, #338)

## 질문
고수 학습 키에서 `board.nut`을 17단계(채점 눈금과 같은 폭) 대신 5단계(20점 칸)로 묶으면, 같은 반복 수에서 키 수가 절반 이하로 줄고 LBR은 나빠지지 않는가?

## 방법
- 같은 잡 `e3-tp-pro-w4`(6인, 워커 4), 같은 반복 10⁵회 × 시드 4개, 둘 다 처음부터 학습(resume 없음).
  - 기준(NUT_K=17): train run 40815871622, sha 4a1237b(#338 머지 전).
  - 비교(NUT_K=5): train run 40894774806, sha 24a9fa6(#338 머지 후).
- 별도 잡 `e3-tp-pro-w4-n5`는 만들지 않았다. 보호된 평가기(LBR·필드)는 `equity_steps`에 k만 넘기므로 nut 눈금은 테이블 상수여야 학습과 평가가 같은 키를 본다(이슈 #332 코멘트, planner 판단).
- 수치 출처는 모두 CI다: `ops:training/e3-tp-pro-w4/<run>.json`. 키 수는 아래 "키 수" 절.

- SE는 시드별 LBR 표준오차를 합친 값(√Σse²/4)이다. 기준의 95% 신뢰구간은 0.964 ± 0.270 = [0.694, 1.235]이고 NUT 5의 0.854는 그 안에 있으며 더 낮다(덜 착취당함).
- 아티팩트 크기는 체크포인트(regret·전략 합 배열)가 대부분이라 키 수에 거의 비례한다. 키 수와 함께 적는다.

### 키 수
- NUT 5: train run **40928087948**(이 PR 브랜치, sha 6733912)이 40894774806의 시드별 체크포인트에서 1회만 더 학습하고 요약에 `infosets_by_seed`를 남겼다(이 PR이 요약에 추가한 필드). 시드별 150,951 / 152,509 / 152,135 / 151,832, `resumed_from_iters_by_seed` = 10⁵ × 4. 1회 반복으로 새로 생기는 키는 많아야 수십 개라 10⁵회 키 수로 본다. 이 run의 LBR은 1회 더 학습한 정책이라 표에 쓰지 않았다.
- NUT 17: 372,190은 기준 run 40815871622의 키 수다(#332 코멘트 10-29 14:46Z). 그때 요약에는 키 수 필드가 없었고, 체크포인트는 NUT 17이라 지금 코드의 `from_state`가 거부해(#338) 같은 방법으로 다시 셀 수 없다.
- 두 값의 비 40.8%는 같은 run들의 CI 아티팩트 크기 비 43.5%와 맞는다(키 문자열은 NUT 5 쪽이 약간 짧다).
- 앞으로 train.yml 요약에는 `infosets_by_seed`가 늘 남는다.

## 판정 (수용 기준)
- 키 수 ≤ 50%: **충족**(40.8%, 아티팩트 크기 비 43.5%).
- LBR이 기준의 95% 신뢰구간 안이거나 더 낫다: **충족**(0.854, 구간 [0.694, 1.235] 안, 평균은 더 낮음).
- 필드 최악도 나빠지지 않았다(−126.3 → −97.2 bb/100, 시드 4개라 방향만 본다).
- 처리량은 그대로다(16.2 → 17.0 it/s, 러너 차이 범위).

## 해석
1. 17단계 nut 칸은 키를 거의 17배로 쪼갰지만, 칸마다 방문이 적어 학습이 느렸다. 5단계로 묶어도 같은 계산량에서 LBR이 나빠지지 않았다. 키를 TP가 실제로 구분해야 하는 만큼만 쪼갠다는 원칙(`2026-10-e3-tp-keys.md`)과 같은 방향이다.
2. NUT_K=3은 시험하지 않는다. 기준 2가 이미 충족되어 더 거칠게 묶을 이유가 없다.
3. 고수 파드 run 40840669062(NUT 5, 2.18×10⁶회)는 195,084키였다. 반복이 약 22배일 때 키는 1.28배다(10⁵회 151,857 → 195,084). 키 증가가 느려졌으므로 ADR 0017의 고수 키 가정(30만)은 NUT 5에서 여유가 있다. 다만 파드는 워커 32개라 같은 잡이 아니다.

## TP 명세 해석: 학습 눈금이 채점 눈금과 달라도 되는가
- TP.md §4.1의 눈금(고수 0–100, ±3)은 **사람의 답을 채점하는 규칙**이다. 정답 `board.nut` 값은 정의식(상위 10% 질량의 상대 비율)으로 계산되고, 학습 키가 몇 칸으로 묶이든 바뀌지 않는다.
- 학습 키는 정책이 "같은 상황"으로 취급할 범위를 정한다. 5단계는 20점 폭 안에서 같은 행동을 한다는 뜻이다. TP-GTO 요구(TP를 거쳐서만 행동)는 키가 TP 값의 함수이면 지켜진다. 함수가 거칠어도 된다.
- 그래서 보호 경로(`docs/TP.md`, `stalker/tp/spec/`, `referee/`)는 고치지 않았다. 채점 눈금이 그대로이고 NUT_K가 테이블 쪽 상수일 뿐임은 `tests/test_e3_pro_key.py`(#338)가 확인한다.
