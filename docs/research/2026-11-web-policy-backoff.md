# 웹 정책 표 미적중과 거친 키 백오프 (#618, 로컬 참고용)

> **참고용 수치.** 이 문서의 숫자는 builder가 컨테이너에서 직접 돌린 값이다(CLAUDE.md: 판단 근거는 CI 결과뿐). CI로 다시 재려면 `--backoff`를 export 요약(#617) 쪽에 붙이는 후속을 쓴다.

## 측정
```bash
for n in 2 3 4 5; do
  python -m stalker.tools.web_hit_rate web/app/policy/mid-$n.json --hands 1000 --seed 611 --backoff
done
```
- 표: 커밋된 `web/app/policy/mid-<n>.json` (main `22a61c6e`, #615 재-export 뒤, run 41813684540 c1 mixn, `min_visits` 2인 10 / 3–5인 5). sha256:
  - mid-2 `a4287c014ca0f3e58ab0d9d31dc5472d860d884eb0f83e410508a79f2b981008`
  - mid-3 `c78a325925b73ea47c15381c5c355917f38aa99b92826d470b718d81d48578ea`
  - mid-4 `3f248f0cd2449a8ffd8310315a99fb4f1d91d283221e91c7e7291576ed0bff5b`
  - mid-5 `0b78519957536a050e453ced988d25c838212413dfd10903245986a8647c2cd4`
- 플레이 규칙은 오늘의 페이지 그대로다: 실제 키에 행이 없으면 균등. 백오프 수준은 **세기만** 하고 플레이에 쓰지 않는다(백오프를 페이지에 넣으면 궤적이 바뀌어 수치도 조금 달라진다).
- 수준 정의(`stalker/tools/web_hit_rate.py` `coarse_key`):
  - **L1** — b1 손 칸(`o<outs>v<vuln>k<block>`)을 지우고 스택 칸 `s<나>:<상대들>`을 `s*`로.
  - **L2** — L1 + 공개 사실(`u<앞><뒤>`·`h`·`g`)과 SPR 칸을 `*`로. 남는 것: 위치·인원·스트리트·상대 수·레이즈 수·주도권·팟 오즈·합법 메뉴·에퀴티 단계(초보 키가 묻는 것과 같은 축, TP.md §4.1). `call|` 키는 L2에서 상대 수만 `*`.
  - 같은 거친 키의 행을 평균한다. 길이(합법 액션 수)가 다른 행은 합치지 않는다.

## 먼저: #616 「97% 미적중」은 도구가 페이지와 다른 규칙으로 돌았기 때문이다
#616 도구는 핸드를 엔진 기본값 **v1 메뉴**(오픈 `r` 하나)와 **무작위 깊이 스택**으로 돌렸다. 그런데 mid-2..5 표는 `menu: real`(오픈 `r2`·`r22`·…)로 학습됐고, 페이지는 파일의 메뉴(`tpgto.js menuOf`)로 **100BB**에서 핸드를 시작한다(`newHand`에 stacks 없음). 키의 합법 메뉴 칸(`fcra` vs `fcr2r22rr3…a`)이 달라 비-`call|` 키는 거의 맞을 수 없었다.
- 같은 mid-3, 200핸드, 시드 611: 이전 규칙 비-`call|` 정밀 적중 **2.7%** (635결정) → 이 PR의 페이지 규칙 1,000핸드 **81.9%** (4,389결정).
- 이 PR이 도구를 고쳤다(`rules_of`: 파일의 `menu`·`raise_cap`, 100BB). #617의 export 요약 `hit_rate`(PR #621)도 `measure`에 `rules`를 넘겨야 같은 값이 나온다.

## 읽기
- **프리플랍은 이미 대부분 맞는다**(86–97%). 남은 미적중은 L1(스택 칸)에서 대부분 해소된다. 학습은 20–250BB 로그 균등 스택이라 페이지의 100BB(`s6`)와 상대 깊이 조합 일부가 표에 없는 것으로 보인다(추정).
- **포스트플랍 정밀 적중은 27–42%(플랍)** 로 낮다. 손 칸·스택 칸을 지운 L1이 플랍에서 5–35%p를 더하고, L2는 플랍·턴에서 1–13%p만 더한다(리버는 결정 수가 17–50으로 적어 읽지 않는다). 플랍 미적중이 4–5인에서 54–61% 남는 것은 L2로도 안 풀린다: 다인 팟 포스트플랍 자체가 학습 40,000회에서 드물었다(학습 커버리지 문제, `min_visits` 필터만의 문제가 아님 — #617 CI 수치로 확인할 것).
- `call|` 키는 모든 인원에서 100% (인원 무관 공유 키, #610).
- 결정 수 가중 전체(비-`call|`)로 보면 정밀 73–82% → L1까지 86–91% → L2까지 87–92%.

## 결론 → ADR 0022
런타임 백오프(정밀 → L1 → L2 → 균등)가 파일 크기 0으로 남은 미적중의 절반 이상을 덮는다. export 때 L1 행을 미리 넣으면 mid-3는 3MB 페이지 예산을 넘는다(2,556,152바이트 + 9,683키 × 약 70바이트 ≈ 3.23MB). 자세한 비교는 `docs/decisions/0022-web-policy-miss-fallback.md`.
