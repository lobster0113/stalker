# own-reach 평균 전략 가중치의 분산 제어 — 장난감 오라클 (#448)

- 배경: `avg_rule="own"`(#426)은 상대 도달 곱 Π로 나눠 불편이지만, E3 6인 CI에서 평균 전략 LBR의 시드 간 sd가 0.40(legacy 0.19)이다. 가중치 1/Π는 꼬리가 무겁다(중앙 22, 최대 7×10⁷, #426 측정).
- 수치는 모두 **로컬 참고값**(1코어, 판정 근거 아님). 재현: `python -m stalker.vcfr.avg_variance`(약 30초). 코드: `stalker/vcfr/avg_variance.py`, 테스트 `tests/test_avg_variance.py`.

## 1. 설정
- 게임: 3인 Kuhn(`toy.kuhn3`, 24딜). 헤즈업(Kuhn·Leduc)에는 나눌 상대가 없어 모든 추정기가 같으므로 돌리지 않았다. 이슈의 "3인 Leduc"는 리포에 없다 — 아래 §4 후속.
- 전략: 고정 σ에서는 증분이 모두 σ의 배수라 정규화한 정책이 가중치와 무관하게 σ가 된다(비교 불가). 그래서 **천천히 움직이는 σ_t**(skewed Dirichlet(0.3) 시작, 로짓 랜덤워크 0.15/단계)로 선형 평균(증분×t)을 비교한다.
- 진실: 같은 σ_t에서 `exact_update(avg_reach="own")`의 합. 지표: 키 질량 가중 L1(추정 정책, 진실 정책).
  - **err** = 30회 반복 각각의 거리의 평균(편향 + 샘플링 잡음).
  - **bias** = 잡음 없는 값. 샘플러 증분의 **기댓값**을 모든 샘플 경로 열거로 정확히 계산(`expected_increment`, 24딜 트리라 가능)해 그로부터 만든 정책의 거리. 반복 수 → ∞의 점근 편향이다. (이전 판은 30회 평균 정책의 거리라 err/√30 ≈ 0.006의 잡음 바닥에 묻혀 있었다 — #523 리뷰 지적. none의 bias가 cap2보다 컸던 것이 그 증거.) 테스트: cap=None의 기댓값 = `exact_update` (1e-12), cap 있는 기댓값 = 샘플러 평균.

## 2. 결과 (err는 30회 반복, bias는 정확)
| 추정기 | 100단계 bias / err | 400단계 bias / err |
|---|---|---|
| none (현재 own) | 0 (불편, 정의상) / 0.0304 | 0 / 0.0332 |
| cap c=2 (1/Π를 2로 자름) | 0.0023 / 0.0231 | 0.0055 / 0.0168 |
| cap c=8 | 0.0021 / 0.0281 | 0.0053 / 0.0205 |
| cap c=32 | 0.0020 / 0.0286 | 0.0065 / 0.0230 |
| exact (20단계마다 정확 패스 ×20) | 0.0341 / 0.0341 | 0.0147 / 0.0147 |
| 키별 self-normalised | none과 동일(아래) | 동일 |

- **키별 self-normalise는 효과가 없다.** 행 Σwσ를 Σw로 나눈 뒤 액션에 걸쳐 정규화하는 것이므로, σ 행의 합이 1이라 서빙 정책은 none과 정확히 같다.
- **cap은 작지만 0이 아닌 편향을 만든다**(0.002~0.007, 단계가 늘수록 커짐). 대신 err는 줄었다(400단계 0.033→0.017, c=2). 즉 이 장난감에서 err 감소의 대부분은 분산 감소이고, 편향 비용은 err 이득의 약 1/3 이하다. 이전 판의 "편향은 늘지 않았다"는 틀렸다.
- exact 패스는 샘플링 잡음이 0이지만 σ_t를 m단계마다 한 번만 보므로 결정적 편향이 생긴다(100단계 0.034, 단계가 길어지면 줄어듦). E3에서는 정확 패스가 전체 트리 순회라 비용이 가장 크다.

## 3. 한계
- 장난감의 Π 꼬리는 E3(중앙 22, 최대 7×10⁷)보다 훨씬 얇다(3인 Kuhn은 깊이 3). cap 값 c의 최적은 E3에서 다를 수 있다. 장난감 결과는 방향(cap이 err를 줄이고 작은 편향을 만든다)만 말한다.
- 반복 30회·단일 시드(1)·단일 궤적이다. 큰 차이(2배)만 믿는다.

## 4. 추천과 후속
- **추천: cap, c≈2~8.** 구현이 한 줄(`min(1/Π, c)`)이고 상태가 없다. `E3Sampler(avg_cap=)`로 장난감에는 들어갔다(`avg_cap=None`이면 기존과 비트 동일, 테스트).
- **E3 본체에 넣었다(#529).** `E3MCCFR(avg_cap=)`: `avg_rule="own"`일 때만, `min(1/Π, c)`로 자른다. 체크포인트 version 8(`avg_cap`, 다른 cap 재개 거부, 다른 옵션 필드도 같이 실음), `parallel.py` 워커 인자, `train_jobs`(`avg_cap` 인자, 결과 `avg_cap`), 기본 `None`이면 `t / Π` 식을 그대로 두어 체크포인트·평균 해시가 main과 비트 동일(`tests/test_e3_avg_rule.py`에 main에서 계산한 sha256 상수; #523의 `t*(1/Π)`는 368/1850 키를 1 ulp 움직였다). 파드(`pod_train`)는 미지원.
- **CI 비교는 머지 후에만 돌릴 수 있다**: `train.yml`은 `workflow_dispatch`로 `ref main`에서만 돌기 때문에 avg_cap 학습 잡은 이 PR이 머지된 뒤에야 실행된다. 잡 `e3-tp-mid-ownavg-cap2-w4`·`e3-tp-mid-ownavg-cap8-w4`가 `e3-tp-mid-ownavg-w4`와 `avg_cap`만 다르다. 측정 결과는 아래 §4.1(#530).
- 후속: ② CI 비교 — §4.1에서 수행(#530), ③ 3인 Leduc 장난감 추가.

**결론.** (1) §4.1의 "cap이 평균 전략 LBR을 낮춘다"(10⁵에서 −0.42/−0.27)는 **3×10⁵에서 재현되지 않는다**: 평균은 세 팔 모두 0.71~0.73으로 같다. 10⁵의 own이 1.20으로 이상하게 높았던 것은 학습이 덜 된 탓이었고, 반복이 늘자 own이 따라잡았다(own 1.20 → 0.72; cap2 0.79 → 0.73; cap8 0.94 → 0.71). 이득은 짧은 학습에서만 보인 과도 효과이고, 평균 LBR 개선 목적으로 기본 cap을 바꿀 근거는 없다. (2) 시드 간 sd는 순서가 이제 일관된다: own 0.299 > cap8 0.132 > cap2 0.065. own 대 cap2의 sd 비는 4.6배로 5시드의 구별 한계(약 3.1배, F(4,4) 97.5% = 9.6 → 분산비 21)를 넘는다(cap8은 2.3배라 못 넘는다). 즉 cap은 평균 수준은 그대로 두면서 시드 간 산포를 줄이는 쪽으로 보인다 — 장난감(§2)의 방향과 같다. 단 단일 측정, 시드 5개, 시드 내 LBR SE가 약 0.27로 sd와 비슷해 평가 잡음 한계(§4.1)는 그대로이고, own 시드 3·4(0.475·0.349)가 현재 전략(0.75·0.58)보다 낮은 점이 own의 sd를 키운다. (3) 평균 전략(0.72)이 현재 전략(0.785)보다 좋아져 #580이 물은 "own 평균이 현재보다 나쁘다"는 3×10⁵에서는 해소됐다 — 원인 이분 탐색 대신 10⁵ 시점의 학습 부족으로 설명된다(#580 조사 범위 축소 후보).
