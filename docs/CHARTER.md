# STALKER 헌장 (보호 문서 — `referee-change` 절차로만 수정)

## 목적 (원문: `docs/ORIGIN.md`)
신진서 9단이 바둑 AI의 수를 연구해 AI와 가장 유사한 수를 두게 된 것처럼, **토너먼트 포커 AI의 액션을 연구·이해해 AI와 가장 유사하게 두는 플레이어**를 만든다.
목표 수준은 "해봤다"가 아니라 **세계급 토너먼트에서 통하는 수준**이다.
AI 요구사항의 상세 원천은 사용자 연구보고서 `docs/research/2026-10-24-user-rnd-report.pdf`(검토: `docs/research/2026-10-24-rnd-report-review.md`, 결정: ADR 0003)다.

## 불변 요구사항
1. **토너먼트 전용.** 캐시게임은 범위 밖.
2. **토너먼트 조건 설정 가능**: 인원(6·9max, 인원 감소 5~2인, 54/180인 MTT), 테이블 크기, 시작 스택, 블라인드 구조, 앤티(없음/일반/BB앤티, 숏스택 징수 예외), 레벨 길이, 페이아웃(승자독식·플랫·톱헤비·MTT형, 바운티는 확장).
3. **정보 누적 적응과 기억 경계**: AI는 한 게임(game_id) 안에서 첫 핸드부터 공개 관측(액션·쇼다운)을 누적해 전략을 수정한다. 게임이 끝나면 게임별 관측 메모리를 폐기하고, 다음 게임은 빈 메모리로 시작한다(학습된 범용 정책 가중치는 유지). 특정 스팟만 푸는 GTO/ICMizer류와의 핵심 차이다.
   - **입력 범위**: 현재 테이블(≤9석) + 현 게임 누적 공개 관측 + 공개 토너먼트 요약(스택 분포 요약 포함). 전체 참가자 개별 로그·타 테이블 상세·비공개 카드·난수는 입력하지 않는다.
   - 경계와 누출은 `referee/GATES.md` Gate L로 상시 검증한다.
4. **네 과정**: 1) AI 실행과 입력·결과 저장 2) 입력·결과 분석 → 프로 지망생이 학습 가능한 수준의 세부 유형화 3) 유형화 자료 기반 학습 서비스 4) 1)~3) 점검 및 시스템 발전.
5. **1)·2)가 바닥**이다. 측정 신호를 내는 기반이 무너지면 나머지는 의미가 없다.
   데이터는 유형화 결과와 학습 내용이 통계적으로 의미 있을 만큼 충분해야 하며, 기준은 `referee/DATA_SUFFICIENCY.md`다. 기준 미달 유형은 가르치지 않는다.
6. **개인 전용**: 외부 배포·상업화 없음. 학습 서비스는 휴대폰·태블릿·노트북 어디서나 사용 가능해야 한다.
7. **AI를 직접 만드는 것이 목적이 아니다.** 신진서 9단이 바둑 AI를 직접 만들지 않았듯, 충분한 성능의 공개 AI·솔버·엔진이 있으면 그것을 쓴다. 직접 만드는 것은 공개된 것으로 채울 수 없는 공백(예: 정보 누적 적응 레이어, 토너먼트 조건 결합, 기록·유형화·학습 서비스)에 한정하고, 그 판단은 근거(벤치마크·라이선스·접근성)와 함께 ADR로 남긴다.
8. **사람 개입 없는 운영**: 개발·리뷰·머지·하네스 개선은 에이전트가 수행한다 (`docs/HARNESS_DESIGN.md`).

## 성공의 정의 (`referee/GATES.md`)
- **ICMizer 상회는 필수·최소 기준**(레벨 1): Gate A(ICMizer 지원 스팟 직접 비교) + Gate B(ICMizer-informed 참조 봇과 전체 토너먼트) + Gate C(누적 기억의 가치, AI-0/1/2).
- 그 위로 레벨 2(강한 AI: OOD 견고성), 레벨 3(인간 초월)이 장기 목표다. 레벨 1 확인 전에는 초인간 수준을 전제한 주장·자원 확정을 하지 않는다.
