# 아키텍처 (현재 상태를 반영해 유지할 것)

## 계층
- `stalker/` — 제품(L0)
  - `core/` — 카드(`cards.py`), 7카드 평가기(`evaluator.py`), MC 에퀴티(`equity.py`), ICM(`icm.py`: Malmuth-Harville 정확해 `icm_equity`(생존자 ≤9) + Gumbel-max 몬테카를로 `icm_equity_mc`, 0 스택=탈락·하위 지급 제외), 프리플랍 레인지(`ranges.py`, `data/preflop_equity.json`: 169 클래스 × 랜덤 상대 1~5명 에퀴티, `python -m stalker.tools.build_tables`로 고정 시드 재생성)
  - `tools/` — 오프라인 도구(`build_tables.py`: 프리플랍 에퀴티 테이블, `bench_engine.py`: 엔진 처리량 벤치, `diff_engine.py`: `FastHand`↔PokerKit 차등 테스트, `bench_texassolver.py`: TexasSolver 스트리트×정확도 솔브 시간·메모리)
  - `tournament/` — 토너먼트 설정 스키마(`config.py`: `TournamentConfig`·페이아웃 생성기·`level_at`/`next_level`, JSON 직렬화, `schema_version`=1)와 `presets/*.json`(`python -m stalker.tools.build_presets`로 재생성). `hand.py`: PokerKit 0.7.7(버전 고정) 위의 NLHE 핸드 래퍼 `Hand` — 테이블 좌석 기준 스택(0=빈 좌석)·버튼·SB/BB·앤티(`none`/`classic`/`bb_ante`), 합법 액션 조회·적용, 종료 시 `HandResult`(좌석별 최종 스택·증감, 메인/사이드 팟과 적격 좌석, 팟 지급). 카드는 주입된 `Generator`로 섞은 자체 덱에서만 딜(재현성), `to_phh()`/`replay_phh_final_stacks()`로 PHH 왕복. 러너는 `director.py`(아래). `fast_hand.py`: `FastHand` — `Hand`와 같은 인터페이스의 순수 파이썬 고속 엔진(ADR 0005). PokerKit 규칙·덱 소비 순서를 복제해 같은 시드·액션이면 합법 액션 집합과 `HandResult`가 동일(`stalker.tools.diff_engine`으로 차등 검사), PHH 내보내기는 없음
  - `tournament/director.py` — `run_game(config, agents, rng, observer)`: 라운드마다 모든 테이블이 한 핸드씩(레벨 = 라운드 번호), 동시 탈락은 핸드 시작 스택이 큰 쪽이 상위 순위(동률은 주입 rng 추첨), 테이블 해체·밸런싱(차 ≤ 1, 이동자는 임의 빈 좌석), 페이아웃 → `GameResult`(순위·상금·핸드 수·불법 액션 수). `length_unit=minutes`·`short_stack_rule=skip`은 미구현(명시적 `ConfigError`). 식별자 `game_id`/`tournament_id`/`hand_id`(게임 내 유일)/`player_id`(= agents 인덱스) 분리.
  - `agents/` — `base.py`: `Agent`(`act`/`observe`/`on_game_start`/`on_game_end`), 플레이어별 `Observation`(자신의 홀카드와 공개 정보만), 공개 `Event`(`START_GAME`/`NEW_HAND`/`ACTION`/`SHOWDOWN`/`HAND_END`/`END_GAME`; 홀카드는 SHOWDOWN에서만 공개). 불법 액션은 체크/폴드로 대체하고 `illegal_actions`로 집계. `random_agent.py`: Gate R용 무작위 합법 봇.
  - `rl/env.py` — `TournamentEnv(config)`: 디렉터를 워커 스레드에서 돌리고 `reset(rng)`/`step(action_index)`로 좌석별 결정을 넘기는 다중 에이전트 env. 관측은 `ObservationBuilder`(좌석별 `GameMemoryStore`)만 사용. 액션 = 폴드·콜·팟 비율 레이즈들·올인(마스크 제공, 마스크된 액션은 `ValueError`). 보상 = 상금 − `buy_in`(상금 단위), 게임 종료 시 한 번. step 결과의 `events`에 `game_start`/`game_end` 경계. `reset(..., seat_agents={pid: Agent})`로 지정한 좌석은 게임 안에서 그 Agent가 두고 `step()`에 나오지 않는다.
  - `rl/features.py` — `encode(HeroObservation)` → 좌석 토큰(9, 패딩 마스크)·카드·전역 특징(numpy, torch 불필요). `validate_observation`이 `docs/OBSERVATION.md` 계약 밖 필드를 거부.
  - `rl/policy.py` — `Policy(PolicyConfig(variant), seed)`(가중치 초기화는 seed로만 결정, 전역 RNG 불변) (optional extra `[rl]`, torch CPU). 좌석 트랜스포머 인코더 + 액터(합법 액션 마스크, 불법 확률 정확히 0) + 크리틱. `ai0`=메모리 없음, `ai1`=상대 통계, `ai2`=통계+GRU(`act`가 상태 유지, 게임 경계에서 `reset_memory()`).
  - `rl/train.py` — Recurrent PPO 셀프플레이(`Trainer(config, TrainConfig(seed))`, `[rl]` 필요). 상대 풀(게임마다 새로 뽑음, 학습 데이터 없음): `TrainConfig.random_seats`개 좌석은 스크립트 무작위 봇(`random_action`, `RandomLegalAgent` 규칙), `reference_seats`개는 Gate B 참조 봇 v1(`ReferenceBot`), `past_checkpoints`=N이면 N 반복마다 가중치 스냅샷을 최근 `past_pool_size`개 유지하고 나머지 좌석(학습 좌석 1개 제외)마다 확률 `past_checkpoint_p`로 과거 스냅샷 `PolicyAgent`가 둔다. 풀이 꺼져 있으면 rng 추출이 기존과 같다. 실험 `scripts/rl_opponent_pool.py`, 기록 `docs/research/2026-10-rl-opponent-pool.md`. trajectory 단위 = `Segment`(한 게임 × 한 플레이어). GRU 상태는 행동할 때와 업데이트 재생(`_replay`) 모두 세그먼트 첫 스텝에서 0 → game_id 간 상태 전달 없음(Gate L6, `check_segments`가 배치마다 검사). 보상 = (상금 − buy_in)/buy_in, GAE. 행동 샘플링·미니배치 순서는 시드 `Generator` 하나로, torch 전역 RNG 미사용 → 같은 시드면 같은 가중치. `save()`는 체크포인트에 `policy_version`(`<variant>-i<반복>-<가중치 sha8>`)을 기록, `load_policy()`. `PolicyAgent`: 학습된 정책을 디렉터 `Agent`로 실행(게임별 메모리, `on_game_start`에서 GRU 초기화, `action_probs`는 순수) — 평가와 Gate L1용.
  - `rl/candidate.py` — Gate B 후보 `--candidate stalker.rl.candidate:policy`: `STALKER_RL_CHECKPOINT`(또는 `checkpoint` 인자)의 체크포인트를 `load_checkpoint()`로 읽어 학습 때 레이즈 비율로 `rng -> PolicyAgent`를 돌려준다. 팩토리의 `policy_version` 속성이 판정 대상 가중치를 가리킨다.
  - `observe/` — 관측 계약(`docs/OBSERVATION.md`): `builder.py`(`ObservationBuilder` → 9좌석 고정 `HeroObservation`, 스택 분포 분위수 요약), `memory.py`(`GameMemoryStore`: game_id 경계, 상대별 컨텍스트 통계·최근 K 액션·공개 쇼다운). director의 `Observation.all_stacks`(라운드 시작 전 생존자 스택, 비면 오류)·`hand_start_stack`(히어로의 핸드 시작 스택, `hero_rank` 산출용)와 ACTION 이벤트의 `street`/`facing_bet`가 입력.
  - `records/` — 기록 스키마 v1(`schema.py`, 상세 `docs/RECORDS.md`): `DecisionRecord`(식별자 7종 분리, 토너먼트 맥락, 본인 관측, 기억 요약, `probs_ai0`/`probs_ai1`, 선택 액션·logprob), `HandRecord`, `GameRecord`(보상 = 상금 − 참가비). 타입 검사 `from_dict`와 규칙 검증 `validate`(확률합·합법 액션·타인 홀카드 부재). `store.py`: 런 디렉터리 = `manifest.json`(설정·시드·git sha·policy_version) + `records.jsonl`, 쓰기·읽기 모두 검증.
  - `typing/` — 유형화 v0(`docs/TYPING.md`): `spots.py`(`spot_key(DecisionRecord)` → 단계·유효 스택 BB·포지션·스트리트·팟 유형·상대 프로파일, 못 만들면 None), `report.py`(셀별 결정 수·행동 빈도, 게임 짝/홀 두 쪽에 `referee.sufficiency.judge_cell`을 적용한 S1·S4·S5·`lessonable` → JSON+Markdown; schema v4부터 `generation_priority` = 미달 셀을 결정 비율 × 미달 정도로 정렬)
  - `pipeline/generate.py` — `python -m stalker.pipeline.generate --preset sng9 --n N --seed S --out DIR`: 참조 봇 토너먼트를 `RecordingBot`(결정마다 `DecisionRecord`, 기억 요약에 상대 VPIP)으로 돌려 검증된 기록·매니페스트·리포트를 쓴다. `HandRecord`는 미생성
  - `oracle/` — `texassolver.py`: TexasSolver 콘솔(고정 커밋, `scripts/install_texassolver.sh`로 설치, AGPL 개인 사용) 래퍼. 헤즈업 포스트플랍 `Spot` → 명령 파일 → 실행 → 덤프의 노드별 `(hi, lo)` 콤보 확률(`RootStrategy`), exploitability·시간·피크 RSS. 바이너리 없으면 `TexasSolverError`. 연구 기록 `docs/research/2026-10-24-texassolver-spike.md`
  - `service/build.py` — `python -m stalker.service.build RUN_DIR --out service/web/data`: 유형화 리포트(`report.json`, 스키마 검사, v1·v2는 `upgrade_report`로 올림)와 퀴즈 스팟(`quiz.json`: `lessonable` 셀에서만, 공개 정보·내 카드·합법 액션·AI 혼합전략)을 만든다. 웹앱은 리포 루트 `service/web/`(정적 HTML/CSS/JS, `service/web/README.md`).
  - (예정, ADR 0002) `oracle/` 프리플랍 ICM 솔버·전략 라이브러리, `adapt/` 상대 모델·적응 계층, `agents/` 벤치마크 봇(기본 인터페이스는 구현됨)
- `referee/` — 심판(보호 경로). 게이트·가드·지표.
  - `anchors/` — 이론 기준선. `hu_equity.py`: numpy 벡터화 7카드 평가기(`evaluate`와 점수 동일) + 169×169 클래스 올인 에퀴티 `E`·비충돌 콤보 쌍 수 `N`(`data/hu_class_equity.json`, `python -m referee.anchors.hu_equity`로 고정 시드 재생성). `icm_reference.py`: ICMizer-등가 참조기 v1 — 액션 순서 스택(끝 2석 = SB·BB)·일반/BB 앤티·페이아웃의 푸시/폴드·단일 콜러 트리를 역귀납 평가, 가상 플레이로 플레이어별 BR 이득 ≤ 상금풀×`tol`(기본 0.1%)까지 수렴. 가치 모델 `icm`(해당 핸드 탈락자는 그 순위 상금)·`chipev`, `fgs_depth` d면 말단을 다음 핸드(버튼 1칸) 깊이 d−1 해로 평가. `pushfold.py`: 헤즈업 칩EV 푸시/폴드 내시(스택 1~25bb 0.5 간격 × BB 앤티 0/1bb, 169 클래스 혼합, 가상 플레이로 착취 가능성 ≤0.01bb/핸드; `data/pushfold.json` 캐시, `python -m referee.anchors.pushfold`로 재생성). `ev_loss(policy_fn, stack, ante)`: SB 정책의 내시 BB 대비 BR 손실(bb/핸드). `evaluate_spot(policy_fn, spot, opponents, hero)`(다른 스팟에서 푼 `Solution`은 `SpotError`; `Spot`의 칩 필드는 정수만, 허용 오차는 `BASELINE_TOL`): 고정 상대(내시 `Solution` 또는 `top_percent_strategy` 같은 `Strategy`) 대비 히어로 기대 상금·BR 대비 손실. 한계(오버콜 없음, 비참여자 카드 제거 무시, 포스팅 올인 스팟 거부)는 모듈 문서에.
  - `agents/` — 심판 소유 벤치마크 봇. `reference_bot.py`: Gate B 참조 봇 v1 `ReferenceBot(rng, payouts)`(`REFERENCE_BOT_VERSION` = 구성요소 버전 조합, `factory(payouts)` = `evaluate`용 팩토리). ① 프리플랍 숏스택 구간(유효 스택 ≤ 15bb, first-in 또는 단일 올인/커버 레이즈에 대한 콜): 핸드 시작 스택으로 테이블 전체 `Spot`(액션 순서·앤티 복원, 0.5bb 양자화, 프로세스 캐시)을 만들어 `icm_reference`로 풀고, 균형해에 대한 최선 응답(순수 레인지, `solve_ranges`)으로 푸시/콜. 단일 테이블이면 설정 지급 비율 ICM, 다중 테이블이면 chipEV(v1 한계). ② 그 외 프리플랍: 고정 차트 `data/preflop_chart_v1.json`(위치별 오픈 top-%, 3벳/콜, 4벳 잼, 스택 40% 이상 커밋이면 올인). ③ 포스트플랍: 남은 상대 수만큼의 무작위 핸드 대비 MC 에퀴티(카드 해시 시드, 캐시) + 팟오즈 고정 규칙. `action_probs(obs)`는 관측의 순수 함수(Gate L `REGISTRY` 등록). `action_values(obs)`: ① 경로의 액션별 균형 EV(상금풀 비율, 그 외 경로는 None) — 생성 파이프라인이 `action_values`로 기록.
  - `stats.py` — 클러스터 부트스트랩 백분위 CI(`bootstrap_ci`), 정규 SPRT(`sprt`, 무익성 중단 전용), `noninferiority`/`superiority`(CI 하한 판정), `required_tournaments`(검정력 0.9·α 0.05 블록 수).
  - `sufficiency.py` — 데이터 충분성 셀 판정(DATA_SUFFICIENCY.md S1·S4·S5): 토너먼트 클러스터 부트스트랩 반폭(rule-of-three 3/토너먼트 수가 하한)/ESS, 시드 다른 두 데이터셋 일치, 80% 부분집합 포화. `lessonable = S1∧S4∧S5` (`judge_cell`).
  - `evaluate.py` — `evaluate(config, candidate, baseline, blocks, seed, rotations)`: 블록마다 같은 게임 시드로 연속 블록 A/B 마스크의 `rotations`개 순환 이동과 각 보완 마스크(좌석 교환)를 플레이하는 duplicate 평가(이동마다 서로 다른 마스크, 짝수 인원은 `rotations` ≤ n/2), 블록 = 부트스트랩 클러스터. `EvalResult.to_json()`(schema 2)에 설정·시드 정책·참조기 버전·블록별 diff·블록별 게임 diff(`block_game_diffs`, 마스크 순서) 기록.
  - `gate_l.py` — Gate L(`python -m referee.gate_l`, `gates full`에 등록). L1(A 로그만 다른 B 첫 결정 확률 동일; 에이전트는 `action_probs(obs)`를 노출하거나 deepcopy로 `act`를 조회), L2(`uses_memory=True` 에이전트만, 아니면 skip), L3(HeroObservation 재귀 스캔 + 타 테이블 이벤트 부재), L4(생존자·상금 즉시 반영), L5(중도 합류 메모리·에이전트 상태), L6(학습기 생기면 활성화, 현재 skip). 검사 대상 에이전트는 `REGISTRY`에 등록. 지표 `gate_l_pass_rate`·`gate_l_checks`·`gate_l_items`(`metrics.py`, 항목별 [통과, 총계]).
  - `gate_r/` — Gate R 규칙 정확성 스위트(`python -m referee.gate_r [--full]`, `gates full`에 등록, 지표 `gate_r_pass_rate`). `evaluator.py`(독립 7장 평가기)·`settlement.py`(독립 사이드팟 정산: 앤티 데드 머니, 레이어 분할, 못 이기는 핸드 머크 후 같은 좌석 팟 병합, 홀수 칩은 버튼 왼쪽 첫 승자)·`checks.py`(공개 이벤트 스트림을 독립 규칙 모델로 재생해 항목별 `Tally`)·`suite.py`(프리셋 × fast 구조 변형 × 봇 × 시드). PokerKit·`stalker.tournament.hand`를 import하지 않는다(테스트로 강제).
- `harness/` — 하네스(L1/L2). 프로토콜, 루틴 지침, 스케줄, 훅, 실험 기록.

## 핵심 설계 결정 (상세는 `docs/decisions/`)
- 카드 = `int` 0..51 (`rank = c >> 2`, `suit = c & 3`), 콤보 인덱스 0..1325 고정.
- 칩은 정수, 난수는 주입된 `numpy.random.Generator`.
- 기록은 버전이 붙은 JSONL(`stalker/records/`, `schema_version`=1) — 1)의 출력이자 2)의 입력. 스키마는 기록 품질 게이트(D5)의 대상.
