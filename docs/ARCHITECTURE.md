# 아키텍처 (현재 상태를 반영해 유지할 것)

> **2026-10-27 방향 전환(ADR 0008)**: 아래 모듈 중 엔진·관측·기록·통계·ICM·Gate R/L은 유지·확장, `rl/`·`oracle/`은 동결, `typing/`·`pipeline/`·`service/`(구 퀴즈 프로토타입)·`referee/gate_a|gate_b|sufficiency`는 은퇴 예정이다(ADR 0008 표).
> 예정 모듈: `stalker/tp/`(TP 명세 로더·채점, 명세 `stalker/tp/spec/`는 보호 경로), `stalker/personas/`(난이도 1~19 페르소나), `web/`(학습 서비스 웹앱 — D1 데모부터).

## 계층
- `stalker/` — 제품(L0)
  - `core/` — 카드(`cards.py`), 7카드 평가기(`evaluator.py`); `tests/test_evaluator_exhaustive.py`가 5장 2,598,960개 전수(등급 7,462·족보별 개수)와 7장 무작위 대조(core·`gate_r/evaluator.py`·`anchors/hu_equity.evaluate_batch`, 비-slow 10⁴ / slow 10⁶)로 세 평가기를 검증, MC 에퀴티(`equity.py`), ICM(`icm.py`: Malmuth-Harville 정확해 `icm_equity`(생존자 ≤9) + Gumbel-max 몬테카를로 `icm_equity_mc`, 0 스택=탈락·하위 지급 제외), 프리플랍 레인지(`ranges.py`, `data/preflop_equity.json`: 169 클래스 × 랜덤 상대 1~5명 에퀴티, `python -m stalker.tools.build_tables`로 고정 시드 재생성)
  - `tools/` — 오프라인 도구(`build_tables.py`: 프리플랍 에퀴티 테이블, `bench_engine.py`: 엔진 처리량 벤치, `diff_engine.py`: `FastHand`↔PokerKit 차등 테스트, `bench_texassolver.py`: TexasSolver 스트리트×정확도 솔브 시간·메모리)
  - `tournament/` — 토너먼트 설정 스키마(`config.py`: `TournamentConfig`·페이아웃 생성기·`level_at`/`next_level`, JSON 직렬화, `schema_version`=1)와 `presets/*.json`(`python -m stalker.tools.build_presets`로 재생성). `hand.py`: PokerKit 0.7.7(버전 고정) 위의 NLHE 핸드 래퍼 `Hand` — 테이블 좌석 기준 스택(0=빈 좌석)·버튼·SB/BB·앤티(`none`/`classic`/`bb_ante`), 합법 액션 조회·적용, 종료 시 `HandResult`(좌석별 최종 스택·증감, 메인/사이드 팟과 적격 좌석, 팟 지급). 카드는 주입된 `Generator`로 섞은 자체 덱에서만 딜(재현성), `to_phh()`/`replay_phh_final_stacks()`로 PHH 왕복. 러너는 `director.py`(아래). `fast_hand.py`: `FastHand` — `Hand`와 같은 인터페이스의 순수 파이썬 고속 엔진(ADR 0005). PokerKit 규칙·덱 소비 순서를 복제해 같은 시드·액션이면 합법 액션 집합과 `HandResult`가 동일(`stalker.tools.diff_engine`으로 차등 검사), PHH 내보내기는 없음. 두 엔진 모두 진행 중 공개 상태 `stacks`·`bets`·`pot`을 같은 값으로 낸다(테스트로 강제)
  - `tournament/director.py` — `run_game(config, agents, rng, observer)`: 라운드마다 모든 테이블이 한 핸드씩(레벨 = 라운드 번호), 동시 탈락은 핸드 시작 스택이 큰 쪽이 상위 순위(동률은 주입 rng 추첨), 테이블 해체·밸런싱(차 ≤ 1, 이동자는 임의 빈 좌석), 페이아웃 → `GameResult`(순위·상금·핸드 수·불법 액션 수). `length_unit=minutes`: 전역 가상 시계가 라운드마다 `max(테이블 시작 인원) × seconds_per_seat`초 진행하고 다음 라운드 레벨 = 경과 분의 레벨(`Observation.level_index`·NEW_HAND `level_index`로 노출). `table_size=2`는 `players=2`일 때만 허용(홀수 잔여 인원이 1인 테이블을 만듦, `ConfigError`). `short_stack_rule`: `all_in`(기본, 못 내는 블라인드·앤티는 가진 만큼 올인) 또는 `skip`(핸드 시작 스택 < bb+앤티인 좌석은 딜은 받되 블라인드를 건너뛰고, SB·BB는 버튼 왼쪽부터 그만큼 가진 첫 두 좌석이 낸다. 데드 블라인드 없음, 3인 미만·해당 좌석 2개 미만이면 `all_in` 배치; 규칙 원문은 `referee/GATES.md` Gate R, 프리셋 `9max_sng_skip`). 실제 SB·BB 좌석은 NEW_HAND `blind_seats`로 기록되고 `Hand(blind_seats=...)`로 전달된다. 식별자 `game_id`/`tournament_id`/`hand_id`(게임 내 유일)/`player_id`(= agents 인덱스) 분리.
  - `cash/` — 캐시게임 세션(Gate R 캐시 규칙 v1). `session.py`: `CashConfig`(좌석 2~9·SB/BB·`buyin`·바이인 한도·핸드 수·`auto_topup`)와 `CashSession`/`run_cash_session(config, agents, rng, engine="fast"|"pokerkit")` — 에이전트 i = 좌석 i 고정, 버튼은 매 핸드 한 칸, 스택 0이면 다음 핸드 전 `buyin` 리바이, `auto_topup`이면 `buyin`까지 탑업, 레이크 0. 결과 `CashResult`: 세션 스트림(SEAT/HAND/HAND_END/REBUY/TOPUP, `referee/gate_r/cash.py` 형식)·좌석별 순손익 `net`(합 0)·`bb_per_100()`. 에이전트는 토너먼트와 같은 `Observation`/`Event` 계약을 받는다. `presets.py`: `cash_{hu,6max,9max}_{40,100,200}bb`(블라인드 1/2, 1,000핸드)
  - `e3/` — E3 학습 환경(#192·#194): `game.py` N인(2~9, 기본 6) 100BB 한 핸드 NLHE 추상 게임, E2와 같은 액션 라벨(f/c/k/r/b33/b75/a), 좌석은 프리플랍 순서(UTG…BTN·SB·BB), 같은 시작 스택이라 사이드팟 없음(테스트로 고정), 불변 상태 + `apply`·`payoff`(좌석별 순손익).
  - `agents/` — `base.py`: `Agent`(`act`/`observe`/`on_game_start`/`on_game_end`), 플레이어별 `Observation`(자신의 홀카드와 공개 정보만), 공개 `Event`(`START_GAME`/`NEW_HAND`/`ACTION`/`SHOWDOWN`/`HAND_END`/`END_GAME`; 홀카드는 SHOWDOWN에서만 공개). 불법 액션은 체크/폴드로 대체하고 `illegal_actions`로 집계. `random_agent.py`: Gate R용 무작위 합법 봇. `check_fold.py`: 결정적 체크/폴드 기준선 `CheckFoldAgent`(공짜면 체크, 베팅에는 폴드). `persona.py`: 파라미터 규칙 봇 `PersonaAgent(PersonaParams(vpip, pfr, aggression, fold_to_bet), rng)`와 9종 프리셋(`PRESETS`, 계획서 §3.5 표 값, `loose_passive_b`만 표에 값 없음). 프리플랍은 핸드 상위 비율(`hand_top_pct`)을 pfr/vpip와 비교(BB 무료 체크 보정 `BB_CHECK_COMP`), 포스트플랍은 메이드핸드 강도×aggression/fold_to_bet. 자기 `Observation`과 주입 rng만 사용. `persona_stats.py`: `measure_session(agents, hands, seed)`가 캐시 세션을 돌려 좌석별 실측 VPIP·PFR·공격성(정의는 docstring)을 낸다. 충실도 테스트 `tests/test_persona.py`(2만 핸드 ±5%p, slow 10만 핸드 ±3%p; 공격성은 보고용·느슨한 한계).
  - `rl/env.py` — `TournamentEnv(config)`: 디렉터를 워커 스레드에서 돌리고 `reset(rng)`/`step(action_index)`로 좌석별 결정을 넘기는 다중 에이전트 env. 관측은 `ObservationBuilder`(좌석별 `GameMemoryStore`)만 사용. 액션 = 폴드·콜·팟 비율 레이즈들·올인(마스크 제공, 마스크된 액션은 `ValueError`). 보상 = 상금 − `buy_in`(상금 단위), 게임 종료 시 한 번. step 결과의 `events`에 `game_start`/`game_end` 경계. `reset(..., seat_agents={pid: Agent})`로 지정한 좌석은 게임 안에서 그 Agent가 두고 `step()`에 나오지 않는다.
  - `rl/features.py` — `encode(HeroObservation)` → 좌석 토큰(9, 패딩 마스크)·카드·전역 특징(numpy, torch 불필요). `validate_observation`이 `docs/OBSERVATION.md` 계약 밖 필드를 거부.
  - `rl/policy.py` — `Policy(PolicyConfig(variant), seed)`(가중치 초기화는 seed로만 결정, 전역 RNG 불변) (optional extra `[rl]`, torch CPU). 좌석 트랜스포머 인코더 + 액터(합법 액션 마스크, 불법 확률 정확히 0) + 크리틱. `ai0`=메모리 없음, `ai1`=상대 통계, `ai2`=통계+GRU(`act`가 상태 유지, 게임 경계에서 `reset_memory()`).
  - `rl/train.py` — Recurrent PPO 셀프플레이(`Trainer(config, TrainConfig(seed))`, `[rl]` 필요). 상대 풀(게임마다 새로 뽑음, 학습 데이터 없음): `TrainConfig.random_seats`개 좌석은 스크립트 무작위 봇(`random_action`, `RandomLegalAgent` 규칙), `reference_seats`개는 Gate B 참조 봇 v1(`ReferenceBot`), `past_checkpoints`=N이면 N 반복마다 가중치 스냅샷을 최근 `past_pool_size`개 유지하고 나머지 좌석(학습 좌석 1개 제외)마다 확률 `past_checkpoint_p`로 과거 스냅샷 `PolicyAgent`가 둔다. 풀이 꺼져 있으면 rng 추출이 기존과 같다. 실험 `scripts/rl_opponent_pool.py`, 기록 `docs/research/2026-10-rl-opponent-pool.md`. trajectory 단위 = `Segment`(한 게임 × 한 플레이어). GRU 상태는 행동할 때와 업데이트 재생(`_replay`) 모두 세그먼트 첫 스텝에서 0 → game_id 간 상태 전달 없음(Gate L6, `check_segments`가 배치마다 검사). 보상 = (상금 − buy_in)/buy_in, GAE. 행동 샘플링·미니배치 순서는 시드 `Generator` 하나로, torch 전역 RNG 미사용 → 같은 시드면 같은 가중치. `save()`는 체크포인트에 `policy_version`(`<variant>-i<반복>-<가중치 sha8>`)을 기록, `load_policy()`. `PolicyAgent`: 학습된 정책을 디렉터 `Agent`로 실행(게임별 메모리, `on_game_start`에서 GRU 초기화, `action_probs`는 순수) — 평가와 Gate L1용.
  - `rl/evaluate.py` — `evaluate(policy, config, games, seed, opponent='random'|'reference')` → `EvalResult`: 정책 1석(게임마다 좌석 회전)의 ROI·표준오차, 같은 딜·시드에서 `CheckFoldAgent`의 기준선 ROI, 정책 액션 분포(`fold`/`check_call`/`raise`/`allin` 비율)와 `fold_rate`(폴드가 합법인 = 베팅을 마주한 결정 중 폴드 비율). 무작위 봇 대비 ROI만으로는 판별력이 없어서(체크/폴드가 +0.75, #78) slow 스모크는 `fold_rate < 0.95`로 체크/폴드 붕괴를 잡는다(현재 스모크 학습은 붕괴하므로 strict xfail, #91에서 해제). 전체 결정 기준 폴드 비율로는 안 된다: 순수 체크/폴드도 공짜 체크 때문에 무작위 봇 상대 약 0.7이다.
  - `rl/candidate.py` — Gate B 후보 `--candidate stalker.rl.candidate:policy`: `STALKER_RL_CHECKPOINT`(또는 `checkpoint` 인자)의 체크포인트를 `load_checkpoint()`로 읽어 학습 때 레이즈 비율로 `rng -> PolicyAgent`를 돌려준다. 팩토리의 `policy_version` 속성이 판정 대상 가중치를 가리킨다.
  - `observe/` — 관측 계약(`docs/OBSERVATION.md`): `builder.py`(`ObservationBuilder` → 9좌석 고정 `HeroObservation`, 스택 분포 분위수 요약), `memory.py`(`GameMemoryStore`: game_id 경계, 상대별 컨텍스트 통계·최근 K 액션·공개 쇼다운). director의 `Observation.all_stacks`(라운드 시작 전 생존자 스택, 비면 오류)·`hand_start_stack`(히어로의 핸드 시작 스택, `hero_rank` 산출용)와 ACTION 이벤트의 `street`/`facing_bet`가 입력.
  - `records/` — 기록 스키마 v1(`schema.py`, 상세 `docs/RECORDS.md`): `DecisionRecord`(식별자 7종 분리, 토너먼트 맥락, 본인 관측, 기억 요약, `probs_ai0`/`probs_ai1`, 선택 액션·logprob), `HandRecord`, `GameRecord`(보상 = 상금 − 참가비). 타입 검사 `from_dict`와 규칙 검증 `validate`(확률합·합법 액션·타인 홀카드 부재). `store.py`: 런 디렉터리 = `manifest.json`(설정·시드·git sha·policy_version) + `records.jsonl`, 쓰기·읽기 모두 검증.
  - `typing/` — 유형화 v0(`docs/TYPING.md`): `spots.py`(`spot_key(DecisionRecord)` → 단계·유효 스택 BB·포지션·스트리트·팟 유형·상대 프로파일, 못 만들면 None), `report.py`(셀별 결정 수·행동 빈도, 게임 짝/홀 두 쪽에 `referee.sufficiency.judge_cell`을 적용한 S1·S4·S5·`lessonable` → JSON+Markdown). 게임 수별 충분성 곡선·D1 필요량 외삽: `scripts/sufficiency_curve.py`, 기록 `docs/research/2026-10-sufficiency-curve.md`
  - `pipeline/generate.py` — `python -m stalker.pipeline.generate --preset sng9 --n N --seed S --out DIR`: 참조 봇 토너먼트를 `RecordingBot`(결정마다 `DecisionRecord`, 기억 요약에 상대 VPIP)으로 돌려 검증된 기록·매니페스트·리포트를 쓴다. `HandRecord`는 미생성
  - `oracle/` — `texassolver.py`: TexasSolver 콘솔(고정 커밋, `scripts/install_texassolver.sh`로 설치, AGPL 개인 사용) 래퍼. 헤즈업 포스트플랍 `Spot` → 명령 파일 → 실행 → 덤프의 노드별 `(hi, lo)` 콤보 확률(`RootStrategy`), exploitability·시간·피크 RSS. 바이너리 없으면 `TexasSolverError`. 연구 기록 `docs/research/2026-10-24-texassolver-spike.md`
  - `service/build.py` — `python -m stalker.service.build RUN_DIR --out service/web/data`: 유형화 리포트(`report.json`, 스키마 검사, v1·v2는 `upgrade_report`로 올림)와 퀴즈 스팟(`quiz.json`: `lessonable` 셀에서만, 공개 정보·내 카드·합법 액션·AI 혼합전략)을 만든다. 웹앱은 리포 루트 `service/web/`(정적 HTML/CSS/JS, `service/web/README.md`).
  - (예정, ADR 0002) `oracle/` 프리플랍 ICM 솔버·전략 라이브러리, `adapt/` 상대 모델·적응 계층, `agents/` 벤치마크 봇(기본 인터페이스는 구현됨)
  - `env/` — 정보 계약(`docs/TP.md` §2). `contract.py`: `PublicObservation`(= `HeroObservation`), `TeacherContext`(가정한 상대 정책·시뮬레이터 설정), `PrivateWorldState`(타인 홀카드·덱·RNG, 엔진 전용), `DecisionContext` v0.1 + `decision_context(po)`(BB 단위 사실; 공개 이력에 스트리트 표지가 없어 포스트플랍에서는 `street_aggressor`·`preflop_aggressor` 둘 다 None). `teacher.py`: `opp_range_label(po, teacher, slot)` — 균등 사전 × 가정 정책의 공개 라인 확률(1326 콤보).
