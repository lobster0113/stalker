# 아키텍처 (현재 상태를 반영해 유지할 것)

> **2026-10-27 방향 전환(ADR 0008)**: 아래 모듈 중 엔진·관측·기록·통계·ICM·Gate R/L은 유지·확장, `rl/`·`oracle/`은 동결, `typing/`·`pipeline/`·`service/`(구 퀴즈 프로토타입)·`referee/gate_a|gate_b|sufficiency`는 은퇴 예정이다(ADR 0008 표).
> 예정 모듈: `stalker/tp/`(TP 명세 로더·채점, 명세 `stalker/tp/spec/`는 보호 경로), `web/`(학습 서비스 웹앱 — D1 데모부터).

## 계층

  - `tournament/` — 토너먼트 설정 스키마(`config.py`: `TournamentConfig`·페이아웃 생성기·`level_at`/`next_level`, JSON 직렬화, `schema_version`=1)와 `presets/*.json`(`python -m stalker.tools.build_presets`로 재생성). `hand.py`: PokerKit 0.7.7(버전 고정) 위의 NLHE 핸드 래퍼 `Hand` — 테이블 좌석 기준 스택(0=빈 좌석)·버튼·SB/BB·앤티(`none`/`classic`/`bb_ante`), 합법 액션 조회·적용, 종료 시 `HandResult`(좌석별 최종 스택·증감, 메인/사이드 팟과 적격 좌석, 팟 지급). 카드는 주입된 `Generator`로 섞은 자체 덱에서만 딜(재현성), `to_phh()`/`replay_phh_final_stacks()`로 PHH 왕복. 러너는 `director.py`(아래). `fast_hand.py`: `FastHand` — `Hand`와 같은 인터페이스의 순수 파이썬 고속 엔진(ADR 0005). PokerKit 규칙·덱 소비 순서를 복제해 같은 시드·액션이면 합법 액션 집합과 `HandResult`가 동일(`stalker.tools.diff_engine`으로 차등 검사), PHH 내보내기는 없음. 두 엔진 모두 진행 중 공개 상태 `stacks`·`bets`·`pot`을 같은 값으로 낸다(테스트로 강제)
  - `tournament/director.py` — `run_game(config, agents, rng, observer)`: 라운드마다 모든 테이블이 한 핸드씩(레벨 = 라운드 번호), 동시 탈락은 핸드 시작 스택이 큰 쪽이 상위 순위(동률은 주입 rng 추첨), 테이블 해체·밸런싱(차 ≤ 1, 이동자는 임의 빈 좌석), 페이아웃 → `GameResult`(순위·상금·핸드 수·불법 액션 수). `length_unit=minutes`: 전역 가상 시계가 라운드마다 `max(테이블 시작 인원) × seconds_per_seat`초 진행하고 다음 라운드 레벨 = 경과 분의 레벨(`Observation.level_index`·NEW_HAND `level_index`로 노출). `table_size=2`는 `players=2`일 때만 허용(홀수 잔여 인원이 1인 테이블을 만듦, `ConfigError`). `short_stack_rule`: `all_in`(기본, 못 내는 블라인드·앤티는 가진 만큼 올인) 또는 `skip`(핸드 시작 스택 < bb+앤티인 좌석은 딜은 받되 블라인드를 건너뛰고, SB·BB는 버튼 왼쪽부터 그만큼 가진 첫 두 좌석이 낸다. 데드 블라인드 없음, 3인 미만·해당 좌석 2개 미만이면 `all_in` 배치; 규칙 원문은 `referee/GATES.md` Gate R, 프리셋 `9max_sng_skip`). 실제 SB·BB 좌석은 NEW_HAND `blind_seats`로 기록되고 `Hand(blind_seats=...)`로 전달된다. 식별자 `game_id`/`tournament_id`/`hand_id`(게임 내 유일)/`player_id`(= agents 인덱스) 분리.
    - **중간 시작** (`tournament/start_state.py`): `StartState`(생존 player_id→스택, 이미 탈락한 수 `eliminated`, `level_index`, 첫 테이블의 첫 핸드 직전 `button` 좌석 — 디렉터가 핸드마다 버튼을 한 칸 옮기므로 첫 핸드 버튼은 그 다음 점유 좌석)를 `run_game(..., start_state=)`에 넘기면 생존자만 앉아 그 상태에서 끝까지 돈다. `make_start_state(config, rng, remaining, stack_profile∈{even,random,skewed}, level_index)`는 주입된 rng로 생존자·스택(합 = `starting_stack × players`, 모두 ≥ 1)·버튼을 뽑는다(같은 시드 → 같은 상태). 레벨 시계는 그 레벨의 시작 시점에서 출발(hands: `hand_no`가 이어짐, minutes: 가상 시계 초기화). 탈락자는 자리에 앉지 않고 순위 `remaining+1..players`를 player_id 오름차순으로 받으며 상금도 그 순위로 계산. `check_game(..., start_state=)`가 같은 검사를 적용하고 Gate R 스위트가 중간 시작 게임을 포함한다. 기록 스키마에는 싣지 않는다(시작 상태는 생성 입력이지 기록 필드가 아님).
    - **단계 판정** `tournament_stage(remaining, paid_places, table_size, players)` — 위에서부터 첫 해당: `in_the_money` = 남은 ≤ 지급 자리; `bubble_near` = 남은 ≤ 지급 + max(1, ⌈지급/2⌉); `final_table` = 처음에 테이블이 둘 이상이었고(players > table_size) 남은 ≤ table_size — 단일 테이블 SNG는 파이널 테이블이 따로 없어 `early`·`middle`이 남는다; `early` = 필드의 75% 이상 남음; 그 외 `middle`. 예: 9인 3자리 지급 SNG에서 9~7인 = early, 6인 = middle, 5·4인 = 버블 근처, 3인 = 머니인.
  - `cash/` — 캐시게임 세션(Gate R 캐시 규칙 v1). `session.py`: `CashConfig`(좌석 2~9·SB/BB·`buyin`·바이인 한도·핸드 수·`auto_topup`)와 `CashSession`/`run_cash_session(config, agents, rng, engine="fast"|"pokerkit")` — 에이전트 i = 좌석 i 고정, 버튼은 매 핸드 한 칸, 스택 0이면 다음 핸드 전 `buyin` 리바이, `auto_topup`이면 `buyin`까지 탑업, 레이크 0. 결과 `CashResult`: 세션 스트림(SEAT/HAND/HAND_END/REBUY/TOPUP, `referee/gate_r/cash.py` 형식)·좌석별 순손익 `net`(합 0)·`bb_per_100()`. 에이전트는 토너먼트와 같은 `Observation`/`Event` 계약을 받는다. `presets.py`: `cash_{hu,6max,9max}_{40,100,200}bb`(블라인드 1/2, 1,000핸드)
  - `e3/` — E3 학습 환경(#192·#194): `game.py` N인(2~9, 기본 6) 100BB 한 핸드 NLHE 추상 게임, E2와 같은 액션 라벨(f/c/k/r/b33/b75/a), 좌석은 프리플랍 순서(UTG…BTN·SB·BB), 같은 시작 스택이라 사이드팟 없음(테스트로 고정), 불변 상태 + `apply`·`payoff`(좌석별 순손익). 규칙은 상태 필드 `menu`·`raise_cap`(#339): 기본 `v1`·상한 3. `tp6`는 #339 때의 TP.md §6 사이즈 버킷(프리플랍 오픈 r22/r/r3, 림퍼 아이솔 `r`=2.5BB+림퍼당 1BB, 벳에 대한 레이즈 r25/r/r4, 포스트플랍 b33/b50/b75/b100/b150), `raise_cap=None`은 상한 없음 + 스택 80% 이상 레이즈는 올인으로 합침. `G.rules(menu, raise_cap)`이 `deal`의 기본을 바꿔 심판 평가기(LBR·필드·Gate R E3 재생)가 수정 없이 같은 규칙으로 돈다(테스트 `tests/test_e3_menu.py`). 잡 `e3-tp-mid-tp6-w4`·`e3-tp-mid-tp6nc-w4`. `real`(#382)은 지금의 TP.md §6 실전 사이즈(오픈 2~10BB 10개, 림퍼 아이솔은 각 오픈+림퍼당 1BB, 3벳 2.5~5x·4벳 2~3x는 `REAL_PREFLOP_RAISE` 한 표, 5벳은 올인만, 포스트플랍 벳 b20~b300 8개, 레이즈 2.5~10x 6개). 프리플랍은 메뉴가 상한 3을 고정하고(`street_cap`), `raise_cap`은 포스트플랍에만 걸린다. 잡 `e3-tp-mid-real-w4`. `translate.py`(#382)는 메뉴 밖 칩 금액을 이웃한 두 메뉴 사이즈로 의사 조화 매핑한다(`split` 결정적 확률 분할 = 채점, `sample` 시드 Generator 추출 = AI의 해석).
  - `e3/tp_key.py`·`e3/mccfr.py` — TP 키 정책 테이블(#196): 정보 집합 = 좌석·스트리트·상대 수·레이즈·이니셔티브·팟 오즈·SPR·합법 액션·`hand.equity` 단계(남은 상대 전원 대비, 상대별 에퀴티 곱). 초보는 포지션 그룹 깊이, 콜/폴드 전용은 짧은 키. 고수(#325, `depth="pro"`, 17단계)는 full 키에 `opp.foldy`(한 핸드·자기 대국에서는 항상 N/A `fN`, 2층 상대 모델용 자리)와 헤즈업 포스트플랍 `board.nut`을 더한다(테이블은 `board.nut`을 5단계 `NUT_K`로 나눈다, #332 — 채점 눈금은 그대로). `board.nut`은 공개 레인지가 필요해 에퀴티 단계에 실어 보내고(`eq + 1000·(nut+1)`), `key`가 `e<eq>|n<nut>`로 적는다. 그래서 보호된 심판 평가기(LBR·필드)는 그대로 고수 키를 읽는다. 잡 `e3-tp-pro-w4`. 공개 레인지를 추적하는 외부 표본 MCCFR(`python -m stalker.e3.mccfr`). 레인지를 움직이는 전략은 옵션 `ranges`(#405): 기본 `current`(이번 반복의 regret matching, #405 이전 모든 런)와 `average`(평균 전략 스냅샷, `range_every`=2000반복마다 갱신, 스냅샷에 없는 키는 현재 전략; 체크포인트 version 2에 스냅샷 포함). 잡 `e3-tp-mid-avgrange-w4`, 파드 `pod_train --ranges average`.
  - `e3/parallel.py` — 배치 동기 병렬 MCCFR(#318). 워커마다 regret 스냅샷 사본으로 반복을 돌리고, 부모가 변화량을 워커 순서대로 더한다. 결과는 (상태, 워커 수, 배치)로만 정해지고 체크포인트(#301)와 호환된다. 워커 1은 순차 `iterate`와 같다. 평균 레인지 모드에서는 부모가 동기화 시점에만 스냅샷을 갱신하고(간격은 `range_every`를 동기화 단위로 올림) 모든 워커가 같은 스냅샷을 읽는다(#405). 잡은 `e3-tp-{beginner,mid}-w4`(러너 4 vCPU)와 9인 `e3-tp-{beginner,mid}9-w4`(#324, 필드 평가 없음).

## 핵심 설계 결정 (상세는 `docs/decisions/`)
- 카드 = `int` 0..51 (`rank = c >> 2`, `suit = c & 3`), 콤보 인덱스 0..1325 고정.
- 칩은 정수, 난수는 주입된 `numpy.random.Generator`.
- 기록은 버전이 붙은 JSONL(`stalker/records/`, `schema_version`=1) — 1)의 출력이자 2)의 입력. 스키마는 기록 품질 게이트(D5)의 대상.
