# 성공 게이트와 성공 레벨 (보호 문서 — `referee-change` 절차로만 수정)

출처: `docs/CHARTER.md`(2026-10-27 방향 전환, ADR 0008), `docs/TP.md`, 설계 리뷰 반영(ADR 0010).
원칙: 게이트 판정은 CI/평가 배치가 산출한다. 평가 설정(환경·상대군·시드 정책·TP 버전·정책 버전)은 판정 전에 고정·기록한다. **수치 기준은 판별력(좋은 후보와 나쁜 후보를 가르는가)을 먼저 측정한 뒤 확정**한다(ADR 0007의 교훈).

## Gate R — 시뮬레이터 규칙 정확성 (상시 CI, 모든 게이트의 전제)
- 칩 보존, 올인·사이드팟 정산의 독립 구현 일치, 포지션·베팅 순서·최소 레이즈, 블라인드·앤티(일반/BB 앤티)와 숏스택 징수, 탈락·순위·상금 배분. 통과율 100%.
- 스위트: `referee/gate_r/` — `python -m referee.gate_r [--full] [--seeds N]`. `gates full`이 `--full`로 실행하고 `metrics.py`가 `gate_r_pass_rate`·`gate_r_checks`(토너먼트)와 `gate_r_cash_pass_rate`·`gate_r_cash_checks`(캐시)를 기록한다.
- 엣지 케이스(SIM-d): `python -m referee.gate_r.edge [--cases N]`(`gates full`의 `gate_r_edge`, 로컬 약 25초). 무작위 플레이로는 드문 상황 8종 — 숏 올인 연쇄, 3개 이상 사이드팟+동점 분할+홀수 칩, 앤티로만 올인, 블라인드 숏, 보드 플레이 분할, 휠·키커, 헤즈업 전환 직후, 동시 다중 탈락 — 을 고정 시드로 일부러 만들고, 분류기가 그 상황이 실제로 일어났다고 확인한 케이스만 센다(종마다 ≥ 50, 못 채우면 실패). 핸드 6종은 덱을 고정해 PokerKit `Hand`·`FastHand`를 같은 액션으로 진행(항목 `engines`: 매 단계 액터·합법 액션, 끝의 카드·`HandResult` 일치)하고 같은 이벤트를 독립 모델로 재생한다. 게임 2종은 `run_game` + 위 검사 전체. 경계 항목별 손계산 골든 케이스는 `tests/test_gate_r_edge.py`(기대값과 계산 근거 주석).
- PHH 재생(SIM-f, #148): `python -m referee.gate_r.phh check`(pytest `tests/test_phh_replay.py`, 약 4초, 네트워크 불필요). 공개 PHH 기록(Pluribus 6인 NLHE 2,000핸드, MIT, 출처·커밋·배제 코드는 `tests/data/phh/README.md`)의 홀카드·보드를 덱으로 주입하고 기록된 액션을 `Hand`·`FastHand`에 그대로 적용해 최종 스택이 `finishing_stacks`와 칩 단위로 같은지 본다. 규칙이 다른 핸드는 배제 사유 코드와 함께 집계하고(샘플에서는 홀수 칩을 반으로 나눈 1건), 배제가 아닌 불일치는 0이어야 한다.
- E3 엔진(#203): `python -m referee.gate_r.e3_suite [--hands N]`(`gates full`의 `gate_r_e3`, 로컬 약 10초). 6인·9인 무작위 핸드 각 1,000개를 같은 홀카드·보드로 PokerKit에서 재생한다. 항목: `e3_actor`(매 액션 뒤 다음 액터·스트리트), `e3_stacks`(모든 좌석 스택), `e3_result`(좌석별 순결과: 폴드 승리·콜되지 않은 칩·분할·홀수 칩), `e3_chips`(결과 합 0, 기여 ≤ 스택, 팟 = 기여 합). 지표 `gate_r_e3_pass_rate`·`gate_r_e3_checks`. 손계산 골든 케이스는 `tests/test_e3_golden.py`. 홀수 칩은 토너먼트 정산과 같은 TDA 규칙(전부 포스트플랍 순서 첫 승자)이다.
- 방법: 모든 프리셋 × 구조 변형 × {무작위 합법 봇, 콜링 스테이션} × 고정 시드로 게임을 돌리고, 공개 이벤트 스트림을 **PokerKit·`stalker.tournament.hand`를 쓰지 않는** 독립 규칙 모델(`checks.py`, `evaluator.py`, `settlement.py`)로 재생해 칩 단위로 대조한다.
- 검사 항목: `antes_blinds`, `action_order`, `bet_sizing`, `street_flow`, `settlement`, `chip_conservation`, `button`, `stack_continuity`, `elimination`, `prizes`.
- 규칙 명세(교과서에 없는 부분은 ADR 0005의 엔진 규칙과 같게 고정):
  - 앤티 → 블라인드 순으로 징수, 각자 남은 칩까지만. 앤티는 최하위 팟의 데드 머니다.
  - 헤즈업은 버튼이 SB를 내고 프리플랍 먼저 행동. 프리플랍은 BB 왼쪽, 이후 스트리트는 버튼 왼쪽부터.
  - 최소 레이즈 증분 = max(1BB, 이번 스트리트 최대 증분). 그 미만은 올인일 때만. 숏 올인 뒤 이미 행동한 좌석은 연속 숏 올인 합이 풀 레이즈에 이를 때까지 콜/폴드만.
  - **숏스택 징수 규칙(`short_stack_rule`, SIM-i2)**. `all_in`(기본): 위와 같이 블라인드·앤티를 가진 만큼 내고 올인. `skip`: ① 판정은 핸드 시작 시점, 앤티를 내기 전 스택으로 한다 — 스택 < bb + 앤티(그 레벨에 앤티가 없으면 0)인 좌석은 그 핸드의 블라인드를 건너뛴다(딜은 받고, `classic` 앤티는 가진 만큼 낸다). ② SB·BB는 버튼 왼쪽부터 시계 방향(버튼이 마지막)으로 그 기준을 넘는 첫 두 좌석이 낸다. 건너뛴 좌석의 블라인드는 데드 블라인드로 남지 않고, 나중에 보충 징수하지도 않는다. `bb_ante`의 앤티는 실제 BB 좌석이 낸다. 프리플랍은 실제 BB 왼쪽부터. ③ 버튼은 그대로 다음 점유 좌석으로 한 칸(숏스택 좌석도 버튼을 받는다). ④ 헤즈업이거나 기준을 넘는 좌석이 2개 미만이면 `all_in` 배치를 쓴다. 디렉터는 NEW_HAND `blind_seats`(SB, BB)로 실제 배치를 기록하고 `antes_blinds` 검사가 시작 스택에서 이 규칙으로 독립 재계산해 대조한다(`all_in`도 같은 검사). 근거: TDA 토너먼트 규칙의 기본은 숏스택도 가진 만큼 블라인드를 내는 것(= `all_in`)이고, `skip`은 TDA에 없는 시뮬레이터 선택지로 캐시게임의 이동 버튼 관행(Robert's Rules of Poker "Button and Blind Use": 블라인드를 못 내는 자리는 건너뛰고 다음 자리가 낸다)을 차용했다 — 원문 대조는 이 작업 환경에서 하지 못했다. 프리셋 `9max_sng_skip`(classic 앤티)이 Gate R 스위트에서 매 CI 돈다.
  - 미콜 칩 반환. 쇼다운에서 어떤 팟도 이길 수 없는 핸드를 먼저 버리고 인접 팟을 합친다. 동점 분할의 홀수 칩은 버튼 왼쪽 첫 승자에게.
- **캐시게임 확장(D2)**: 고정 블라인드·탈락 없음·리바이/탑업 규칙·좌석 이탈을 명세에 추가하고 같은 독립 모델로 대조한다. 레이크는 v1 범위 밖(명세에 명시). 규칙 v1과 검사 5종(`referee/gate_r/cash.py`, 엔진 `CashSession`은 SIM-b에서 이 명세에 맞춘다):

  | 규칙 | v1 값 |
  |---|---|
  | 블라인드 | 세션 내 고정 SB/BB, 스트래들 없음 |
  | 레이크 | 0 (도입 시 명세·검사 개정) |
  | 인원 | 세션 동안 고정 좌석 수. 중간 합류·이탈 없음(v1) — 버튼은 모든 좌석을 순서대로 돈다 |
  | 최초 바이인 | `min_buyin` ≤ 금액 ≤ `max_buyin` |
  | 리바이 | 핸드 사이에, 스택이 0인 좌석만, 바이인 한도 안. 스택 0인 좌석은 다음 핸드 전에 반드시 리바이(빈 스택으로 핸드 시작 금지) |
  | 탑업 | 핸드 사이에, 스택이 0보다 크고 `스택+금액 ≤ max_buyin` |
  | 세션 길이 | 정확히 `hands` 핸드 |

  | 검사 | 불변식 |
  |---|---|
  | `cash_rebuy` | 위 최초 바이인·리바이 규칙(핸드 시작 시 빈 스택 금지 포함) |
  | `cash_topup` | 위 탑업 규칙(핸드 도중 금지 포함) |
  | `button` | 핸드마다 버튼이 다음 좌석으로 한 칸 이동 |
  | `chip_conservation` | 핸드 전후 테이블 전체 칩 동일, 음수 스택 없음, 핸드 시작 스택 = 추적 스택, 좌석별 순손익(최종 스택 − 총 바이인) 합 = −레이크 |
  | `session_length` | 핸드 수 = 설정값, 핸드가 열린 채 끝나지 않음, 좌석 수 = 설정값이고 첫 핸드 뒤 좌석 추가 없음 |
- **캐시 3자 일치(SIM-b2·SIM-c)**: `referee/gate_r/cash_suite.py`가 캐시 프리셋 9개 × 세션(무작위 합법 봇·콜링 스테이션 × 탑업 있음/없음, 고정 시드)을 `FastHand`와 PokerKit `Hand`로 같은 시드에 각각 돌린다.
  - `engine_agreement`: 두 엔진의 세션 스트림(SEAT/HAND/HAND_END/REBUY/TOPUP)·핸드 이벤트·최종 스택·리바이·탑업이 같다. 핸드를 끝내는 액션의 `pot` 하나만 비교에서 뺀다(PokerKit은 지급 뒤 0, FastHand는 지급 전 값을 보고하는 표시값이며, 뒤따르는 스택·델타는 전부 비교한다).
  - 두 엔진 스트림 각각을 독립 모델로 재생한다: 세션 검사 5종(위 표)과 핸드 검사(`antes_blinds`: SB/BB 고정·앤티 0, `action_order`·`bet_sizing`·`street_flow`·`settlement`는 토너먼트와 같은 모델). 그래서 두 엔진이 같은 오답에 합의해도 모델이 잡는다.
  - 규모: `python -m referee.gate_r`(지표용 기본) 프리셋당 2세션×100핸드, `--full` 프리셋당 12세션×1000핸드 = 합계 108,000핸드(엔진당). quick 게이트(pytest)는 프리셋당 2세션×50핸드. 통과율 100%.
- 규칙 명세를 바꾸는 것은 referee-change다. 엔진이 명세와 다르면 엔진을 고친다(검사를 xfail로 돌리지 않는다).
- **통과가 보증하는 것과 아닌 것**: Gate R 100%는 "지정한 검사 집합에서 세 구현(PokerKit·FastHand·독립 모델)이 일치"를 뜻한다. 모든 가능한 상태의 무오류를 보증하지 않는다(세 구현이 같은 해석 결함을 공유할 수 있다). 그래서 경계 항목(`button`, 숏 올인 재오픈, 미콜 반환, 동점 분할·홀수 칩, 동시 탈락, 탑업)마다 손으로 검증한 골든 케이스를 두고, 공개 핸드 기록(PHH) 재생은 규칙 환경이 맞는 게임만 쓰며 배제 사유를 기록한다.
- **중간 시작(`start_state`, SIM-i3)**: 생존자만 앉고 시작 스택은 `start_state.stacks`(합 = `starting_stack × players`, 모두 ≥ 1)다. 이미 탈락한 선수는 순위 `remaining+1..players`를 player_id 오름차순으로 받는다(상금도 그 순위). 레벨 시계는 `level_index` 레벨의 시작 시점에서 출발한다(hands: 앞 레벨 길이 합만큼 핸드가 이미 지남, minutes: 그만큼의 분이 이미 지남). 첫 핸드의 버튼은 `button` 좌석 다음의 첫 점유 좌석이다. `check_game(start_state=)`가 칩 보존·순위·시계를 이 규칙으로 재계산하고, 스위트의 `MID_START`(`9max_sng_flat` 4인, `6max_sng_topheavy` 3인, `mtt54` 20인; random/skewed 스택, 레벨 시드별 순환)가 매 CI에서 돈다. 스택 +1 변이는 검사가 잡는다(테스트로 고정).
- **토너먼트 시계(`length_unit="minutes"`, SIM-i1)**: 디렉터의 한 라운드(모든 테이블이 한 핸드씩)가 끝나면 시계가 `max(그 라운드 각 테이블의 핸드 시작 인원) × seconds_per_seat`초 진행하고, 다음 라운드의 레벨은 경과 분(경과 초 // 60)에 해당하는 레벨이다(마지막 레벨은 반복). `antes_blinds` 검사는 기록된 NEW_HAND의 시작 인원에서 이 규칙으로 레벨을 독립 재계산해 대조한다. Gate R 스위트의 `<프리셋>/minutes` 변형(레벨 1분)이 이를 매 CI에서 돌린다.
- **토너먼트 시계(확장 시, 위 규칙의 일반화 방향)**: 레벨 길이가 시간 단위면 대회 전역 가상 시계를 쓴다. 테이블별 핸드 완료 이벤트가 시계를 진행시키고, 블라인드 상승은 "상승 시각 이후 시작하는 핸드"부터 적용, 테이블 병합·이동은 핸드 사이에만. 가상 시간은 실제 대회의 근사임을 결과에 표시한다.

## Gate L — 정보 경계 (상시 CI)
| ID | 테스트 | 통과 조건 |
|---|---|---|
| L1 | B 게임 첫 결정에 동일한 카드·보드·스택·블라인드·현재 핸드 액션을 주고 **A 게임 로그만 바꿈** | B 첫 행동 확률(그리고 TP 값) 완전 동일 |
| L2 | A 게임 핸드 50에서 1~49 핸드 공개 로그 일부 변경 | 기억을 쓰는 정책에서 변화 관측(기억이 실제로 쓰임) |
| L3 | 관측 구조체 검사 | 타인 홀카드·덱 순서·난수 시드·타 테이블 개별 로그 부재 |
| L4 | 생존자 수·상금 구조 변경 | 다음 관측에 즉시 반영 |
| L5 | 게임 중 합류 | 합류 이후 관측만 메모리에 존재 |
| L6 | 학습 배치 | game_id 경계에서 상태 초기화, 게임 간 상태 전달 없음 |
| L7 | 숨은 카드 교체 (ADR 0010). `check_l7`: 모두 체크/콜하는 고정 게임(카드와 무관한 공개 액션)에서 히어로 결정 6개(프리플랍 3·포스트플랍 3)마다, 히어로 홀카드·깔린 보드는 덱의 같은 자리에 두고 나머지 카드만 섞은 덱 N=50개로 엔진을 다시 돌려 **세계마다 디렉터가 관측을 새로 만든다**. 그 관측으로 레이블 경로(엔진 관측 → `PublicObservation` → DecisionContext·`opp.range` 교사 레이블)와 Gate L `REGISTRY`의 정책을 실행 | `PublicObservation`과 상대 정책 가정이 같고 타인 홀카드·덱만 다르면 **정책 출력과 TP 정답 레이블**(그리고 DecisionContext)이 완전 동일. 판별: 덱을 읽는 가짜 레이블러·정책 입력, 덱을 관측에 흘리는 엔진은 실패해야 한다 |
| L8 | 특성 출처 | 정책 입력 텐서의 모든 필드가 `PublicObservation` 또는 DecisionContext에서 왔음을 런타임 출처 표지로 확인(정적 import 검사만으로는 부족). `TeacherContext`·`PrivateWorldState` 값이 섞이면 실패 |

스위트: `referee/gate_l.py` — `python -m referee.gate_l`. 지표 `gate_l_pass_rate`·`gate_l_checks`·`gate_l_items`.

## Gate T — TP 경유 (D3부터 상시 CI)
- T1 병목: 같은 TP 판단 값 + 같은 DecisionContext(`docs/TP.md` §1.1)이면, 그 밖의 관측을 무작위로 바꿔도 `act.choice` 분포가 완전히 같다. 구현: `referee/gate_t` `check_t1` — 기록된 게임의 결정 8개(프리플랍 4·포스트플랍 4)마다 TP 벡터와 DecisionContext를 고정하고 상대 식별자·통계·메모리·게임 ID를 N=100회 무작위로 바꾼다. 등록 정책은 `referee/gate_t` `REGISTRY`.
- T2 계산 항목 일관성: `docs/TP.md`의 "계산" 항목은 정의식으로 다시 계산한 값과 허용 오차(명세 상수) 안에서 일치한다. 구현(#282): `referee/gate_t/t2.py` `check_t2` — 기록된 게임에서 계산 항목을 낸 결정 8개마다, 정책 자신의 판단 항목(`opp.range`, 없으면 균등 사전)과 공개 사실로 다시 계산해 명세 `grading.t2_tolerance`(0–100 척도 1점) 안인지 본다(TP.md §5 연쇄 채점 ①). 재계산: 프리플랍 헤즈업 `hand.equity`는 심판 클래스 대 클래스 표(`referee/anchors/hu_equity`), 프리플랍 멀티웨이는 제품의 n명 상대 표(독립 아님 — 상대 수·레인지 연쇄만 검사), 포스트플랍 헤즈업 `hand.equity`·`hand.outs`·`hand.vuln`은 `stalker/tp/reference.py` 전수 열거. TeacherContext 가정이 필요한 항목(`opp.value`·`board.*`·`plan.foldeq`)과 멀티웨이 포스트플랍·`plan.icm`은 "unsupported"로 **실패**한다(조용한 통과 금지). 판별: 멀티웨이에서 상대 1명 기준 에퀴티를 낸 정책과 +5점 정책은 실패, 정수 반올림만 다른 정책은 통과(테스트). 등록 시점에 기본 헤드가 멀티웨이에서도 상대 1명 기준 에퀴티를 내던 것을 T2가 잡아, 헤드를 남은 상대 수 기준으로 고쳤다.
- T3 형식: 모든 TP 값이 명세의 척도·눈금·형식 안에 있고, N/A 항목은 값이 없으며, 해당 등급에서 묻지 않는 항목에 의존하지 않는다.
- T4 충분성(판별): 반드시 구분돼야 할 스팟 쌍 20종 이상(예: BTN 대 BB 단독 팟 vs BTN 대 BB·SB 멀티웨이, 버블 직전 vs 머니인 확정, 같은 에퀴티·다른 포지션)에서 액션 헤드 입력(TP + DecisionContext)이 서로 다르다. 스팟 목록은 버전 관리한다. T1~T3은 병목 **준수**를, T4는 병목이 **충분한 정보**를 담는지를 본다. 구현: `referee/gate_t/t4.py` `check_t4` + 스팟 쌍 목록 `t4_spots_v1.json`(21쌍, 쌍마다 이유 한 줄, sha256 출력). 각 스팟을 엔진 `Observation` → `PublicObservation`으로 만들어 액션 헤드 입력(TP 벡터 + DecisionContext)이 다른지 본다. 판별: 포지션·상대 수를 지운 입력은 실패한다(테스트). 로더(`inconsistency`)는 실제 핸드가 도달할 수 없는 스팟(폴드한 좌석이 핸드에 남음, 핸드 밖 좌석의 베팅, 프리플랍 좌석별 마지막 콜·레이즈 금액 ≠ `bets_bb` — #254)을 거부한다.
- 통과율 100%. 기계 판독 TP 명세(`stalker/tp/spec/`)의 버전과 해시를 결과에 기록한다.

## Gate S — 둔감성, regret 기반 (D3부터)
- 방법: 고정 스팟 세트(환경·등급별, 버전 관리)에서 `docs/TP.md` §6 버킷 안의 섭동을 가해 TP 값·액션 분포 변화와 **안정화 regret**(독립 기준 — 앵커·솔버·Q 평가 — 대비, 섭동 전후 각자의 최선 대비 손실 증가분)을 잰다.
- 지표: 판단 항목 변화 95백분위, 액션 분포 총변이거리(TV) 95백분위, 안정화 regret 평균·상위 1%, 경계 절벽 비율. 같은 정의를 개별 스팟이 아니라 **집계 분포**에 적용한다(TP.md의 버킷 표와 같은 범위).
- 통과(초기안): 변화 95백분위 ≤ 등급 눈금 한 칸, TV 95백분위 ≤ 0.15, 안정화 regret 상위 1% ≤ 팟의 2%. 그리고 **민감해야 할 골든 스팟**(`docs/TP.md` §6 민감 예외: 올인 임계·버블·콜 가격 임계 등)에서는 기준 정책과 같은 방향으로 행동이 바뀌어야 한다 — 평탄화하면 실패.
- 보고: 안정성–강도 파레토(Gate Q 지표와 함께). Gate S 통과가 Gate Q·앵커 regret 악화로 달성되면 안 된다.
- 판별력 확인: 원시 수치에 과민한 정책과 모든 것을 평탄화한 정책이 둘 다 실패해야 한다.
- 구현 v0(#280, E1 헤즈업 푸시/폴드만): `referee/gate_s/`(`python -m referee.gate_s`, 스팟 세트 `spots_v1.json` + sha256, 재생성 `python -m referee.gate_s.make_spots`). 섭동은 §6 스택 버킷(≤5·5–10·10–15BB) 안에서 앵커 격자(0.5BB)로 옮긴다. 민감 예외 ④를 핸드 단위로 적용한다: 내시 앵커의 최선 액션이 같으면 '안정' 핸드(TV 측정), 최선 액션이 팟의 1% 이상 차이로 뒤집히면 '예외' 핸드(골든 스팟에서 앵커 방향으로 뒤집힌 질량의 절반 이상 움직여야 통과). 예외를 빼지 않으면 내시 앵커 자신이 TV p95 0.24(SB)·0.33(BB)로 실패한다 — 짧은 스택의 푸시/폴드 균형은 실제로 스택에 민감하다. 아직 `gates full`에 등록하지 않는다(정책 결과를 본 뒤 등록).

## Gate Q — 강도 (D3부터) — 네 항목은 서로 다른 것을 뜻한다
| ID | 무엇 | 뜻하는 것 | 뜻하지 않는 것 |
|---|---|---|---|
| Q1 | 지정 상대군 대비 성적: 페르소나 필드 duplicate 평가(캐시 bb/100, 토너먼트 ROI) | 그 상대군 대비 우위 | 균형·착취 불가 |
| Q2 | 의사결정 손실: 이론 앵커(헤즈업 푸시/폴드 내시 `referee/anchors/pushfold.py`, ICM 참조기)·솔버 스팟(TexasSolver) 대비 EV 손실 | 그 스팟 집합에서의 근사도 | 다른 스팟의 품질 |
| Q3 | 발견된 착취 이득: 국소 최선 응답(LBR)·학습된 공격자(RL-BR)가 찾은 이득의 추정치와 CI | 착취 가능성의 **하한**(최소 이만큼은 착취됨) | 상한. 공격자가 못 찾았다고 취약점이 작다는 뜻이 아니다 |
| Q4 | 균형 인증: 정확한 최선 응답 계산(E1 헤즈업 푸시/폴드, Kuhn·Leduc 같은 장난감 게임) | 그 환경에서 착취 가능성 상한 | 다른 환경 |

- 공식 통과 기준(Q1): 같은 환경의 **최상위 등급 페르소나 필드** 대비 95% CI 하한 > 0. 난이도별 전 필드 결과는 보고 지표다.
- Q4 기록(CI, `referee/metrics.py` `e0()`·`e1()`, #170): `e0_kuhn_cfr_exploitability`·`e0_leduc_cfr_exploitability`(무제약 CFR+), `e1_tp_<등급>_exploitability`(E1 TP 병목 정책, 콜당했을 때 에퀴티·분위 눈금, 스택 5·10·15bb 평균), `e1_tp_uniform_beginner_exploitability`(v0.1 눈금 대조), `e1_nash_fp_exploitability`(무제약 기준). 단위는 E0 칩/핸드, E1 bb/핸드.
- Q4가 없는 환경의 보고서·모델 카드·서비스 문구에 "착취 불가", "GTO 인증", "착취 가능성 ≤ X"를 쓰지 않는다. Q3은 "발견된 착취 이득"으로만 쓴다.
- **복잡성 비용**: 같은 환경에서 TP 병목 없는 기준 정책 대비 Q1·Q2·Q3(·Q4) 차이. 게이트가 아니라 보고 지표(등급별).
- **적응 가치**: 게임 내 기억(성향 통계)을 끈 같은 모델 대비, 성향이 뚜렷한 페르소나 상대 이득(95% CI). 기억 사용 여부(L2)와 별도로 EV 이득을 본다.
- **상대 집합 대비 최대 손실**(3인 이상, ADR 0014 1층, 보고 지표): 상대 집합은 평가 전에 등록한 목록이다 — 학습 착취자(같은 추상화와 더 세밀한 추상화의 리그 착취자), 이전 챔피언 풀, 같은 환경의 스타일 페르소나 전부, 그리고 이들을 섞은 좌석 배치. 구성마다 duplicate 평가로 캐시 bb/100(토너먼트 ROI)과 95% CI를 내고, **최악 구성의 점추정과 95% CI 하한**을 보고한다. 모델 선택에 쓴 세트와 분리한다(통계 절차). Q4가 없으므로 "착취 가능성 ≤ X"로 쓰지 않는다.
- **착취 계층 지표**(ADR 0014 2층, 보고 지표, 착취 계층 구현부터): ① 추가 이득 = 위 적응 가치와 같은 정의(착취 계층 켬 − 끔, 성향이 뚜렷한 페르소나 상대, 95% CI). ② 적응 상대 최악 손실 = 착취 계층을 노리는 상대(성향을 위장했다가 바꾸는 페르소나, 학습 착취자) 대비 켬 − 끔 차이의 95% CI 하한. 손실 한도 값은 착취 계층 설계 ADR에서 평가 전에 정한다.

## Gate F — 따라 하기 견고성 (D3부터)
- 방법: TP-GTO의 판단 값에 사람 수준 오차를 넣고, 계산 항목은 그 오차 값으로 다시 계산해 둔 "따라 하는 봇"의 성적을 잰다.
- 오차 모델 세 가지를 **별도 결과**로 낸다: ① 합성(등급별 가우시안, 0–100 절단, 연속 결정 간 상관 포함; 초기안 초보 σ=20, 중수 12, 고수 6), ② 시간 압박(Quick 모드 입력 시간 제한에서 모은 분포), ③ 사용자 실측(서비스 기록의 실제 입력 오차 분포, 데이터가 생기면).
- 통과(초기안, ①로 판정): 같은 등급의 따라 하는 봇이 그 등급의 대상 실력 페르소나를 95% CI로 이긴다(초보→실력 하위, 중수→중위, 고수→상위 페르소나 필드).
- 구현 v0(#281, E1 헤즈업 푸시/폴드, 오차 모델 ①): `referee/gate_f/`(`python -m referee.gate_f [--scale quantile|uniform]`). TP 값에 등급 σ 가우시안 오차를 넣고 오차 값이 든 눈금 칸의 행동을 한다. 칸 확률은 정확 계산(표본 오차 없음). E1에는 페르소나가 없어 통과 판정 없이 내시 상대 대비 손실과 정확 착취도만 보고한다. σ는 값의 척도에 걸리므로 균등 눈금(`hand.equity`)과 분위 눈금(`hand.pct`)의 손실은 같은 사람 오차의 비교가 아니다 — 척도별 실제 오차 분포는 #261·오차 모델 ③에서 정한다.

## Gate U — 서비스 품질 (D1부터 CI)
- 웹 E2E(Playwright): 핵심 흐름(설정 → Training Game 한 핸드 → TP 입력 → 채점 → 학습 섹션 추천, 학습 섹션 1문제, 복기 입력 → 비교) 통과.
- 화면 3종(폰 390×844, 태블릿 820×1180, 노트북 1440×900) 스크린샷을 아티팩트로 남기고, 가로 스크롤·잘린 요소 0.
- 성능 예산: 첫 화면 로드 ≤ 2s(모바일 스로틀링). 접근성: axe 심각 위반 0.
- 결정당 입력 시간(Quick 모드 P50/P95)을 기록한다(측정 지표, 판정 아님).
- 모든 정답 화면에 신뢰도 라벨(`모의`/`검증 중`/`검증 완료`)이 있는지 E2E가 확인한다.
- 시각 품질은 Reviewer가 스크린샷으로 판단하는 추론적 센서다(`harness/routines/reviewer.md`). 실기기·배포 적합성(콜드 스타트, 전체 크기, 저장 위치)은 Gate U가 보증하지 않는다 — 배포 스파이크에서 따로 잰다.

## Gate E — 학습 효과 (D4부터) — "시뮬레이션 내 학습 효과"
- 시뮬레이션 학습자: TP 오차가 큰 봇이 채점·약점 추천·학습 섹션 루프를 거친다.
- 필수: **처음 보는 스팟 홀드아웃**(보드·레인지·상대 유형·스택 조합이 학습 문제와 겹치지 않음)에서의 개선(전이). 비교군: 무작위 추천, 항목별 균등 연습, 액션 외우기(TP 없이 정답 액션만), TP 힌트 없는 복기.
- 실제 사람의 향상은 Gate E가 아니라 성공 레벨 3으로 따로 잰다.

## Gate X — 설명 충실도 (정의만, 구현은 D4)
- TP 입력을 조금 바꿨을 때, 설명이 말한 대로 행동이 바뀌는가(설명과 실제 출력 변화의 일치).
- 설명이 상관관계를 원인처럼 말하지 않는가(반사실적 검사).
- 설명을 읽은 시뮬레이션 학습자가 처음 보는 스팟에 적용할 수 있는가.
- 설명이 예외(올인 임계·버블·멀티웨이)를 알려주는가.

## 모델 승인 상태 (환경·등급별, 모델 카드에 기록)
| 상태 | 필요한 증거 | 서비스 화면 |
|---|---|---|
| `DRAFT` | 형식·API 검증 | 데모·모의 라벨 |
| `SIM_VALIDATED` | Gate R·L·T 통과, TP 정답 레이블 정합성(T2) | "검증 중" — 시뮬레이션 기준 조언, 불확실성 표시, 점수 없음 |
| `BENCHMARKED` | Gate S·Q·F 결과 기록(Q4가 있으면 포함) | "검증 중" — 강도 수치와 적용 환경 표시 |
| `PEDAGOGY_APPROVED` | 정답 안정성(학습 시드 간), 항목별 채점 승인(`eligible_for_grading`), (D4부터) Gate X | "검증 완료" — 채점·학습 추천 허용 |

- 한 환경의 상태는 다른 환경으로 자동 승계되지 않는다(E1 통과 ≠ MTT 통과).
- 항목별 채점 승인: `PEDAGOGY_APPROVED`여도 정답 안정성 기준을 못 넘는 TP 항목은 `eligible_for_grading=false`로 두고 참고값으로만 보여준다.

## 통계 절차 (모든 게이트 공통)
- 표본 수는 사전 등록한다(검정력 ≥ 0.9, α = 0.05, 최소 효과 δ). 성공 판정용 조기 중단 금지, 무익성 중단(SPRT)만 허용. 표본이 모자라면 "판정 불가(표본 부족)". 도구: `referee/stats.py`, `referee/evaluate.py`.
- **재현·동등**은 CI 겹침으로 판정하지 않는다. 사전에 정한 허용 차 δ_eq로 동등성 검정(두 단측 검정, 차이의 90% CI가 [−δ_eq, δ_eq] 안)을 한다.
- **세트 분리**: 개발 세트(에이전트가 봄) / 순환 검증 세트(모델 선택용, 주기적으로 교체) / 최종 블라인드 감사 세트(`HOLDOUT_SEED` Secret, 최종 보고에만). 체크포인트 선택에 쓴 세트의 결과를 최종 성적으로 보고하지 않는다.
- **다중 비교**: 한 판정에서 여러 페르소나·환경·항목을 동시에 검정하면 Holm 보정한다.
- **꼬리**: 평균·95백분위와 함께 상위 1% 손실과 중요 유형별 최대 손실을 보고한다.
- **기준 고정**: 게이트 수치는 평가 전에 고정한다. 실패한 후보를 본 뒤 기준을 바꾸면 변경 사유와 이전 기준의 결과를 함께 기록한다(Auditor 감사 항목).
