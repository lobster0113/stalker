# 데이터 충분성 기준 (보호 문서 — `referee-change` 절차로만 수정)

> 사용자 지시(2026-10-24): "AI 인풋·아웃풋 데이터는 유형화 결과와 학습 내용이 의미가 있을 정도로 충분해야 한다. 기준은 에이전트가 판단하라."
> 아래 기준은 부트스트랩 세션이 정한 초기값이다. **완화하려면** 통계적 근거를 갖춘 `referee-change` PR이 필요하고, 강화는 언제든 가능하다.

## 0. 원칙
1. **충분하지 않은 유형은 가르치지 않는다.** 학습 서비스(3)에 노출되는 모든 교훈·문제는 아래 기준을 통과한 셀에서만 나온다. 미달 셀은 "데이터 부족"으로 표시하고 데이터 생성 우선순위에 올린다.
2. **표본은 원시 개수가 아니라 유효 표본 수(ESS)로 센다.** 같은 토너먼트·같은 상대에서 나온 결정들은 서로 독립이 아니므로 토너먼트 단위 클러스터 부트스트랩으로 분산을 추정하고 `ESS = p(1-p) / Var(p̂)`로 환산한다.
3. **유형의 세분화 정도는 데이터가 결정한다.** 셀은 두 자식 셀이 모두 기준을 통과할 때만 분할한다(최소 잎 크기 원칙). 데이터가 늘면 유형이 자동으로 세밀해진다.

## 1. 셀(유형) 단위 기준
| 기준 | 정의 | 통과 조건 | 근거 |
|---|---|---|---|
| **S1 정밀도** | 셀의 각 주요 액션 빈도(AI 혼합전략 확률의 평균) 95% 신뢰구간 반폭 | ≤ 5%p (ESS ≥ 385에 해당). 반폭 = max(부트스트랩 반폭, rule-of-three 상한 3/토너먼트 수): 분산 0 행동도 토너먼트 ≥ 60이어야 통과 | 최악의 경우 p=0.5: 1.96²·0.25/0.05² ≈ 384. 분산 0은 정밀함이 아니라 n개 토너먼트에서 이탈을 못 본 것이므로 95% 상한 3/n을 쓴다 |
| **S2 핸드 차트** | 프리플랍 셀에서 핸드 클래스(169)별 전략을 가르칠 경우, 각 핸드 그룹별 ESS | 그룹당 ≥ 30, 그룹은 인접 핸드 병합 허용 | 차트 단위 교훈의 최소 신뢰 |
| **S3 적응 차이** | "상대 유형 A vs B에서 AI가 X%p 다르게 둔다"는 교훈 | 10%p 차이를 검정력 0.8, α=0.05로 검출 가능 (각 쪽 ESS ≥ 392) 이고 실제 차이의 CI가 0을 포함하지 않음 | README의 차별점(정보 누적 적응)을 가르치는 교훈의 최소 조건 |
| **S4 재현성** | 시드가 다른 독립 데이터셋 2개에서 같은 셀의 결론(주 액션, 빈도 ±5%p) 일치 | 일치 | 우연한 패턴의 교훈화 방지 |
| **S5 포화** | 데이터 80% 부분집합과 100%의 결론 차이 | 주 액션 동일, 빈도 차 ≤ 2%p | 더 모아도 결론이 바뀌지 않음 |
| **S6 EV 근거** | 교훈이 "A가 B보다 낫다"를 말할 때 AI의 EV 차이 추정 | 차이의 95% CI가 0을 포함하지 않음 | 빈도뿐 아니라 이유(EV)까지 의미 있어야 함 |

셀은 S1·S4·S5를 통과하면 **교훈 가능**, 추가로 S2/S3/S6을 통과해야 해당 종류의 교훈(차트/적응/EV 비교)을 낼 수 있다.

## 2. 데이터셋 전체 기준 (학습 서비스 개시 조건)
| 기준 | 통과 조건 |
|---|---|
| **D1 가중 커버리지** | 실제 토너먼트에서 마주치는 결정의 빈도로 가중했을 때, 교훈 가능 셀이 차지하는 비율 ≥ 95% (Phase 4 개시 조건), ≥ 99% (장기 목표) |
| **D2 조건 커버리지** | 설정 축(필드 크기 구간, 앤티 방식, 구조 속도, 단계: 초반/중반/버블/ITM/파이널테이블, 스택 깊이 구간)의 각 조합 중 실사용 대상 조합마다 D1 충족 |
| **D3 상대 다양성** | 적응 교훈을 위해 상대 유형(최소 nit/TAG/LAG/콜링스테이션/매니악/숏스택 푸시폴드)별로 S3 충족 셀이 존재 |
| **D4 시점 다양성** | 토너먼트 초반(정보 적음)부터 후반(정보 많음)까지 "누적 정보량" 구간별로 셀이 충족 — 정보 누적에 따른 전략 변화를 가르치기 위함 |
| **D5 결정 품질** | 기록의 스키마 유효 100%, AI 출력 확률합 = 1, 재현 가능(시드·코드 커밋·AI 버전 기록) |

## 3. 산출과 운영
- 이 기준의 계산은 `referee/`의 코드가 하고 CI/배치가 `ops:metrics/`에 기록한다(구현은 Phase 2 `referee-change` 이슈).
- **데이터 생성 우선순위**는 "기준 미달 셀 × 실전 출현 빈도"가 큰 순으로 정한다 → 생성 파이프라인(1)이 유형화(2)의 부족분을 겨냥해 데이터를 만든다.
- 데이터 규모 예상: 셀 수 수천 × ESS 수백 → **수백만 결정 단위**. AI 연동 방식 선택(ADR)에서 결정당 연산 비용은 이 규모를 감당할 수 있는지로 평가한다.
- 각 기준의 현재 통과율은 북극성 지표(유형화 축)의 일부로 추적한다.
