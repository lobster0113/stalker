# 022: 재개 가능한 CI 학습 — 체크포인트 이어 달리기
- 상태: 진행 중
- 제안: 대화 세션, 2026-10-29 / 이슈 #301
## 문제 (관측 근거)
`train.yml`(실험 014)은 시드당 한 잡이고, 잡은 340분에서 끊긴다. E3 6-max 초보의 처리량은 약 8 it/s다(run 40664565294: 10⁵회에 시드당 최대 237분). 그래서 한 번에 약 1.4×10⁵회까지만 돈다. 같은 정책은 LBR 0.82 bb/핸드, 페르소나 최악 구성 −83~−133 bb/100으로 아직 약하다(#296). 설계 노트 #192 §6은 10⁵–10⁶회가 필요하다고 본다. 유료 파드도 잡당 330분 상한(`harness/cloud/launcher.py` MAX_JOB_MINUTES)이 같다. 따라서 연산을 사도 실행 길이 문제는 풀리지 않는다.
## 가설
잡이 끝날 때 학습 상태(regret·평균 전략·난수 상태) 체크포인트를 아티팩트로 남기고, 다음 디스패치가 `resume_run`으로 그것을 받아 이어 돌린다. 그러면 조각을 이어도 결과가 한 번에 돈 것과 비트 단위로 같고, 시드당 반복 수의 상한이 사라진다.
## 변경
`stalker/e3/mccfr.py` `state()`/`from_state()`, `stalker/train_jobs.py` `--resume`(`e3-tp-*`만, 체크포인트 `*.ckpt.json`, 요약에서 제외), `.github/workflows/train.yml` 입력 `resume_run`(숫자 검증, env 전달, `actions: read`, `download-artifact` run-id).
## 측정 지표와 측정창
머지 후 첫 이어 달리기 3회 또는 14일 중 먼저 오는 쪽. 근거는 train run 로그와 ops `training/<job>/` 요약뿐이다.
- 이어 달린 실행 중 체크포인트를 받아 재개에 성공한 비율(`resumed_from_iters_by_seed`가 이전 실행의 `iters`와 같음).
- 조각당 체크포인트 크기, 내려받기·불러오기 시간(잡 로그).
## 성공 기준 (수치)
- 재개 성공 100%(시드별 `resumed_from` = 이전 누적 반복 수).
- 체크포인트 크기 ≤ 50 MB(`ARTIFACT_MAX_BYTES` 256 MB 안), 불러오기 ≤ 2분.
- 같은 반복 수의 한 번 실행과 정책 sha256이 같음(테스트로 보장, CI 테스트 통과).
## 롤백 방법
`resume_run`을 비워 두면 이전 동작과 같다(체크포인트 파일이 아티팩트에 하나 더 생길 뿐이다). 문제가 생기면 이 PR을 revert한다.
