# 012: guard_bash를 셸 명령 조각마다 적용
- 상태: 진행 중
- 제안: 대화 세션, 2026-10-27 / 이슈 #141 / PR #158
## 문제
`harness/hooks/guard_bash.py` 규칙이 `.*`로 Bash 호출 전체를 훑었다. 그래서 같은 줄의 **다른 명령**에 있는 ` +x`(jq 문자열 연결, 코멘트 본문의 "+", `date -u +%Y…`)를 강제 푸시로 오인했다. 2026-10-27 대화 세션에서 4회 오차단이 있었다. 그중 한 번은 `git commit … && git push …` 묶음이 통째로 막혀 커밋이 되지 않았고, 다음 명령이 엉뚱한 브랜치에서 실행됐다(커밋이 다른 브랜치에 올라감, 푸시 전에 바로잡음). 이슈를 만드는 명령도 본문 예시 때문에 막혔다.
## 가설
셸 구분자(`;`, `&&`, `||`, `|`, 줄바꿈)로 나눈 조각마다 같은 규칙을 적용하면, 실제 위반은 그대로 막고 오차단은 사라진다.
## 변경
- `guard_bash.check`: `SEPARATORS`로 조각을 나눠 조각마다 `BLOCK` 규칙 적용. 규칙 자체는 그대로.
- 회귀 테스트 `test_bash_guard_checks_each_command_separately`.
## 위험
따옴표 안의 구분자도 나눈다. 그래서 `git push origin "a;b" --force`처럼 따옴표 안에 `;`가 있는 브랜치 이름 뒤에 `--force`를 붙이면 통과한다. 실제로 나올 법한 명령이 아니고, 서버 쪽 브랜치 보호와 리뷰가 남아 있어 위험은 낮다.
